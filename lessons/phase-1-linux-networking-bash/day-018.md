## Theory (1h)

### A. firewalld concepts (20 min)
- firewalld is a dynamic firewall manager on top of netfilter (nftables backend on
  current RHEL/Fedora). Config is organized by **zones** — a zone is a trust level
  applied to an interface or source: `public` (default, untrusted), `internal`,
  `trusted` (allow everything), `drop` (silently drop everything).
- `firewall-cmd --get-default-zone`, `firewall-cmd --get-active-zones` (which zone(s)
  are bound to which interface right now).
- **Runtime vs permanent**: changes without `--permanent` apply immediately but vanish
  on reload/reboot; `--permanent` persists but needs `firewall-cmd --reload` to take
  effect live. The two-step habit (`--permanent` then `--reload`, or test with runtime
  first then make it permanent) avoids "it worked in testing but not after reboot."

### B. Services, ports, rich rules (25 min)
- Named services (predefined port bundles): `firewall-cmd --list-services`,
  `firewall-cmd --add-service=http --permanent`. `firewall-cmd
  --get-services` lists all known named services.
- Raw ports when no named service fits: `firewall-cmd --add-port=8080/tcp --permanent`.
- **Rich rules** for conditional logic (source-restricted access, logging, rate
  limiting): `firewall-cmd --add-rich-rule='rule family="ipv4" source
  address="192.168.1.0/24" service name="ssh" accept' --permanent` — SSH allowed only
  from that subnet.
- `firewall-cmd --list-all` (full picture of one zone: services, ports, rich rules) —
  your one-command sanity check after any change.

### C. SELinux modes (10 min)
- Three modes: **Enforcing** (default, blocks and logs violations), **Permissive**
  (logs but doesn't block — great for troubleshooting/testing policy), **Disabled**
  (off entirely — generally a bad idea in production, hides real issues rather than
  fixing them).
- Check: `getenforce`. Change temporarily: `sudo setenforce 0` (permissive) / `1`
  (enforcing) — doesn't survive reboot. Permanent: edit `/etc/selinux/config`
  (`SELINUX=enforcing`).

### D. SELinux contexts, the 5-second version (5 min)
- Every file/process has a context (`user:role:type:level`) — SELinux policy decisions
  are mostly driven by the **type** field. `ls -Z file`, `ps -Z` to view. Full depth
  (booleans, `restorecon`, `audit2why`) is Day 19's whole session — today is just
  orientation so firewalld and SELinux don't feel like two unrelated black boxes.

## Lab (2h)

### Part 1 — Zone orientation (25 min)
1. `firewall-cmd --get-default-zone`, `firewall-cmd --get-active-zones`.
2. `firewall-cmd --list-all` — read every field: interfaces, services, ports, rich
   rules for your active zone.
3. `firewall-cmd --get-services | tr ' ' '\n' | grep -i http` — confirm `http`/`https`
   are known named services.

### Part 2 — Allow a service and a port (40 min)
4. Install and start nginx as test traffic to gate (full nginx theory is Day 20 — here
   it's just a thing to firewall): `sudo dnf install -y nginx`, `sudo systemctl
   enable --now nginx`.
5. From a second machine (or `curl localhost` locally first to confirm it runs),
   `curl http://<this-vm-ip>` from the second VM from Day 17 — note whether it's
   blocked (likely yes, before opening the firewall).
6. `sudo firewall-cmd --add-service=http --permanent`, `sudo firewall-cmd --reload`,
   `firewall-cmd --list-services` to confirm.
7. Retry the `curl` from the second VM — should now succeed.
8. Open a raw port for testing: `sudo firewall-cmd --add-port=8080/tcp --permanent`,
   `sudo firewall-cmd --reload`, confirm with `firewall-cmd --list-ports`. Start
   `python3 -m http.server 8080 &` and curl it from the second VM to prove the port
   rule works, then stop the server and remove the port rule:
   `sudo firewall-cmd --remove-port=8080/tcp --permanent && sudo firewall-cmd --reload`.

### Part 3 — Rich rules (30 min)
9. Restrict SSH to only your lab subnet (find your subnet from Day 15's work,
   e.g. `192.168.1.0/24`):
   `sudo firewall-cmd --add-rich-rule='rule family="ipv4" source
   address="192.168.1.0/24" service name="ssh" accept' --permanent`
   `sudo firewall-cmd --reload`
10. `firewall-cmd --list-rich-rules` — confirm it's present.
11. **Caution check before removing default SSH access**: confirm your rich rule's
    subnet actually includes your own current IP (`ip a`) — removing the default
    `ssh` service without this could lock you out. If confident, remove the default
    open `ssh` service and rely solely on the rich rule; otherwise leave both and just
    note the rich-rule syntax as understood.
12. Clean up the rich rule after confirming it worked:
    `sudo firewall-cmd --remove-rich-rule='...(same rule)...' --permanent &&
    sudo firewall-cmd --reload`.

### Part 4 — SELinux orientation (25 min)
13. `getenforce` — note current mode (should be Enforcing on a stock RHEL/Fedora).
14. `ls -Z /var/www/html/` (nginx's typical docroot) and `ps -Z $(pgrep nginx | head
    -1)` — read the type field for each (e.g. `httpd_sys_content_t`, `httpd_t`).
15. `sudo setenforce 0`, `getenforce` to confirm permissive, then `sudo setenforce 1`
    to restore — confirm it's reversible without touching the permanent config file.

**Definition of done:** read and explained your active zone's full `--list-all` output ·
opened and closed both a named service and a raw port, verified from a second machine ·
wrote and removed a working rich rule scoped to a subnet · toggled `getenforce`
between enforcing/permissive and explained the difference.
