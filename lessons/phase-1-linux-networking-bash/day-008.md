## Theory (1h)

### A. Viewing processes (15 min)
- `ps aux` (BSD style, all processes, user-oriented columns) vs `ps -ef` (System V
  style, shows PPID clearly) — know both, RHEL exams expect either.
- Key columns: PID, PPID (parent), %CPU, %MEM, STAT (process state: R running, S
  sleeping, D uninterruptible sleep, Z zombie, T stopped).
- `top` (live view, `q` to quit, `k` to kill from inside, `1` toggles per-core CPU) and
  `htop` if installed (nicer UI, tree view, mouse support, F9 to kill).
- Process tree: `pstree`, or `ps -ef --forest`.

### B. Signals and kill (20 min)
- A signal is an async notification to a process. Common ones: **SIGTERM (15)** —
  polite "please exit," **SIGKILL (9)** — immediate, ungraceful, cannot be caught or
  ignored, **SIGHUP (1)** — historically "terminal hung up," now often means "reload
  config," **SIGINT (2)** — what Ctrl-C sends.
- `kill <pid>` sends SIGTERM by default; `kill -9 <pid>` or `kill -SIGKILL <pid>` for
  the hard kill; `kill -l` lists all signal names/numbers.
- `killall <name>` kills by process name; `pkill -f <pattern>` matches against the full
  command line.
- Best practice: always try SIGTERM first, give the process a few seconds to clean up,
  escalate to SIGKILL only if it's stuck.

### C. Priority and job control (15 min)
- `nice -n 10 command` starts a process with lower priority (range -20 highest to 19
  lowest; only root can go negative). `renice -n 5 -p <pid>` changes a running
  process's priority.
- Job control: `command &` (background), `jobs` (list), `fg %1` / `bg %1` (bring to
  foreground/background), `Ctrl-Z` (suspend foreground job), `disown` (detach from
  shell so it survives logout), `nohup command &` (survive hangup signal specifically).

### D. /proc and lsof (10 min)
- `/proc/<pid>/` exposes live process internals as files: `cmdline`, `environ`,
  `status`, `fd/` (open file descriptors — symlinks), `cwd` (symlink to working dir).
  Ties directly back to Day 1's "kernel exposes state as files" idea.
- `lsof -p <pid>` (what files/sockets a process has open), `lsof -i :<port>` (what's
  listening on a port — you'll use this constantly for networking debugging later).

## Lab (2h)

### Part 1 — ps and top (25 min)
1. `ps aux | head -20` then `ps -ef | head -20` — identify the same process (e.g.
   `systemd` PID 1) in both formats and map the column differences.
2. `pstree -p | less` — find `boot_logger.sh` if it's running, or find your own shell's
   ancestry back to PID 1.
3. `top` — sort by memory (`Shift-M` or the `M` key in `top`), identify the top 3
   memory consumers. Quit with `q`.

### Part 2 — signals (35 min)
4. Start a long-running dummy process: `sleep 300 &` — note its PID with `jobs -l`.
5. `kill -0 <pid>` — a trick to check "is this PID alive?" without actually sending a
   signal (exit code only).
6. `kill <pid>` (SIGTERM) — confirm it's gone via `ps -p <pid>`.
7. Start another `sleep 300 &`, this time trap it in a script to observe SIGTERM vs
   SIGKILL:
   ```bash
   printf '#!/bin/bash\ntrap "echo caught SIGTERM; exit 0" SIGTERM\nsleep 300\n' > ~/lab08/trapdemo.sh
   chmod +x ~/lab08/trapdemo.sh
   ~/lab08/trapdemo.sh &
   ```
   `kill <pid>` — watch it print "caught SIGTERM" and exit cleanly.
8. Repeat but `kill -9 <pid>` this time — confirm no "caught" message (SIGKILL cannot
   be trapped).

### Part 3 — priority and jobs (30 min)
9. `nice -n 15 sleep 200 &`; `ps -o pid,ni,cmd -p $!` — confirm the nice value shown.
10. `renice -n 5 -p $!` — change it on a running process, confirm with `ps -o pid,ni`.
11. Start `sleep 100`, `Ctrl-Z` to suspend, `jobs` to see it stopped, `bg %1` to resume
    in background, `fg %1` to bring back to foreground, `Ctrl-C` to kill it.
12. `nohup sleep 60 & disown` — close and reopen your terminal session (or just note
    that it would survive logout) — explain why `nohup` + `disown` together matter.

### Part 4 — /proc and lsof (30 min)
13. `echo $$` (your shell's own PID). `ls /proc/$$/` — inspect `status`, `cmdline`
    (`cat /proc/$$/cmdline | tr '\0' ' '`), and `fd/` (`ls -l /proc/$$/fd/`).
14. `sleep 300 &` again, note PID, `cat /proc/<pid>/status | head -10` — find `State:`
    and `VmRSS:` (resident memory) lines.
15. `sudo lsof -i :22` (or whatever port sshd listens on) — confirm sshd is the owner.
    `lsof -p $$` — see your own shell's open file descriptors, tying back to Day 2's
    FD 0/1/2 discussion.

**Definition of done:** can read both `ps aux` and `ps -ef` output · demonstrated
SIGTERM being trapped and SIGKILL not being trappable · used `nice`/`renice` correctly ·
job control (`bg`/`fg`/`disown`/`nohup`) demonstrated · inspected `/proc/<pid>` and used
`lsof -i` for a real port.
