## Theory (1h)

### A. sed — the stream editor (20 min)
- Core substitution: `sed 's/pattern/replacement/'` — first match per line only;
  add `g` for all matches: `s/foo/bar/g`.
- In-place edit: `sed -i 's/foo/bar/' file` (danger: no undo — use `-i.bak` to keep a
  backup: `sed -i.bak 's/foo/bar/' file`).
- Addresses restrict which lines act: `sed '3d' file` (delete line 3), `sed '2,4d'`
  (range), `sed '/pattern/d'` (delete matching lines), `sed -n '/start/,/end/p'`
  (print only a matched range, `-n` suppresses default auto-print).
- Capture groups + backreferences: `sed -E 's/(user)([0-9]+)/\2-\1/'`.

### B. awk — fields, patterns, actions (25 min)
- Model: `awk 'pattern { action }' file` — for each line, if pattern matches (or is
  blank = always), run the action.
- Fields: `$1`, `$2`, ... `$0` = whole line, `NF` = number of fields, `NR` = current
  record (line) number. Default field separator is whitespace; `-F:` sets a custom one
  (e.g. for `/etc/passwd`).
- Common one-liners: `awk -F: '{print $1, $3}' /etc/passwd` (username + UID),
  `awk '$3 > 1000 {print $1}'` (numeric comparison on a field), `awk 'END{print NR}'`
  (line count, awk's version of `wc -l`).
- Built-in aggregation: accumulate into a variable across lines —
  `awk '{sum += $1} END {print sum}'`.

### C. The classic pipeline tools (15 min)
- `sort` (`-n` numeric, `-r` reverse, `-k N` sort by field N, `-u` unique while sorting),
  `uniq` (`-c` count occurrences — **requires pre-sorted input**), `cut` (`-d: -f1,3`
  select delimited fields), `tr` (`tr 'a-z' 'A-Z'`, `tr -d '\n'` delete chars),
  `paste` (merge lines from files side by side).
- The idiom `sort | uniq -c | sort -rn` (frequency count, most common first) is one of
  the most-used pipelines in ops work — memorize it.

## Lab (2h)

### Part 1 — sed drills (25 min)
1. `cp /etc/passwd ~/lab06/passwd.copy`. `sed 's/bash/BASH/' passwd.copy | head -3` —
   confirm only first match per line changes without `g`... (passwd has one "bash" per
   line, so add a controlled test: `echo "bash bash bash" | sed 's/bash/sh/'` vs
   `sed 's/bash/sh/g'`).
2. `sed -n '1,5p' passwd.copy` — print only lines 1–5.
3. `sed '/nologin/d' passwd.copy | wc -l` — how many lines survive removing nologin
   accounts? Compare to `grep -vc nologin passwd.copy`.
4. `sed -i.bak 's/:bash$/:zsh/' passwd.copy` — confirm the change and that
   `passwd.copy.bak` preserved the original.

### Part 2 — awk drills (35 min)
5. `awk -F: '{print $1, $7}' /etc/passwd | column -t` — username + shell, aligned.
6. `awk -F: '$3 >= 1000 && $3 < 65534 {print $1, $3}' /etc/passwd` — regular human
   users only (exclude system range and `nobody`).
7. `awk -F: 'END{print NR " total accounts"}' /etc/passwd`.
8. `journalctl -b -p err --no-pager | awk '{print $5}' | sort | uniq -c | sort -rn |
   head` — which unit/process throws the most boot-time errors? (adjust field number
   if your journald output columns differ — inspect a raw line first with
   `journalctl -b -p err --no-pager | head -1`).

### Part 3 — sort/uniq/cut/tr/paste (30 min)
9. `cut -d: -f1,3 /etc/passwd | sort -t: -k2 -n | head` — usernames sorted by UID.
10. `awk -F: '{print $7}' /etc/passwd | sort | uniq -c | sort -rn` — shell frequency
    count, most common first (the memorize-this idiom in action).
11. `echo "Hello World" | tr 'a-z' 'A-Z'`; `cat /etc/passwd | tr ':' '\t' | head -3`.
12. `cut -d: -f1 /etc/passwd > names.txt; cut -d: -f3 /etc/passwd > uids.txt; paste
    names.txt uids.txt | head`.

### Part 4 — Incremental project step (30 min)
Add an awk-based log-stats summary to `boot_logger.sh`:
13. Append a new section to the script:
    ```bash
    echo "--- Log stats summary (awk) ---"
    if ls logs/boot_*.log >/dev/null 2>&1; then
      awk 'BEGIN{count=0} {count++} END{print "Total log lines across files:", count}' logs/boot_*.log
      echo "Errors logged so far:"
      wc -l < logs/boot_errors.log 2>/dev/null || echo 0
    fi
    ```
14. Run `./boot_logger.sh` twice, confirm the awk summary line count grows sensibly and
    matches `wc -l logs/boot_*.log` by hand.
15. Update the "keep last 5 logs" pruning check: confirm the awk summary only counts
    files still present after pruning (i.e. it naturally reflects the pruned set since
    it globs `logs/boot_*.log` fresh each run).
