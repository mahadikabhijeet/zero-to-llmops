## Theory (1h)

### A. Install, venv, and why isolate (15 min)
- Check version: `python3 --version` (RHEL/Fedora ships Python 3 as `python3`,
  `python` may not exist — always use `python3`/`pip3` explicitly).
- **Virtual environments** isolate per-project dependencies from the system Python
  (and from each other) — avoids "works on my machine" version conflicts and protects
  the system's own Python (which OS tooling like `dnf` itself may depend on).
- `python3 -m venv ~/venvs/fresher`, activate: `source ~/venvs/fresher/bin/activate`
  (prompt changes to show it's active), `deactivate` to exit. `pip install <pkg>`
  installs only into the active venv.

### B. Syntax and types (20 min)
- No braces — **indentation defines blocks** (4 spaces is the PEP 8 convention;
  mixing tabs/spaces is a real error, not just style).
- Core types: `int`, `float`, `str`, `bool`, `list` (mutable, ordered — `[1, 2, 3]`),
  `tuple` (immutable, ordered — `(1, 2, 3)`), `dict` (key-value — `{"a": 1}`), `set`
  (unordered, unique — `{1, 2, 3}`), `None` (bash has no direct equivalent — closest
  is an unset/empty variable, but `None` is a real distinct value, not absence).
- Dynamic typing: variables aren't declared with a type, but values are strongly typed
  (`"1" + 1` is a `TypeError`, unlike bash's loose string concatenation).
- f-strings for formatting: `f"Hello, {name}! You are {age} years old."` — the modern
  standard, prefer over `.format()` or `%`.

### C. Control flow (15 min)
- `if/elif/else` — same logic as bash, different syntax, colon + indentation instead
  of `then`/`fi`:
  ```python
  if x > 10:
      print("big")
  elif x > 0:
      print("small")
  else:
      print("non-positive")
  ```
- `for item in iterable:` (Python's `for` iterates over items directly, unlike bash's
  word-based loop — a conceptual shift worth calling out explicitly).
  `while condition:`. `range(5)` generates 0–4. `break`/`continue` work as in bash.

### D. REPL habits (10 min)
- `python3` alone drops into the interactive REPL — invaluable for testing a snippet
  before committing it to a script. `>>> ` prompt, `exit()` or Ctrl-D to leave.
- `help(str)`, `dir(obj)` (list an object's methods/attributes) — the Python
  equivalents of `man`/`--help` from Day 2's help-seeking skill.
- IPython (if installed) is a nicer REPL (tab completion, history) — mention only,
  stock `python3` REPL is sufficient for this course.

## Lab (2h)

### Part 1 — venv setup (25 min)
1. `python3 --version`. `python3 -m venv ~/venvs/fresher`.
2. `source ~/venvs/fresher/bin/activate` — confirm prompt change. `which python3` —
   confirm it now points inside the venv.
3. `pip install requests` (a library we'll actually use on Day 36) — confirm it
   installs without needing `sudo` (proof it's isolated to the venv).
4. `deactivate` — confirm `which python3` reverts to the system path.

### Part 2 — REPL exploration (25 min)
5. `python3` — in the REPL, try: `1 + 1`, `"1" + "1"`, `"1" + 1` (watch the
   `TypeError`), `type(5)`, `type(5.0)`, `type("5")`.
6. `x = [1, 2, 3]; x.append(4); print(x)` — mutability of lists.
7. `t = (1, 2, 3); t[0] = 99` — watch the error, confirm tuple immutability.
8. `help(list)` briefly, `dir([1,2,3])` — skim available list methods.

### Part 3 — Types and control flow script (40 min)
9. Write `~/lab25/checks.py`:
   ```python
   import subprocess

   def is_active(service):
       result = subprocess.run(
           ["systemctl", "is-active", "--quiet", service]
       )
       return result.returncode == 0

   services = ["sshd", "nginx", "boot-logger.service", "bogus-service"]
   for svc in services:
       status = "up" if is_active(svc) else "down"
       print(f"{svc}: {status}")
   ```
   Run it: `python3 ~/lab25/checks.py` (inside the activated venv is fine, no third
   party packages needed here — `subprocess` is standard library).
10. Modify it to count up/down services using a dict and an f-string summary at the
    end: `print(f"{up_count} up, {down_count} down out of {len(services)}")`.

### Part 4 — Data structures drill (30 min)
11. Build a dict mapping service name → expected state (mirroring Day 23's bash
    associative array): `expected = {"sshd": "active", "nginx": "active",
    "bogus-service": "inactive"}`. Loop over `.items()`, compare against
    `subprocess.run(["systemctl", "is-active", svc], capture_output=True,
    text=True).stdout.strip()`, print PASS/FAIL per entry.
12. `set()` demo: `a = {1,2,3}; b = {2,3,4}; print(a & b, a | b, a - b)` — intersection,
    union, difference. Note the direct visual parallel to Venn diagrams — useful
    mental model for later work (e.g. reconciling expected vs actual state, a very
    ops-relevant idiom).

**Definition of done:** created and activated a venv, installed a package into it,
confirmed isolation from system Python · ran REPL type/mutability experiments ·
wrote and ran a working Python service-check script using `subprocess` and f-strings ·
demonstrated set operations.
