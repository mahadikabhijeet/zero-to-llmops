## Theory (1h)

### A. set -euo pipefail (20 min)
- `set -e`: exit immediately if any command fails (non-zero exit) — without it, bash
  scripts silently plow forward after errors, a huge source of production incidents.
  Caveat: doesn't trigger inside `if`/`&&`/`||`/`while` conditions (those are expected
  to "fail" sometimes) — know this so you're not surprised.
- `set -u`: treat unset variables as an error instead of silently expanding to empty
  string — catches typos like `$fiel` instead of `$file` immediately.
- `set -o pipefail`: without it, a pipeline's exit code is only the **last** command's
  — `false | true` would report success. With it, the pipeline fails if *any* stage
  fails.
- Standard header for any serious script: `set -euo pipefail` as the first
  non-comment line. Combine with `IFS=$'\n\t'` in stricter scripts to avoid
  word-splitting on spaces (know it exists; not always necessary).

### B. shellcheck (15 min)
- `shellcheck script.sh` — a static analyzer that catches quoting bugs, unused
  variables, `[ ]` vs `[[ ]]` pitfalls, and dozens of other common mistakes, with
  explanations and codes (e.g. SC2086 = "double quote to prevent globbing/word
  splitting"). `sudo dnf install -y ShellCheck`.
- Treat shellcheck output as a checklist before calling any script "done" — it's the
  bash equivalent of a linter, and job interviews increasingly expect it as baseline
  hygiene.

### C. getopts (15 min)
- Proper flag parsing instead of hand-rolling `$1`/`$2` position checks:
  ```bash
  while getopts "vh" opt; do
      case "$opt" in
          v) verbose=true ;;
          h) echo "Usage: $0 [-v] [-h]"; exit 0 ;;
          *) echo "Unknown option"; exit 1 ;;
      esac
  done
  ```
- `":vh"` (leading colon) enables silent error handling with `\?`/`:` cases for
  invalid/missing-argument options — a step up in robustness once the basic pattern is
  solid. Options requiring a value use a trailing colon in the optstring: `"o:"` means
  `-o` needs an argument, retrieved via `$OPTARG`.

### D. cron and at (10 min)
- `crontab -e` (per-user), `crontab -l` (list). Format: `min hour dom mon dow
  command`. `*/15 * * * *` = every 15 minutes — the cron equivalent of Day 12's
  systemd timer. `at now + 5 minutes` for one-off scheduled jobs (`atq` to list
  pending, `atrm <id>` to cancel).
- We already chose systemd timers for the project (Day 12) because of journald
  integration and dependency ordering — cron/at are still worth knowing since many
  real environments (and RHCSA-style exams) expect fluency in both.

## Lab (2h)

### Part 1 — set -euo pipefail in practice (30 min)
1. Write a deliberately fragile script `~/lab24/fragile.sh` (no `set` options) that
   references an unset variable and calls a command that fails, then keeps going and
   prints "done" regardless. Run it, observe it "succeeds" anyway (echoes "done").
2. Add `set -euo pipefail` as the first line, re-run — confirm it now stops at the
   first failure and reports a non-zero exit via `echo $?` in a wrapping check
   (`./fragile.sh; echo "exit: $?"`).
3. Deliberately trigger the `pipefail` case: `false | true; echo $?` (no pipefail,
   shows 0) vs `set -o pipefail; false | true; echo $?` (shows 1) — run both to see
   the contrast directly.

### Part 2 — shellcheck (25 min)
4. `sudo dnf install -y ShellCheck` if not present. Run `shellcheck
   /opt/fresher_project/boot_logger.sh` — read every warning.
5. Fix at least 3 real issues it surfaces (commonly: unquoted variables, useless
   `cat`, or `[ ]` vs `[[ ]]` suggestions). Re-run shellcheck to confirm they're
   resolved.
6. Run shellcheck against one of your Day 22/23 lab scripts too — fix at least one
   issue there as well.

### Part 3 — getopts (30 min)
7. Write `~/lab24/report_tool.sh` implementing the getopts pattern from Theory C, with
   `-v` (verbose) and `-h` (help), plus `-o <file>` (output path, using `$OPTARG`).
   Test all three: `./report_tool.sh -v`, `./report_tool.sh -h`, `./report_tool.sh -o
   /tmp/out.txt`, and an invalid flag `./report_tool.sh -z`.

### Part 4 — ★ Project milestone: robust-bash refactor of boot_logger.sh (35 min)
8. Add `set -euo pipefail` as the first line after the shebang in `boot_logger.sh`.
9. Run it — it will likely now fail somewhere it previously "succeeded" silently
   (e.g. a `grep`/`journalctl` pipeline that legitimately returns non-zero when no
   matches exist). Fix each failure point properly: wrap expected-to-sometimes-fail
   commands with `|| true` where a non-match is a valid outcome (e.g.
   `journalctl -b -p err --no-pager | tail -10 || true`), rather than removing
   `set -e` to paper over it.
10. Add `getopts` support for a `-v` verbose flag that, when set, echoes each major
    step before running it (e.g. "Generating HTML report...").
11. Run `shellcheck boot_logger.sh` again — fix remaining warnings until clean or only
    intentionally-ignored ones remain (document any you deliberately skip with a
    one-line comment explaining why).
12. Full regression test: `sudo -u svc_fresher /opt/fresher_project/boot_logger.sh -v`
    and `systemctl start boot-logger.service` — confirm both still work end to end
    (text logs, HTML report, awk summary all intact) with the new robustness layer.

**Definition of done:** ★ `boot_logger.sh` starts with `set -euo pipefail`, passes
shellcheck cleanly (or with documented exceptions), supports `-v` via `getopts`, and
still runs correctly both directly and via its systemd service · demonstrated the
`pipefail` on/off contrast directly.
