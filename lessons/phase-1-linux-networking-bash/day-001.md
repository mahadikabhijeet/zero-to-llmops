## Theory (1h)

### A. What Linux actually is (15 min)
- **Kernel vs OS vs distro**: the kernel (Linus Torvalds, 1991) is the core program that
  talks to hardware and manages processes/memory/files. A "distro" (Fedora, RHEL, Ubuntu)
  bundles the kernel + GNU userland tools + package manager + defaults.
- Why RHEL/Fedora for this course: enterprise standard, RHCSA/RHCE certification path,
  `dnf`/`rpm` package family, SELinux by default (we'll go deep on this in Week 3).
- Layers: hardware → kernel (rings/privilege: kernel space vs user space) → shell → apps.
  `uname -a`, `uname -r`, `cat /etc/os-release` — identify what you're running.

### B. The boot process, stage by stage (25 min)
- **Firmware**: BIOS (legacy, MBR) vs **UEFI** (modern, GPT, Secure Boot) — power-on
  self-test, then hands off to a boot loader.
- **GRUB2**: reads its config (`/boot/grub2/grub.cfg`), presents the boot menu, loads the
  selected kernel image + **initramfs** (a temporary root filesystem in RAM with drivers
  needed to mount the real root — e.g. LVM/RAID modules).
- **Kernel init**: kernel decompresses, initializes hardware/drivers using initramfs,
  mounts the real root filesystem, then execs **PID 1**.
- **PID 1 = systemd**: the first userspace process, parent of everything else. Replaces
  the old SysV init. Runs **targets** (like old-school runlevels) — `multi-user.target`
  (no GUI, ops default) vs `graphical.target`.
- Command to see it end to end: `systemd-analyze` (total boot time),
  `systemd-analyze blame` (slowest units), `systemd-analyze critical-chain`.

### C. systemd basics (20 min)
- systemd manages **units**: services (`.service`), targets (`.target`), timers
  (`.timer`), mounts, sockets. Everything is a unit with a lifecycle.
- Core commands: `systemctl status <unit>`, `systemctl start|stop|restart|enable|disable
  <unit>`, `systemctl list-units --type=service`, `systemctl get-default` /
  `systemctl set-default multi-user.target`.
- **journald**: systemd's binary logging system, replaces (or supplements) flat-file
  syslog. `journalctl` reads it. Key flags: `journalctl -b` (this boot only),
  `journalctl -u <unit>` (one unit's logs), `journalctl -f` (follow, live tail),
  `journalctl -p err` (priority filter), `journalctl --since "10 min ago"`.

## Lab (2h)

### Part 1 — Orientation (20 min)
1. Log into your RHEL/Fedora VM. Run `uname -a`, `cat /etc/os-release`, `hostnamectl`.
   Note kernel version, distro version, architecture.
2. Run `systemd-analyze` and `systemd-analyze blame | head -20`. Which unit is slowest
   to start? Note it.
3. `systemd-analyze critical-chain` — read the chain of dependencies that delayed boot.

### Part 2 — systemd exploration (40 min)
4. `systemctl list-units --type=target` — what target are you in? Confirm with
   `systemctl get-default`.
5. `systemctl status sshd` (or another running service on your VM). Identify: Loaded
   (path to unit file), Active (state + since when), Main PID, and the last few log
   lines shown inline.
6. `systemctl list-units --type=service --state=running` — pick 3 services you don't
   recognize and `systemctl status` each; guess their purpose, then `man <name>` if it
   exists.
7. Stop and start a safe, non-critical service (e.g. `chronyd` if available, or ask your
   trainer for a safe target): `sudo systemctl stop <svc>`, confirm with `status`, then
   `sudo systemctl start <svc>` again.

### Part 3 — journalctl drills (30 min)
8. `journalctl -b | wc -l` — how many log lines this boot?
9. `journalctl -b -p err` — any errors at boot? Read a couple.
10. `journalctl -u systemd-journald --no-pager | tail -20`.
11. `journalctl --since "1 hour ago" --until now | less` — practice `less` navigation
    (`/pattern`, `n`, `q`) inside the pager.
12. Reboot the VM (`sudo reboot`, or `sudo systemctl reboot`) if permitted, log back in,
    and run `journalctl -b -1` — this reads the *previous* boot's log (persistent
    journal must be enabled; if it errors, note it — we'll fix persistence on Day 13).

### Part 4 — Incremental project: seed `boot_logger.sh` (30 min)
This script is the spine of the whole 180-day course — it will evolve every phase.
13. `sudo mkdir -p /opt/fresher_project` and take ownership:
    `sudo chown $USER:$USER /opt/fresher_project`.
14. Create `/opt/fresher_project/boot_logger.sh`:
    ```bash
    #!/bin/bash
    echo "=== Boot Logger Report ==="
    echo "Hostname: $(hostname)"
    echo "Kernel: $(uname -r)"
    echo "Boot time (systemd-analyze):"
    systemd-analyze
    echo "--- Slowest 5 units ---"
    systemd-analyze blame | head -5
    echo "--- Recent boot errors ---"
    journalctl -b -p err --no-pager | tail -10
    ```
15. `chmod +x boot_logger.sh` and run it: `./boot_logger.sh`. Confirm output makes sense
    against what you saw in Parts 1–3.

**Definition of done:** can explain BIOS/UEFI → GRUB → kernel → initramfs → systemd in
your own words · `systemd-analyze blame` and `journalctl -b -p err` run cleanly ·
`boot_logger.sh` exists in `/opt/fresher_project/`, is executable, and produces the
report above without errors.
