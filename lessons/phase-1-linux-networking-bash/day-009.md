## Theory (1h)

### A. rpm — the low-level package tool (15 min)
- RPM (Red Hat Package Manager) is the underlying format/database; `dnf` is the
  higher-level tool that resolves dependencies and talks to repos. Know both — exams
  and forensics need `rpm`, daily work uses `dnf`.
- Query: `rpm -q <pkg>` (installed version), `rpm -qi <pkg>` (info), `rpm -ql <pkg>`
  (files owned by package), `rpm -qf <path>` (**which package owns this file** — the
  forensics move), `rpm -qa` (list everything installed).
- Verify: `rpm -V <pkg>` (checks files against the package's recorded checksums/perms —
  flags tampering or accidental edits).

### B. dnf — the daily driver (20 min)
- Search/info: `dnf search <term>`, `dnf info <pkg>`.
- Install/remove: `dnf install <pkg>`, `dnf remove <pkg>`, `dnf reinstall <pkg>`.
- Update: `dnf check-update`, `dnf update` (or `upgrade`), `dnf update <pkg>` for one
  package only.
- Groups: `dnf group list`, `dnf group install "<group name>"` (bundles of related
  packages, e.g. "Development Tools").
- List installed: `dnf list installed`, `dnf list installed | grep <term>`.

### C. Repos (15 min)
- Repo definitions live in `/etc/yum.repos.d/*.repo` (still `yum.repos.d` for
  backward-compat even on `dnf`-only systems). Each has `[section]`, `baseurl` or
  `metalink`, `enabled=0/1`, `gpgcheck=1`.
- `dnf repolist` (enabled repos), `dnf repolist all` (including disabled).
- `dnf config-manager --add-repo <url>` to add a third-party repo (know it exists;
  treat with caution — untrusted repos are a real attack surface).

### D. History, rollback, and modularity (10 min)
- `dnf history` (list of transactions), `dnf history info <id>` (what a transaction
  did), `dnf history undo <id>` (roll it back) — this safety net is a big reason `dnf`
  beats manual `rpm -i`.
- Modularity (AppStream streams): some packages ship multiple versions side by side
  (e.g. different language runtimes) — `dnf module list`, `dnf module install
  <name>:<stream>`. Just know the concept exists; deep dive isn't this course's focus.

## Lab (2h)

### Part 1 — rpm forensics (30 min)
1. `rpm -q bash`; `rpm -qi bash | head -15` — read vendor, build date, license.
2. `rpm -ql bash | head -20` — see the files bash's package owns.
3. `rpm -qf $(which bash)` — confirm it traces back to the `bash` package.
4. `rpm -qf /etc/passwd` — expect "not owned by any package" (config files created at
   install time by scripts, not shipped as package content) — note *why* that's
   different from `bash`.
5. `rpm -V bash` — no output = no discrepancies. Then deliberately touch a file it owns
   (pick something harmless, e.g. change a doc file's timestamp) and re-run `rpm -V` to
   see it flag the change; revert or note it.

### Part 2 — dnf daily ops (35 min)
6. `dnf search tree` — is `tree` (the directory-listing tool from Day 2) installed?
   `dnf list installed tree` to check, `sudo dnf install -y tree` if missing.
7. `dnf info tree` — read summary, size, license, repo it came from.
8. `dnf repolist` — list your enabled repos. `dnf repolist all` — see any disabled ones.
9. `dnf check-update` — see what's pending (don't necessarily update the whole system
   mid-course unless your trainer says to — note the count instead).
10. `dnf group list` — pick one group, `dnf group info "<name>"` to see what it bundles.

### Part 3 — history and rollback (30 min)
11. `dnf history` — find the transaction ID for installing `tree` (or whatever you
    just installed).
12. `dnf history info <id>` — confirm it shows exactly what was installed.
13. `sudo dnf history undo <id>` — roll it back; confirm with `rpm -q tree` (should say
    "not installed"). Reinstall it since Day 6's log-inspection labs assumed common
    tools: `sudo dnf install -y tree`.
14. `dnf history list all | tail -20` — skim the full transaction log for the system.

### Part 4 — repo config file read (25 min)
15. `ls /etc/yum.repos.d/` — list repo files. `cat` one and identify `baseurl`/
    `metalink`, `enabled`, `gpgcheck` fields.
16. `grep -H "gpgcheck" /etc/yum.repos.d/*.repo` — confirm all your enabled repos have
    GPG checking on (a real security check you'd do on a hardened box).

**Definition of done:** used `rpm -qf` to trace a file to its owning package · ran a
`dnf install`/`dnf history undo`/reinstall cycle successfully · can explain the
difference between rpm and dnf in one sentence · confirmed `gpgcheck=1` on your repos.
