## Theory (1h)

### A. NetworkManager and nmcli (25 min)
- RHEL/Fedora manage network config via **NetworkManager**; `nmcli` is its CLI.
  Connections (profiles) are separate from devices — one device can have multiple
  saved connection profiles.
- View: `nmcli device status` (device ↔ connection mapping), `nmcli connection show`
  (all profiles), `nmcli connection show <name>` (full detail of one).
- Static IP config: `nmcli connection modify <name> ipv4.addresses 192.168.1.50/24
  ipv4.gateway 192.168.1.1 ipv4.dns "8.8.8.8 1.1.1.1" ipv4.method manual`, then
  `nmcli connection up <name>` to apply (or `nmcli connection down <name>` first if
  already active and stubborn).
- Legacy config files still exist under `/etc/NetworkManager/system-connections/` —
  know they're generated/managed by nmcli, don't hand-edit unless troubleshooting.

### B. DNS client resolution (15 min)
- `/etc/resolv.conf` lists nameservers (`nameserver 8.8.8.8`) and search domains —
  on NetworkManager-managed systems this file is often auto-generated; the *real*
  source of truth is the connection's `ipv4.dns` setting from nmcli.
- `/etc/nsswitch.conf` controls resolution *order* (files before dns, etc.) — 5-second
  mention, not a deep dive.
- `dig <domain>` (detailed query + answer + authority sections), `dig +short <domain>`
  (just the answer), `dig @8.8.8.8 <domain>` (query a specific server, bypassing
  local resolv.conf — useful for isolating "is it my DNS config or the record itself").
- `host <domain>` — quicker/terser alternative to dig for a fast check.

### C. /etc/hosts (10 min)
- Static hostname→IP mappings, checked *before* DNS per nsswitch order by default.
  Format: `<ip> <hostname> [aliases]`. Useful for local lab hostnames without standing
  up real DNS — we'll use this for the Day 17 second-VM backup setup.

### D. ss — socket statistics (10 min)
- `ss` replaces the older `netstat`. `ss -tulpn`: `-t` TCP, `-u` UDP, `-l` listening
  only, `-p` show owning process (needs root for full detail), `-n` numeric (skip DNS
  lookups, faster and clearer).
- `ss -tan state established` — filter by connection state. This is your go-to for
  "what's listening on this box and who owns it," feeding directly into the firewalld
  work on Day 18.

## Lab (2h)

### Part 1 — nmcli exploration (30 min)
1. `nmcli device status` — identify your active device and its connection name.
2. `nmcli connection show <name>` — read `ipv4.method`, `ipv4.addresses`,
   `ipv4.gateway`, `ipv4.dns`.
3. **On a disposable/snapshot-able VM only** (confirm with your trainer or take a
   snapshot first — this can disconnect you): note your current settings, then
   `nmcli connection modify <name> ipv4.addresses 192.168.100.50/24 ipv4.gateway
   192.168.100.1 ipv4.method manual`, `nmcli connection up <name>`, confirm with
   `ip a`. Revert immediately after confirming: `nmcli connection modify <name>
   ipv4.method auto`, `nmcli connection up <name>`.
4. If a live static-IP change is too risky on your VM, instead do this read-only:
   `nmcli -f ipv4 connection show <name>` and write out, from memory, the exact
   `nmcli connection modify` command you *would* run to set a static IP of
   `10.0.0.20/24` with gateway `10.0.0.1` and DNS `8.8.8.8`.

### Part 2 — DNS drills (35 min)
5. `cat /etc/resolv.conf` — note current nameservers.
6. `dig redhat.com` — read all sections: QUESTION, ANSWER, AUTHORITY. Then
   `dig +short redhat.com` for the terse version.
7. `dig @1.1.1.1 redhat.com` — compare answer to your default resolver's answer.
8. `host github.com` — compare output style to `dig +short`.
9. `dig -x 8.8.8.8` — reverse DNS lookup, resolving an IP back to a hostname.

### Part 3 — /etc/hosts (20 min)
10. `sudo sh -c 'echo "127.0.0.1 fresher-local" >> /etc/hosts'`, then `ping -c 2
    fresher-local` — confirm it resolves locally without touching DNS.
11. `getent hosts fresher-local` — confirm nsswitch resolves it via the `files` source.

### Part 4 — ss drills (35 min)
12. `ss -tulpn | head -20` — identify sshd's listening port and any other services.
13. `ss -tan state established` — list current established TCP connections (likely
    your own SSH session).
14. `sudo ss -tlpn | grep :22` — confirm sshd ownership of port 22 specifically.
15. Start a quick listener to test the tooling: `python3 -m http.server 8080 &`, then
    `ss -tulpn | grep 8080` — confirm you can see it, then `kill %1` to stop it and
    verify it disappears from `ss` output.

**Definition of done:** read and (if safe) modified an nmcli connection's static IP
settings · ran `dig`/`dig +short`/`dig @server` and interpreted the answer section ·
added and resolved an `/etc/hosts` entry · used `ss -tulpn` to identify a listening
service and confirmed removal after killing it.
