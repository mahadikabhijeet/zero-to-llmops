## Theory (1h)

### A. Anatomy of the command line (10 min)
- Terminal vs shell vs console; bash as the default shell.
- Command structure: `command -options arguments`; short (`-l`) vs long (`--all`) options.
- Getting help — the skill that outlasts every tool: `man` (and its **sections**: 1 user
  commands, 5 file formats, 8 admin — e.g. `man 5 passwd` vs `man passwd`), `--help`,
  `info`, `type`/`which`, `man -k <keyword>` (apropos).

### B. The filesystem hierarchy — FHS (15 min)
- Everything is a file; single rooted tree at `/`.
- Walk the map: `/etc` (config), `/var` (logs, spool), `/usr` (installed software),
  `/opt` (third-party — our project lives here), `/home`, `/root`, `/tmp`,
  `/proc` & `/sys` (kernel views — tie back to Day 1 boot), `/dev`, `/boot`.
- Absolute vs relative paths; `.`, `..`, `~`, `-` (previous dir).

### C. Core file tools (15 min)
- Navigate/inspect: `pwd`, `cd`, `ls` (`-l -a -h -t -r`), `file`, `stat`, `tree`.
- Manipulate: `cp` (`-r -p`), `mv`, `rm` (`-r`; why `rm -rf` deserves fear), `mkdir -p`,
  `touch`, `ln` (hard vs symbolic — inode concept, 5-min detour).
- View: `cat`, `less` (navigation keys), `head`, `tail` (**`tail -f` — the ops
  engineer's heartbeat**), `wc`.
- Find things: `find` (by name/type/size/mtime, `-exec`), `locate` vs `find`.

### D. I/O redirection — the day's core idea (20 min)
- Every process gets three streams: **stdin (0), stdout (1), stderr (2)**. File
  descriptors are just numbers pointing at open files.
- Redirect: `>` (truncate), `>>` (append), `2>` (errors), `2>&1` and `&>` (merge),
  `< file` (stdin from file), `/dev/null` (the bit bucket).
- Pipes: `|` connects stdout→stdin; `tee` splits a stream (watch AND log).
- Chaining: `;` (always), `&&` (on success), `||` (on failure) — exit codes preview
  (`echo $?`), which Day 3+ Bash scripting builds on.
- Globbing (`*`, `?`, `[a-z]`) and why quoting matters (`"$var"` — preview).

## Lab (2h)

### Part 1 — FHS expedition (20 min)
1. `ls -l /` and identify the purpose of each top-level dir aloud.
2. Find where `bash` lives (`which bash`, `type bash`); inspect it with `file` and `stat`.
3. `man 5 os-release`, then `cat /etc/os-release`.
4. Look at `/proc/cpuinfo` and `/proc/meminfo` — connect to Day 1 (kernel exposes state as files).

### Part 2 — File-management drills (30 min)
5. Build this tree with the fewest commands (`mkdir -p`, brace expansion bonus):
   `~/lab02/{projects/{alpha,beta},archive,scratch}`
6. Create 5 files in `scratch/`, copy to `archive/` preserving timestamps (`cp -p`),
   move `alpha` → `projects/alpha-v1`, delete `scratch/` safely.
7. Make a symlink and a hard link to one file; delete the original; compare what happens.
8. `find /etc -name "*.conf" -mtime -30` — explain each result. Then
   `find ~/lab02 -type f -size +0 -exec ls -lh {} \;`.

### Part 3 — Redirection gauntlet (40 min)
9. `ls /etc /nonexistent > out.txt 2> err.txt` — inspect both; explain the split.
10. Same command, one file: `&> all.txt` and the classic `> all.txt 2>&1`. Then the
    trap: `2>&1 > all.txt` — why does stderr still hit the screen? (Order matters.)
11. Count sudo-capable users: `grep -c wheel /etc/group`; count total users:
    `wc -l < /etc/passwd` (why no filename in wc's output?).
12. Pipe chains: `journalctl -b | grep -i error | wc -l`;
    `ls -lt /var/log | head -5 | tee newest_logs.txt`.
13. In terminal A: `tail -f /var/log/messages` (or `journalctl -f`). In terminal B:
    `logger "day02 test from $USER"`. Watch it arrive — this is live log-following.
14. Chaining: `mkdir /tmp/x && cd /tmp/x || echo "failed"` — test both outcomes.

### Part 4 — Incremental project step (30 min)
Evolve `/opt/fresher_project/boot_logger.sh` from Day 1 using today's material:
- Create `/opt/fresher_project/logs/`.
- Script writes normal output to `logs/boot_$(date +%F).log` (append), errors to
  `logs/boot_errors.log` via `2>>`, and also shows live output using `tee -a`.
- Add a "keep last 5 logs" cleanup: `ls -t logs/boot_*.log | tail -n +6 | xargs -r rm --`
  (walk through WHY each piece works — it's a pipe-chain capstone).
- Run it twice; verify with `tail`, `wc -l`, `find logs/ -mtime -1`.

**Definition of done:** tree correct · can explain `2>&1` ordering · live-tail demo
worked · boot_logger writes split logs and prunes to 5.
