## Theory (1h)

### A. LVM concepts (25 min)
- Three layers: **Physical Volume (PV)** — a raw disk/partition initialized for LVM;
  **Volume Group (VG)** — a pool combining one or more PVs; **Logical Volume (LV)** —
  a resizable "virtual partition" carved out of a VG. This indirection is *why* LVM
  lets you resize/extend storage without repartitioning.
- Why it matters for ops: you can add a new disk, extend the VG, then extend the LV and
  filesystem live (mostly) — the flexibility fdisk-only partitioning doesn't give you.
- Commands per layer: `pvcreate`, `pvdisplay`/`pvs`; `vgcreate`, `vgdisplay`/`vgs`,
  `vgextend`; `lvcreate`, `lvdisplay`/`lvs`, `lvextend`.

### B. Extending an LV (15 min)
- Grow the LV: `lvextend -L +1G /dev/vgname/lvname` (or `-l +100%FREE` to use all
  remaining space in the VG).
- Grow the filesystem to match (the LV growing doesn't automatically grow the
  filesystem sitting on it): `xfs_growfs /mountpoint` (xfs, online, mounted) or
  `resize2fs /dev/vgname/lvname` (ext4, can be online or offline).
- Order matters: extend LV first, then grow the filesystem — never the reverse.

### C. Swap (10 min)
- Swap = disk space used as overflow when RAM is exhausted; a performance safety net,
  not a RAM replacement. Can be a dedicated partition or an LV.
- Create: `mkswap /dev/vgname/swaplv`, activate: `swapon /dev/vgname/swaplv`, check:
  `swapon --show` or `free -h`. Persist in `/etc/fstab` with `swap` as the fstype and
  `none` as the mountpoint.

### D. NFS client + autofs (10 min)
- NFS lets you mount a remote directory as if local. Client side: `sudo dnf install
  nfs-utils`, then `mount -t nfs <server>:/export/path /local/mountpoint` (also
  persistable in fstab).
- **autofs** mounts on-demand and unmounts after idle time, instead of always-mounted —
  useful for occasional access, reduces stale-mount risk. `/etc/auto.master` points to
  map files; know the concept exists, deep configuration isn't this course's focus yet.

## Lab (2h)

### Part 1 — Build an LVM stack (40 min)
1. Attach or simulate a second disk (loopback if needed, as in Day 10 Part 2):
   `dd if=/dev/zero of=~/lab11/lvmdisk.img bs=1M count=1024; sudo losetup -fP
   ~/lab11/lvmdisk.img` — find its `/dev/loopN` name.
2. `sudo pvcreate /dev/loopN` (or `/dev/sdb` if using a real disk) — `sudo pvs` to
   confirm.
3. `sudo vgcreate fresher_vg /dev/loopN` — `sudo vgs` and `sudo vgdisplay fresher_vg`.
4. `sudo lvcreate -L 500M -n fresher_lv fresher_vg` — `sudo lvs`.
5. `sudo mkfs.xfs /dev/fresher_vg/fresher_lv`, `sudo mkdir -p /mnt/lvtest`,
   `sudo mount /dev/fresher_vg/fresher_lv /mnt/lvtest`, `df -h /mnt/lvtest`.

### Part 2 — Extend it live (30 min)
6. Fill it partway to make the exercise real: `sudo dd if=/dev/zero
   of=/mnt/lvtest/filler bs=1M count=400`, `df -h /mnt/lvtest` — nearly full.
7. `sudo lvextend -L +300M /dev/fresher_vg/fresher_lv` — `sudo lvs` to confirm new size.
8. `sudo xfs_growfs /mnt/lvtest` — `df -h /mnt/lvtest` to confirm the filesystem grew
   to match, *without unmounting*.
9. Persist it: `sudo blkid /dev/fresher_vg/fresher_lv`, add a `UUID=... /mnt/lvtest
   xfs defaults,nofail 0 2` line to `/etc/fstab`, `sudo mount -a` to verify.

### Part 3 — Swap (25 min)
10. `free -h` — note current swap size (may be 0 on a minimal VM).
11. `sudo lvcreate -L 256M -n swap_lv fresher_vg` (using remaining VG space).
12. `sudo mkswap /dev/fresher_vg/swap_lv`, `sudo swapon /dev/fresher_vg/swap_lv`,
    `free -h` and `swapon --show` to confirm.
13. Add to fstab: `UUID=<uuid> none swap sw 0 0` (get UUID via `blkid`), then
    `sudo swapoff -a && sudo swapon -a` to test the fstab line works end to end.

### Part 4 — NFS client concept walkthrough (25 min)
14. `sudo dnf install -y nfs-utils` — confirm install.
15. If a second VM/server is available with an NFS export, mount it:
    `sudo mount -t nfs <server-ip>:/export/path /mnt/nfstest`, `df -h`. If no server is
    available, instead read `man 5 nfs` and `man exports` and write 5 lines summarizing
    the client-side mount syntax and what `/etc/exports` controls server-side — you'll
    revisit this properly on Day 17 when we build a second VM for the rsync backup
    project step.
16. `cat /etc/auto.master` — identify the format even if you don't configure a live
    autofs map today.

**Definition of done:** built a full PV→VG→LV stack, formatted, mounted, and extended
it live with `xfs_growfs` without unmounting · created and persisted a swap LV ·
confirmed `mount -a`/`swapon -a` work cleanly from fstab entries · explained NFS
client mount syntax even without a live server.
