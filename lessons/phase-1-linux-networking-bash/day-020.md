## Theory (1h)

### A. nginx basics (15 min)
- `sudo dnf install -y nginx`, `sudo systemctl enable --now nginx`. Config root:
  `/etc/nginx/nginx.conf` plus `/etc/nginx/conf.d/*.conf` for site-specific server
  blocks (RHEL/Fedora convention).
- A minimal server block: `listen 80;`, `server_name`, `root <path>;`, `location / {
  ... }`. `nginx -t` syntax-checks before reload — same habit as `sshd -t`.
  `systemctl reload nginx` (graceful, no dropped connections) vs `restart` (full
  bounce).
- Default docroot is typically `/usr/share/nginx/html`; Day 19 already showed you how
  to safely point `root` elsewhere with correct SELinux context.

### B. curl -v anatomy (15 min)
- `curl -v http://host/path` shows the full exchange: `>` lines are the request sent
  (method, path, headers), `<` lines are the response (status line, headers), then the
  body.
- Request line: `GET /path HTTP/1.1`. Response status line: `HTTP/1.1 200 OK`.
  `curl -I` (HEAD request, headers only, no body — fast check).
- `curl -o file <url>` (save body to file), `curl -X POST -d "key=value" <url>` (send
  form data), `curl -H "Header: value" <url>` (custom header).

### C. HTTP verbs, status codes, headers (15 min)
- Verbs: **GET** (read), **POST** (create/submit), **PUT** (replace), **PATCH**
  (partial update), **DELETE** — the vocabulary every API and load balancer speaks.
- Status code families: 2xx success (200 OK, 201 Created, 204 No Content), 3xx
  redirect (301 permanent, 302 found/temporary), 4xx client error (400 bad request,
  401 unauthorized, 403 forbidden, 404 not found), 5xx server error (500 internal,
  502 bad gateway, 503 unavailable).
- Key headers: `Content-Type`, `Content-Length`, `Location` (redirects), `Host`
  (which vhost the client wants — critical for name-based virtual hosting),
  `Cache-Control`.

### D. TLS concepts and a self-signed cert (15 min)
- TLS provides encryption + (usually) server identity verification. The handshake, at
  a conceptual level: client and server negotiate a cipher, server presents a
  certificate, client verifies it against a trusted CA chain (self-signed certs skip
  this trust step — browsers/curl will warn, but the *encryption* still works).
- Generate a self-signed cert for lab use:
  `openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout key.pem -out cert.pem
  -subj "/CN=fresher-lab.local"`.
- nginx TLS server block adds `listen 443 ssl;`, `ssl_certificate`,
  `ssl_certificate_key`. `curl -vk https://host/` (`-k` = skip cert verification, lab
  only — never in production).

## Lab (2h)

### Part 1 — Install and configure nginx cleanly (30 min)
1. `sudo dnf install -y nginx` (if not already from Day 19), `sudo systemctl
   enable --now nginx`, `curl -I http://localhost/` — confirm 200 OK on the default
   page.
2. Create `/etc/nginx/conf.d/fresher.conf`:
   ```nginx
   server {
       listen 80;
       server_name fresher-local;
       root /opt/fresher_project/www;
       location / {
           index report.html;
       }
   }
   ```
3. `sudo nginx -t` — confirm syntax OK. `sudo systemctl reload nginx`.

### Part 2 — curl -v and HTTP anatomy (30 min)
4. `curl -v http://localhost/` against the default page — read every `>` and `<`
   line, identify the request line, status line, and at least 3 response headers.
5. `curl -I http://localhost/` — confirm same status without the body.
6. `curl -v http://localhost/does-not-exist` — read the 404 response, note the
   `Content-Type` of nginx's default error page.
7. `curl -v -H "Host: fresher-local" http://localhost/` — force the Host header to
   hit your new `fresher.conf` vhost even without DNS/hosts entry for it (should 404
   until Part 3's HTML file exists).

### Part 3 — Incremental project step: HTML report served via nginx (40 min)
8. `mkdir -p /opt/fresher_project/www`.
9. Edit `boot_logger.sh` to also emit an HTML version alongside the plain-text one —
   append this function and call it at the end of the script:
   ```bash
   generate_html_report() {
       {
         echo "<html><head><title>Fresher Project Boot Report</title></head><body>"
         echo "<h1>Boot Report — $(date)</h1><pre>"
         cat logs/boot_$(date +%F).log 2>/dev/null
         echo "</pre></body></html>"
       } > /opt/fresher_project/www/report.html
   }
   generate_html_report
   ```
10. `sudo -u svc_fresher /opt/fresher_project/boot_logger.sh` (or trigger via
    `systemctl start boot-logger.service`) — confirm `www/report.html` is created.
11. `sudo restorecon -Rv /opt/fresher_project/www` (SELinux context fix, per Day 19 —
    `/opt` content isn't auto-labeled as web content) and add the fcontext rule first
    if `restorecon` doesn't fix it:
    `sudo semanage fcontext -a -t httpd_sys_content_t "/opt/fresher_project/www(/.*)?"`
    then `restorecon -Rv` again.
12. `sudo firewall-cmd --add-service=http --permanent && sudo firewall-cmd --reload`
    (skip if already done Day 18).
13. Add `/etc/hosts` entry `127.0.0.1 fresher-local` (or use your VM's real IP + hosts
    entry on a second machine), then `curl -H "Host: fresher-local"
    http://localhost/report.html` — confirm the boot report renders as HTML.

### Part 4 — TLS with a self-signed cert (20 min)
14. `sudo mkdir -p /etc/nginx/ssl`, generate the cert per Theory D into that directory,
    add a `listen 443 ssl;` block to `fresher.conf` referencing the cert/key, `nginx -t`,
    `systemctl reload nginx`.
15. `curl -vk https://localhost/report.html` — confirm the handshake completes (read
    the `* SSL connection using...` line in curl's verbose output) and the page loads
    despite the "self-signed" trust warning.

**Definition of done:** nginx serving a custom vhost with correct SELinux context ·
`curl -v` output read and explained (request line, status line, 3+ headers) ·
`boot_logger.sh` now generates `www/report.html` and it's reachable over HTTP · a
self-signed TLS cert serves the same content over HTTPS via curl.
