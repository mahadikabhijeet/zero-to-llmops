## Theory (1h)

### A. Functions (15 min)
- ```python
  def greet(name, greeting="Hello"):
      return f"{greeting}, {name}!"
  ```
  Default arguments, keyword arguments (`greet(name="Sam", greeting="Hi")`), and
  Python's direct `return` (vs bash functions' numeric-only `return`/exit-code model
  from Day 23 — Python functions return real values of any type).
- `*args` (variable positional args, arrives as a tuple) and `**kwargs` (variable
  keyword args, arrives as a dict) — know the syntax exists; used heavily in libraries.
- Type hints (preview, deeper on Day 38): `def greet(name: str) -> str:` — optional,
  documentation + tooling aid, not enforced at runtime.

### B. Files and context managers (20 min)
- `with open("file.txt") as f:` — the context manager pattern guarantees the file is
  closed even if an exception occurs inside the block, without needing bash's manual
  trap-based cleanup from Day 23.
- Modes: `"r"` (read, default), `"w"` (write, truncates), `"a"` (append), `"r+"`
  (read+write). `f.read()` (whole file), `f.readlines()` (list of lines),
  `for line in f:` (memory-efficient line iteration — prefer this over `readlines()`
  for large files).
- Writing: `f.write("text\n")` (no automatic newline, unlike `print`). JSON files
  specifically: `json.load(f)` / `json.dump(data, f)` — foreshadows Day 27's
  `sys_report.py` JSON output.

### C. Exceptions (15 min)
- ```python
  try:
      value = int(input_str)
  except ValueError:
      print("not a number")
  except (TypeError, KeyError) as e:
      print(f"other error: {e}")
  else:
      print("succeeded, no exception")
  finally:
      print("always runs")
  ```
- `finally` is Python's direct equivalent of bash's `trap ... EXIT` from Day 23 —
  guaranteed cleanup regardless of success/failure.
- Catch specific exceptions, not a bare `except:` (which also catches things like
  `KeyboardInterrupt` — a real footgun). `raise` re-throws; `raise ValueError("msg")`
  throws your own.

### D. Dict/list idioms (10 min)
- List comprehension: `[x*2 for x in range(5)]`, with filter: `[x for x in nums if x >
  0]` — more Pythonic than manual `for` + `append` loops for simple transforms.
- Dict comprehension: `{k: v.upper() for k, v in data.items()}`.
- `.get(key, default)` avoids `KeyError` on missing dict keys — safer than `dict[key]`
  when a key might not exist. `dict.setdefault(key, [])` for building up
  grouped/nested structures.

### Part 2 — Files and context managers (35 min)
3. `with open("/opt/fresher_project/logs/boot_errors.log") as f:` (or any text file if
   that one's empty) — `for line in f: print(line.strip())`.
4. Write to a new file with `with open(...)`, confirm content with `cat` afterward.
5. Convert one of Day 25's dict structures (the expected-service-state dict) to JSON:

   indent=2)`. `cat expected.json` to confirm formatting. Then read it back:
   `with open("expected.json") as f: loaded = json.load(f); print(loaded)`.

### Part 3 — Exceptions (30 min)
6. Write a small CLI-ish script that takes a string input and tries `int()` on it,
   catching `ValueError` and printing a friendly message instead of crashing. Test
   with both a valid number and garbage text.
7. Deliberately trigger a `KeyError` on a dict lookup with `dict[missing_key]`, catch
   it specifically, then rewrite using `.get(missing_key, "default")` to avoid the
   exception entirely — compare both approaches.
8. Add a `finally:` block to one of your scripts that prints "cleanup done" — confirm
   it runs both when the `try` succeeds and when it raises.

### Part 4 — Comprehensions applied to the project (30 min)
9. Read `/opt/fresher_project/logs/boot_errors.log` (or generate some sample lines if
   empty) into a list of lines, then use a list comprehension to filter only lines
   containing "error" (case-insensitive): `[l for l in lines if "error" in
   l.lower()]`.
10. Build a dict comprehension summarizing service states from Day 25's `checks.py`
    output structure: `{svc: "up" if is_active(svc) else "down" for svc in services}`
    — refactor `checks.py` to use this comprehension instead of the manual loop, then
    confirm identical output.
11. Combine steps: write the final summary dict to a JSON file
    `~/lab26/service_summary.json` using the context-manager + `json.dump` pattern —
    this JSON-summary technique is exactly what Day 27's `sys_report.py` will build on.

**Definition of done:** wrote and called a function with a default arg and one with
`*args` · used `with open()` for both reading and writing, including JSON round-trip ·
caught at least two different specific exception types and used `finally` · refactored
a loop into a working list/dict comprehension and wrote its result to JSON.
