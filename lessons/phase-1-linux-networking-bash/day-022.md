## Theory (1h)

### A. Variables and quoting (20 min)
- Assignment has **no spaces around `=`**: `name=value`. Reference with `$name` or
  `${name}` (braces needed when concatenating: `${name}_suffix`).
- Quoting rules — the single most consequential habit in bash: **double quotes**
  (`"$var"`) allow variable/command expansion but preserve spaces as one word;
  **single quotes** (`'$var'`) suppress all expansion, completely literal; **no
  quotes** lets the shell word-split and glob-expand — the source of countless bugs
  with filenames containing spaces.
- Command substitution: `$(command)` (preferred, nestable) vs backticks (legacy,
  avoid). Arithmetic: `$((expr))`.
- Special variables: `$0` (script name), `$1`...`$9` (positional args — deeper on
  Day 23), `$#` (arg count), `$@`/`$*` (all args), `$?` (last exit code), `$$` (own
  PID, used on Day 8).

### B. test and [[ ]] (15 min)
- `test expr` and `[ expr ]` are the same command (POSIX-portable, older, requires
  careful quoting/spacing: `[ -f "$file" ]` — space after `[` and before `]` is
  mandatory).
- `[[ expr ]]` is bash's extended form — safer (no word-splitting surprises on
  unquoted variables), supports `&&`/`||`/`<`/`>` directly, and pattern matching
  (`[[ $x == abc* ]]`). Prefer `[[ ]]` in bash scripts; know `[ ]` exists for
  POSIX/sh portability.
- Common tests: `-f` (regular file exists), `-d` (directory exists), `-e` (exists,
  any type), `-z`/`-n` (string empty/non-empty), `-eq`/`-ne`/`-lt`/`-gt` (numeric
  compare — NOT `==`/`<`/`>` for numbers in `[ ]`), string `==`/`!=`.

### C. if and case (15 min)
- ```bash
  if [[ -f "$file" ]]; then
      echo "exists"
  elif [[ -d "$file" ]]; then
      echo "is a dir"
  else
      echo "missing"
  fi
  ```
- `case` for multi-branch string matching, cleaner than a long `elif` chain:
  ```bash
  case "$1" in
      start) echo starting ;;
      stop)  echo stopping ;;
      *)     echo "usage: $0 {start|stop}" ;;
  esac
  ```

### D. Loops and read (10 min)
- `for i in 1 2 3; do ...; done`; `for f in *.log; do ...; done` (globbing);
  C-style `for (( i=0; i<10; i++ )); do ...; done`.
- `while [[ condition ]]; do ...; done`; `while read -r line; do ...; done < file`
  (the correct way to read a file line by line — `-r` prevents backslash
  interpretation, always use it).
- `read -p "Prompt: " var` for interactive input.

## Lab (2h)

### Part 1 — Variables and quoting drills (30 min)
1. `name="World"; echo "Hello, $name!"` vs `echo 'Hello, $name!'` — observe the
   difference directly.
2. Create a file with a space in its name: `touch "my file.txt"`. Write a one-liner
   loop that breaks on it unquoted: `for f in $(ls); do echo $f; done` (watch it split
   "my" and "file.txt" into two). Fix it: `for f in *; do echo "$f"; done` (quoted,
   globbing not word-splitting) — confirm the fix.
3. `count=5; echo "Count is: ${count}0"` — confirm why `${}` was necessary here versus
   `$count0` (which would look for an undefined variable `count0`).

### Part 2 — test and [[ ]] (30 min)
4. `[[ -f /etc/passwd ]] && echo "exists"` — confirm true. `[[ -d /etc/passwd ]] ||
   echo "not a dir"` — confirm the `||` branch fires.
5. `x=5; [ "$x" -eq 5 ] && echo "match"` — then try (deliberately, to see the failure)
   `[ "$x" == 5 ]` in POSIX `[ ]` form for numeric compare and note it "works" by
   coincidence with `==` as a string compare here — explain why `-eq` is still correct
   practice for numbers.
6. `[[ -z "$UNSET_VAR" ]] && echo "empty or unset"` — confirm.

### Part 3 — if/case (30 min)
7. Write `~/lab22/checkfile.sh` implementing the if/elif/else from Theory C, taking a
   path as `$1`, run it against `/etc/passwd`, `/etc`, and `/nonexistent`.
8. Write `~/lab22/svcctl.sh` implementing the `case` example from Theory C — extend it
   with a `status` branch that runs `systemctl status boot-logger.service` (echo a
   placeholder is fine if you don't want to actually call systemctl inside a practice
   script). Test with no args, `start`, `stop`, `status`, and `bogus`.

### Part 4 — Loops and read (30 min)
9. `for i in {1..5}; do echo "Iteration $i"; done` (brace expansion range).
10. `for f in /opt/fresher_project/logs/*.log*; do echo "Found: $f"; done` — confirm
    it lists your project's log files by glob.
11. Write a `while read -r line; do echo "LOG: $line"; done <
    /opt/fresher_project/logs/boot_errors.log` (or any text file) — confirm it prints
    every line even if the file has no trailing newline or contains backslashes.
12. `read -p "Enter your name: " uname; echo "Hello, $uname"` — test interactively.

**Definition of done:** demonstrated the unquoted-vs-quoted word-splitting bug and its
fix · wrote and ran a working if/elif/else script and a case-statement script · used
`[[ ]]` correctly for both string and numeric tests · read a file line-by-line
correctly with `while read -r`.
