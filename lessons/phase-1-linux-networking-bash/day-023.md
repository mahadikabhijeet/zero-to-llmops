## Theory (1h)

### A. Functions and positional args (20 min)
- ```bash
  greet() {
      local name="$1"
      echo "Hello, $name"
  }
  greet "World"
  ```
  `local` scopes a variable to the function — without it, bash variables are global by
  default, a common source of bugs in longer scripts.
- Inside a function, `$1`, `$2`... refer to the function's own arguments (not the
  script's), `$#` is the function's arg count, `$@` all of them.
- At script level, `$0` is the script's own path/name — useful in usage messages
  (`echo "Usage: $0 <arg>"`).

### B. Exit codes (15 min)
- Every command/script returns 0 (success) or 1–255 (failure, meaning is
  command-specific). `exit N` at script end sets it explicitly; a function's `return N`
  sets the function's own exit status separately from the calling script's `$?`.
- Convention: check `$?` immediately after the command you care about — anything in
  between (even `echo`) overwrites it. `if command; then ... fi` — you rarely need to
  check `$?` manually since `if`/`&&`/`||` read the exit code directly.

### C. Arrays (15 min)
- Indexed arrays: `arr=(a b c)`, `${arr[0]}`, `${arr[@]}` (all elements, each properly
  word-split even with spaces — always quote: `"${arr[@]}"`), `${#arr[@]}` (length).
- Append: `arr+=(d)`. Loop: `for item in "${arr[@]}"; do ...; done`.
- Associative arrays (bash 4+): `declare -A map; map[key]=value; echo "${map[key]}"`;
  `"${!map[@]}"` for all keys.

### D. Traps and here-docs (10 min)
- `trap 'cleanup_function' EXIT` runs `cleanup_function` no matter how the script
  exits (normal, error, or signal) — the standard pattern for guaranteed cleanup (temp
  files, lock files). `trap 'echo caught INT' SIGINT` intercepts Ctrl-C specifically
  (used already in Day 8's trap demo).
- Here-docs feed multi-line input to a command without a separate file:
  ```bash
  cat <<EOF
  Multi-line
  text block, $variable expands here
  EOF
  ```
  `<<'EOF'` (quoted delimiter) disables expansion inside the block — useful for
  literal templates.

## Lab (2h)

### Part 1 — Functions (30 min)
1. Write `~/lab23/funcs.sh` with a function `is_service_running()` that takes a
   service name as `$1` and returns 0 if `systemctl is-active --quiet "$1"` succeeds,
   else 1 — don't `echo` anything, just `return` the check's exit code directly:
   `is_service_running() { systemctl is-active --quiet "$1"; }`.
2. Call it: `if is_service_running nginx; then echo "nginx up"; else echo "nginx
   down"; fi`. Test against `nginx` and a nonexistent service name.
3. Add a second function `log_msg()` using `local` for its parameter, confirm (with
   `declare -p` inside vs outside the function, or simply testing scope) that a
   same-named global variable is unaffected.

### Part 2 — Exit codes (25 min)
4. Write a 3-line script that deliberately fails a command (e.g. `ls /nonexistent`)
   then immediately `echo "Exit was: $?"` — confirm you see a non-zero code.
5. Insert an `echo "checking..."` between the failing command and the `$?` check —
   confirm `$?` now shows 0 (echo's own success) instead, illustrating why you must
   check `$?` immediately.
6. Write a function with `return 2` on a specific failure path and `return 0`
   otherwise; call it and branch on its return value with `if`.

### Part 3 — Arrays (35 min)
7. `services=(sshd nginx boot-logger.service firewalld)` — loop over it with
   `for svc in "${services[@]}"; do systemctl is-active --quiet "$svc" && echo "$svc:
   up" || echo "$svc: down"; done`.
8. `echo "Checking ${#services[@]} services"` — confirm array length.
9. Build an associative array of service→expected-state:
   `declare -A expected=( [sshd]=active [nginx]=active [bogus-svc]=inactive )`, loop
   over `"${!expected[@]}"` and compare actual vs expected state, printing PASS/FAIL
   per entry.

### Part 4 — Traps and here-docs (30 min)
10. Write `~/lab23/tempcleanup.sh`:
    ```bash
    #!/bin/bash
    tmpfile=$(mktemp)
    trap 'rm -f "$tmpfile"; echo "cleaned up $tmpfile"' EXIT
    echo "working with $tmpfile"
    sleep 3
    ```
    Run it, confirm the cleanup message fires even on normal exit. Run again and
    `Ctrl-C` it mid-sleep — confirm the trap still fires (EXIT trap catches signal
    termination too).
11. Use a here-doc to generate the report header for boot_logger's HTML output more
    cleanly — refactor the `generate_html_report` function from Day 20 to build the
    `<head>` section via `cat <<EOF ... EOF` instead of individual `echo` lines; test
    that `report.html` still renders correctly.

**Definition of done:** wrote a function using `local` correctly and returning a
meaningful exit code · demonstrated the "$? gets overwritten" gotcha · used both
indexed and associative arrays in a real check-services loop · wrote a working EXIT
trap that cleans up a temp file on both normal exit and Ctrl-C · refactored one part of
boot_logger's HTML generation to use a here-doc.
