## Theory (1h)

### A. journald persistence (15 min)
- By default on many minimal installs, the journal is **volatile** (RAM-only, lost on
  reboot) — that's why `journalctl -b -1` may have errored back on Day 1.
- Config: `/etc/systemd/journald.conf` — `Storage=persistent` (write to
  `/var/log/journal/`, survives reboot) vs `Storage=volatile` vs `auto` (persistent
  only if the directory already exists).
- `SystemMaxUse=`, `SystemKeepFree=` control disk budget for the journal itself —
  journald self-prunes, unlike flat files.
- After changing config: `sudo systemctl restart systemd-journald`.

### B. rsyslog (15 min)
- rsyslog is the traditional syslog daemon — still present on RHEL/Fedora alongside
  journald, mainly for flat-file log routing (`/var/log/messages`, `/var/log/secure`)
  and forwarding to remote log servers.
- Config: `/etc/rsyslog.conf` + `/etc/rsyslog.d/*.conf`. Facility.priority syntax:
  `authpriv.* /var/log/secure` (facility = subsystem category, priority = severity
  threshold).
- journald actually forwards to rsyslog by default on RHEL/Fedora via
  `ForwardToSyslog=yes` — the two aren't competing, they're often chained.

### C. logrotate (20 min)
- Solves what Day 2's hand-rolled `ls -t | tail -n +6 | xargs rm` did manually, but
  properly: age/size-based rotation, compression, and post-rotate hooks.
- Config: `/etc/logrotate.conf` (global defaults) + `/etc/logrotate.d/<name>` (per-app
  drop-ins). Key directives: `daily`/`weekly`/`monthly`, `rotate N` (how many old copies
  to keep), `compress`, `missingok`, `notifempty`, `copytruncate` (rotate without
  restarting the writer — needed if the app can't reopen its log file on signal).
- Runs via a systemd timer (`systemctl list-timers | grep logrotate`) or classic cron,
  not continuously. Test a config without waiting for the schedule:
  `logrotate -d /etc/logrotate.d/<name>` (dry run, verbose) or `-f` (force run now).

### D. Log triage method (10 min)
- A repeatable approach when something's broken: (1) `journalctl -u <unit> --since
  "10 min ago"` for the specific service, (2) `journalctl -p err -b` for system-wide
  errors this boot, (3) check app-specific flat logs in `/var/log/`, (4) correlate
  timestamps across sources. This ordering — narrow to broad, or broad to narrow — beats
  randomly grepping everything.

## Lab (2h)

### Part 1 — journald persistence (25 min)
1. `journalctl --disk-usage` — see current journal disk footprint.
2. `cat /etc/journald.conf | grep -v '^#' | grep -v '^$'` — confirm current `Storage=`
   setting (likely commented out/default).
3. `sudo sed -i 's/^#Storage=.*/Storage=persistent/' /etc/systemd/journald.conf` (or
   add the line if the commented default isn't present), then
   `sudo systemctl restart systemd-journald`.
4. `ls /var/log/journal/` — confirm a directory now exists (a machine-ID-named subdir).
   Reboot if time allows, then `journalctl -b -1` — should now work.

### Part 2 — rsyslog (20 min)
5. `cat /etc/rsyslog.conf | grep -v '^#' | grep -v '^$' | head -20`.
6. `ls /etc/rsyslog.d/` — inspect one drop-in file.
7. `tail -20 /var/log/secure` (or `/var/log/auth.log` naming aside — RHEL uses
   `secure`) — confirm auth-related entries; correlate one with `journalctl -u sshd`
   around the same timestamp.

### Part 3 — logrotate config for boot_logger (40 min)
8. `cat /etc/logrotate.conf` — read the global defaults (rotate count, compress,
   schedule).
9. Create `/etc/logrotate.d/fresher_project`:
   ```
   /opt/fresher_project/logs/boot_*.log {
       daily
       rotate 5
       compress
       missingok
       notifempty
       copytruncate
   }
   /opt/fresher_project/logs/boot_errors.log {
       weekly
       rotate 4
       compress
       missingok
       notifempty
       copytruncate
   }
   ```
10. Dry-run it: `sudo logrotate -d /etc/logrotate.d/fresher_project` — read the
    verbose output, confirm it targets the right files.
11. Force a real rotation to test: `sudo logrotate -f /etc/logrotate.d/fresher_project`
    — `ls -la /opt/fresher_project/logs/` — confirm rotated/compressed files appear
    (e.g. `boot_2026-07-04.log.1.gz`).

### Part 4 — Incremental project step: retire the hand-rolled prune (25 min)
12. Open `boot_logger.sh` and **remove** the Day 2 pruning line
    (`ls -t logs/boot_*.log | tail -n +6 | xargs -r rm --`) — logrotate now owns
    retention.
13. Keep the awk summary section from Day 6 (still useful — it just reflects whatever
    files logrotate has left behind).
14. Run `./boot_logger.sh` a few times, then `sudo logrotate -f
    /etc/logrotate.d/fresher_project` again, confirm the log set matches the `rotate 5`
    policy instead of the old hand-rolled "keep 5" logic — same outcome, proper tool.

**Definition of done:** journald set to `Storage=persistent` and confirmed surviving a
restart/reboot · working `/etc/logrotate.d/fresher_project` config verified with `-d`
dry-run and `-f` forced run · `boot_logger.sh`'s manual pruning line removed, retention
now owned by logrotate.
