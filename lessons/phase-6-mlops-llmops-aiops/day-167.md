# Day 167 — Capstone Spec Day: Scope, Architecture Review, Success Criteria, 8-Day Build Plan

Phase 6 · follows Day 166 (AIOps II — anomaly detection wired into Alertmanager).
Format today: **planning session**, not a tool tutorial — 1h scoping conversation
+ 2h writing the spec that Days 169–177 will execute against.

---

## Recall warm-up (5 min)
1. What are the four platform properties the Day 150 (Phase 5) capstone demonstrated?
2. What is the project's one ML component, and where does it plug into Alertmanager?
3. Name three skills from Phases 1–4 that haven't been exercised since they were taught.

## Objective
Produce a written capstone spec that the fresher will build against for the next
8 build days (169–177), demonstrating **the full stack taught across all six
phases** in one coherent, demo-able system — not a new toy, but the incremental
`/opt/fresher_project/` taken through its final, portfolio-grade form via the
golden path built in Phase 5 (Backstage template, Day 141–142).

## Scope decision (instructor + fresher, 45 min conversation)
- **Default recommendation**: scaffold a *second, small service* through the
  Backstage software template (proving the golden path actually works end to end
  for someone other than its builder) that integrates with the existing
  `fresher_project` platform — e.g., a small companion service (a webhook receiver,
  a status-page generator, or a second API) rather than a from-scratch unrelated
  app. This keeps 8 days realistic and lets every day's build step land on
  already-proven infrastructure (cluster, GitOps, observability stack, ML
  component) instead of re-deriving it.
- Alternative (if the fresher wants full ownership novelty): a small but real
  personal-utility app of his choosing, scoped tightly enough to fit the 8-day
  plan below. Either way, the **capstone must reuse**, not rebuild, the cluster,
  GitOps tooling, and observability stack already running.
- Decision to record today: which of the two paths, and the one-sentence purpose
  of the chosen service.

## Success criteria (write these down verbatim, they gate Day 175's buffer review)
1. Repo scaffolded via the Backstage template (D169), with CI green from commit 1.
2. Infra defined in Terraform (D169), applied without manual console/CLI steps.
3. Core service(s) deployed to the cluster via Helm + GitOps/ArgoCD (D170–171).
4. Dashboards + at least 2 SLOs with burn-rate alerts live (D172).
5. Security baseline: secrets never in git, SAST/dep scan in CI, one OPA/Gatekeeper
   policy enforced (D173).
6. The project's ML/AIOps anomaly-detection component visibly integrated with this
   capstone's telemetry (D174) — not a second, disconnected model.
7. Survives one chaos experiment and one load test without violating its SLOs, or
   the SLO violation is explained and remediated (D176).
8. Documented (architecture diagram, README, runbook) and demoed on video (D177).

## 8-day build plan (map to Days 169–177 — the fixed skeleton)
| Day | Build sprint | Primary deliverable |
|-----|--------------|----------------------|
| 169 | Repo scaffold + infra | Backstage-scaffolded repo; Terraform-provisioned infra |
| 170 | Core services + CI | Working service(s); green CI pipeline |
| 171 | k8s/Helm + GitOps | Deployed via Helm, managed by ArgoCD |
| 172 | Observability + SLOs | Dashboards, SLOs, burn-rate alerts |
| 173 | Security + policy + secrets | Secrets mgmt, scanning, one enforced policy |
| 174 | ML/AIOps integration | Anomaly detection wired to this service's metrics |
| 175 | REVIEW + capstone buffer | Catch up any slipped deliverable |
| 176 | Chaos + load + hardening | Chaos + k6 results, fixes applied |
| 177 | Docs + demo video | README, diagram, recorded walkthrough |

## Checkpoints (trainer confirms each before moving on)
- End of D169: repo exists, CI green, infra applied — **go/no-go to continue**.
- End of D172: SLOs are measurable in Grafana with real traffic, not placeholders.
- End of D174: the ML component's alert path is demonstrably live for this service.
- End of D176: at least one chaos/load finding was found AND fixed (not just observed).

## Trainer-review questions (ask at day's end)
1. Why does the capstone reuse the existing cluster/GitOps/ML stack rather than
   standing up parallel infrastructure?
2. What happens on Day 175 if a deliverable from 169–174 is behind schedule?
3. Walk through success criterion 6 — what does "visibly integrated" mean
   concretely, in terms of what you'll be able to show?
4. What's the single biggest risk to finishing this plan in 8 days, and what's the
   fallback if it materializes?

## Definition of done
Spec document (`capstone-spec.md`, committed to the project repo) contains: scope
decision, all 8 success criteria, the day-by-day table above, and named owners
for each checkpoint. Fresher can restate the plan unprompted.
