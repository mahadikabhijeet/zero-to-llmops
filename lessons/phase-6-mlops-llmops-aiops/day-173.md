# Day 173 — Capstone Build 5: Security + Policy + Secrets

Phase 6 · Capstone build sprint, day 5 of 7.

---

## Recall warm-up (5 min)
1. What are the capstone's two SLOs, and why those two?
2. What triggered the burn-rate alert drill yesterday, and did the runbook help?
3. What's still missing from the observability setup, per yesterday's checkpoint?

## Objectives (today)
1. Verify no secrets exist in git history or plaintext manifests — remediate any found.
2. Confirm SAST/dependency scanning and SBOM generation are wired into CI
   (Day 143 muscle) and actually gate the pipeline.
3. Author and enforce one OPA/Gatekeeper policy against the capstone's namespace.

## Deliverables
- A documented secrets audit: how secrets are managed today (vault/sops/age/
  k8s Secrets, Day 58) for this service, with any plaintext-in-git findings fixed
  and the git history scrubbed if needed (flag to trainer before force-pushing
  any history rewrite — hard-to-reverse action).
- SBOM generated for the service's container image, attached as a CI artifact.
- A SAST/dep-scan finding deliberately introduced and confirmed to fail the build,
  then removed.
- One Gatekeeper constraint (e.g., require resource limits, disallow `:latest`
  tags, require non-root) enforced against the capstone's namespace, with a
  violating manifest tested and confirmed rejected.

## Suggested time-box (3h)
- **0:00–0:20** — Recap the "what NEVER goes in git" list from Day 58 and
  Gatekeeper's constraint/constraint-template model from Day 143 before starting.
- **0:20–1:00** — Run the secrets audit: `git log -p` scan for accidental
  secrets (or a tool like `gitleaks`), confirm current secret handling, remediate
  any findings.
- **1:00–1:40** — Wire/verify SBOM generation and confirm the SAST/dep-scan gate
  with a deliberate finding.
- **1:40–2:40** — Author the Gatekeeper constraint, apply it, test with both a
  compliant and a violating manifest.
- **2:40–3:00** — Checkpoint review.

## Checkpoint (trainer confirms before Day 174 starts)
- No secrets found in plaintext in git or manifests (or confirmed remediated).
- SBOM artifact exists for the latest build.
- Gatekeeper constraint demonstrably blocks a violating manifest, applied live.

## Trainer-review questions
1. Walk through exactly how a secret reaches this service at runtime today.
2. Show me the Gatekeeper constraint rejecting a bad manifest — what was the
   exact error?
3. If a real secret had leaked into git history, what would the remediation
   process look like, and why does it require explicit approval before acting?
4. What's the one security gap you'd prioritize next with more time?

## Definition of done
Secrets audit complete and clean, SBOM generated, scan gate proven to catch a
real finding, one Gatekeeper policy enforced and tested against both compliant
and violating manifests, checkpoint confirmed.
