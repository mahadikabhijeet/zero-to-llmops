# Day 177 — Capstone Docs + Demo Video

Phase 6 · Capstone build sprint, final day. Format: build sprint producing a
portfolio artifact, not a tool tutorial.

---

## Recall warm-up (5 min)
1. What did the chaos experiment reveal yesterday, and what alert fired (if any)?
2. What was the load test's saturation point and bottleneck?
3. What hardening fix was applied and verified?

## Objectives (today)
1. Produce documentation good enough for a stranger (or an interviewer) to
   understand the capstone without a live walkthrough.
2. Record a demo video using the OBS setup already established for training
   sessions (README decisions, 2026-07-04) — this is the fresher's own first
   YouTube-able artifact, not just a recording of being taught.

## Deliverables
- An architecture diagram (any tool — even hand-drawn and photographed is fine;
  clarity matters more than polish) covering: services, data flow, the GitOps
  path, the observability path, and where the ML/AIOps component sits.
- A capstone README covering: what it does and why, how to run it, the 8 success
  criteria from `capstone-spec.md` with a checkmark and one-line evidence for each,
  links to runbooks, and the chaos/load test findings from Day 176.
- A recorded demo video (5–10 min target): live walkthrough of the architecture
  diagram, a live deploy via GitOps, the dashboards under real traffic, one
  alert firing on purpose (chaos or synthetic anomaly), and a one-line wrap-up of
  what was learned.
- The video published to the training YouTube channel per the README's existing
  recording pipeline (OBS → MP4 → upload) — **confirm publish scope/visibility
  with the instructor before making it public**, since this is an outward-facing,
  hard-to-reverse action.

## Suggested time-box (3h)
- **0:00–0:30** — Draft the architecture diagram; walk through it once with the
  trainer before recording, to catch gaps while they're still cheap to fix.
- **0:30–1:15** — Write the README, going success-criterion by success-criterion
  against `capstone-spec.md` — do not check a box without live evidence.
- **1:15–1:30** — Two-minute OBS test recording per the README's established
  pipeline (Scene B terminal + webcam, mic on, desktop audio off unless doing
  consented Q&A).
- **1:30–2:30** — Record the demo (may take 2–3 takes; that's normal and expected).
- **2:30–3:00** — Review the recording, commit the README + diagram, hand off the
  video file for the instructor's publish decision.

## Checkpoint (trainer confirms before Day 178 starts)
- All 8 success criteria in `capstone-spec.md` are checked with real evidence,
  not aspirational statements.
- The demo video shows at least one alert firing live, not just a static dashboard.
- README and diagram are committed to the capstone repo.

## Trainer-review questions
1. Pick one success criterion — show me the exact evidence backing its checkmark.
2. What part of the demo, if any, needed a second take, and why?
3. If an interviewer watched only this video, what's the one thing you'd want
   them to remember about this project?
4. What's still not "portfolio-perfect" that you'd polish with one more day?

## Definition of done
Architecture diagram, README with all 8 success criteria evidenced, demo video
recorded showing a live alert, video handed off for the instructor's explicit
publish decision (not published unilaterally).

## Day 178 preview
Job sprint: final resume pass, LinkedIn rewrite, 20 applications, and referral
asks — turning the finished capstone into placement momentum.
