## Theory (1h)

### A. The ML lifecycle, mapped to what you already know (15 min)
- Stages: **data → train → evaluate → serve → monitor → retrain**. This is a loop,
  not a line — same shape as your CI/CD loop.
- Direct analogies: training run ≈ a build; the model file is a **build artifact**
  (versioned, like a container image); serving ≈ deployment; monitoring for drift ≈
  observability/alerting; retraining trigger ≈ a CI pipeline re-run.
- The punchline for this phase: **you already know 80% of MLOps mechanically** —
  what's new is the artifact type (a model) and a few new failure modes (drift, data
  quality, non-determinism).

### B. Train/serve split (15 min)
- **Training**: batch, can be slow/expensive, run offline, needs the historical
  dataset, produces a model artifact + metrics.
- **Serving**: online, latency-sensitive, needs to be small/fast/reliable, takes one
  input at a time (or small batches), returns a prediction.
- Same discipline as build vs deploy: never train inside the serving path; never let
  serving depend on the training environment being up.

### C. scikit-learn "hello-model" (20 min)
- Core vocabulary: **features** (X, inputs) and **labels** (y, what you predict).
- `train_test_split` — never evaluate on data the model trained on (the ops
  equivalent of "never test in prod").
- A model object has two verbs: `.fit(X_train, y_train)` (train) and
  `.predict(X_test)` (serve). That's the whole interface for most scikit-learn models.
- A simple, well-known classifier: `sklearn.ensemble.RandomForestClassifier` or
  `sklearn.linear_model.LogisticRegression`. Evaluate with `accuracy_score` and
  `classification_report` from `sklearn.metrics`.
- Persistence: `joblib.dump(model, "model.joblib")` / `joblib.load(...)` — this file
  is your build artifact from here on.

### D. Reproducibility concerns preview (10 min)
- `random_state=` for reproducible splits/training — the ML equivalent of pinning a
  dependency version. Flag it now; Day 153 (DVC) makes the whole pipeline
  reproducible.

## Lab (2h)

### Part 1 — Environment (20 min)
1. `python3 -m venv ~/ml-lab && source ~/ml-lab/bin/activate`
2. `pip install scikit-learn pandas joblib` — confirm versions with `pip freeze`.

### Part 2 — Hello-model (45 min)
3. In a REPL or script, load a built-in dataset:
   `from sklearn.datasets import load_iris; data = load_iris()`.
4. `from sklearn.model_selection import train_test_split` — split 80/20 with
   `random_state=42`.
5. Train a `RandomForestClassifier(random_state=42)` on the training split; call
   `.fit()`.
6. Predict on the test split; print `accuracy_score` and `classification_report`.
   Note the accuracy — this is your baseline metric, the ML equivalent of a test
   pass rate.

### Part 3 — Save/load as an artifact (35 min)
7. Write `train.py`: loads data, splits, trains, saves `model.joblib` via joblib,
   prints accuracy to stdout.
8. Write `predict.py`: loads `model.joblib`, accepts a hardcoded sample row, prints
   the predicted class. Run both scripts end to end.
9. Delete `model.joblib`, rerun `train.py`, confirm `predict.py` still works —
   this is your first "artifact rebuild" drill.

### Part 4 — Project scaffold (20 min)
10. In `/opt/fresher_project/`, create an `ml/` directory with `train.py`,
    `predict.py`, `requirements.txt` (scikit-learn, pandas, joblib) — this is the
    scaffold the anomaly-detection model (Day 165) will land in. No project metrics
    used yet; that starts Day 152 with MLflow.
11. Commit the scaffold to the project repo with a clear message.

**Definition of done:** venv built, hello-model trains and reports accuracy > baseline
(better than random guessing), model save/load round-trips correctly, `ml/` scaffold
committed to the project repo.
