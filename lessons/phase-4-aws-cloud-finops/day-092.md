## Theory (1h)

### A. Cloud service & responsibility models (15 min)
- IaaS vs PaaS vs SaaS — where does undifferentiated heavy lifting move? (EC2 vs Elastic
  Beanstalk vs Gmail as anchors).
- Shared responsibility model: AWS secures *of* the cloud (hardware, hypervisor, physical
  facilities); you secure *in* the cloud (IAM, data, OS patching on EC2, network config).
  This line shifts as you move IaaS→PaaS→SaaS.
- Regions vs Availability Zones (AZs): a region is a geography with 3+ isolated AZs
  (separate power/network); design for AZ failure, not just instance failure.

### B. AWS account structure & billing basics (15 min)
- Root account vs IAM users — **never use root day-to-day**; root is for account-level
  tasks only (billing, closing account, first IAM setup).
- Free tier types: 12-months-free, always-free, and trials — check the free-tier page,
  not memory, before provisioning anything.
- Support plans, service quotas, and why every lab in this course teaches teardown.

### C. IAM fundamentals (20 min)
- Users, groups, roles, policies — the four building blocks.
- Policy = JSON document (Effect/Action/Resource/Condition); AWS-managed vs
  customer-managed vs inline.
- Principle of least privilege — start deny-by-default, add only what's needed.
- `aws configure` and named profiles (`--profile`) — why never hardcode keys in code.

### D. Console orientation (10 min)
- Region selector (top-right) — most services are regional; a resource created in
  `ap-south-1` is invisible in `us-east-1`.
- Resource Groups & Tag Editor — how you'll find everything later (ties to Day 117 FinOps
  tagging strategy).
- CloudShell — a browser-based CLI with AWS CLI preinstalled, no local setup needed.

## Lab (2h)

### Part 1 — Account creation & hardening (30 min)
1. Create AWS free-tier account (if not already done) using a dedicated email; note the
   12-digit account ID.
2. Enable MFA on the **root** user immediately (virtual MFA app, e.g. an authenticator app).
3. Set an account alias: IAM console → Account settings → Alias (e.g. `fresher-devops`).

### Part 2 — First IAM user + CLI (40 min)
4. IAM console → Users → create user `fresher-admin`; do NOT attach `AdministratorAccess`
   directly — instead create a group `admins`, attach `AdministratorAccess` to the group
   (temporarily, for learning speed — Day 93 tightens this), add user to group.
5. Generate access keys for `fresher-admin` (Security credentials tab → Access keys →
   CLI use case).
6. Install AWS CLI v2 locally; run `aws configure --profile fresher` and enter
   Access Key ID, Secret Access Key, default region, output format (`json`).
7. Verify: `aws sts get-caller-identity --profile fresher` — confirm it returns the IAM
   user ARN, not root.

### Part 3 — Console tour (30 min)
8. Walk the top service categories: Compute (EC2, Lambda), Storage (S3), Database (RDS),
   Networking (VPC), Containers (ECR/ECS/EKS) — just locate each, no resources yet.
9. Open Billing & Cost Management → Bills — note current spend (should be $0.00).
10. `aws ec2 describe-regions --output table --profile fresher` — see all regions from
    the CLI; pick and note your default working region for the course.

### Part 4 — Documentation (20 min)
11. In the project repo, create `docs/aws-account.md`: account alias, chosen default
    region, IAM group/user naming convention, and a "never do this" list (share root
    creds, commit access keys, use `AdministratorAccess` in prod).
12. Commit: `git add docs/aws-account.md && git commit -m "docs: AWS account setup"`.

**Definition of done:** root MFA enabled · `fresher-admin` IAM user working via CLI
profile · console tour complete · `docs/aws-account.md` committed.
