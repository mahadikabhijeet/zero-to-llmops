## Theory (1h)

### A. NACLs vs Security Groups (15 min)
- Network ACL (NACL): stateless, subnet-level, evaluates numbered rules in order (lowest
  first), supports explicit Allow AND Deny — the opposite of SG's allow-only model.
- Stateless means: if you allow inbound 22, you must *also* explicitly allow the
  ephemeral-port outbound response traffic (typically 1024–65535), unlike SGs which
  auto-allow return traffic.
- Default NACL allows all traffic both ways; custom NACLs default-deny — most designs
  leave NACLs permissive and do the real enforcement at the SG layer (defense-in-depth
  is the exception, not the default, for a learning setup).

### B. VPC Endpoints (15 min)
- Problem: private-subnet resources need AWS APIs (S3, DynamoDB, etc.) without routing
  through the public internet via NAT (cost + security surface).
- Gateway endpoints (S3, DynamoDB only): free, route-table-based, no ENI.
- Interface endpoints (most other services): billed per-hour + per-GB, create an ENI
  with a private IP in your subnet, backed by PrivateLink.
- Today's takeaway: an S3 gateway endpoint would let yesterday's private instance reach
  S3 with zero NAT cost — a direct FinOps lever (ties to Day 117).

### C. VPC Peering (15 min)
- 1:1 connection between two VPCs (same or different accounts/regions), non-transitive
  (if A↔B and B↔C, A cannot reach C through B) — this is the #1 peering gotcha.
- Requires: peering connection request/accept, route table entries on both sides
  pointing at the peering connection, and non-overlapping CIDRs (Day 96's planning
  point pays off here).
- Alternative for many-VPC topologies: Transit Gateway (hub-and-spoke) — mention only,
  out of scope for the free tier at this stage.

### D. Bastion host pattern (15 min)
- A bastion (jump host) sits in a public subnet with a narrow SG (SSH from your IP
  only) and is the *only* path into private-subnet instances.
- SSH agent forwarding (`ssh -A`) or `ProxyJump`/`ProxyCommand` (recall Day 17) lets you
  hop through the bastion without copying private keys onto it.
- Production alternative worth naming: AWS Systems Manager Session Manager — no bastion,
  no open SSH port, IAM-based access; mention as the modern replacement, build the
  classic pattern today because it teaches the network fundamentals.

## Lab (2h)

### Part 1 — Rebuild the VPC skeleton (25 min)
1. Recreate Day 96's VPC/subnets/IGW/route tables (script it this time —
   `docs/aws-network/build-vpc.sh` calling the same `aws ec2` commands — so it's
   reusable for Day 107's Terraform version).

### Part 2 — S3 Gateway endpoint (25 min)
2. Create an S3 gateway endpoint: `aws ec2 create-vpc-endpoint --vpc-id <vpc-id>
   --service-name com.amazonaws.<region>.s3 --route-table-ids <private-rt-id>
   --vpc-endpoint-type Gateway`.
3. Launch an instance in the private subnet (no NAT this time — skip NAT Gateway
   creation to prove the point), and from it run `aws s3 ls` (with an instance profile
   role attached, or a local profile if testing manually) — confirm S3 reachability
   with zero NAT Gateway.

### Part 3 — Bastion + NACL drill (45 min)
4. Launch a bastion in the public subnet (SG: SSH from your IP only) and a target
   instance in the private subnet (SG: SSH only from the bastion's SG, by SG-reference
   not CIDR).
5. `ssh -i key.pem -A ec2-user@<bastion-ip>` then `ssh ec2-user@<private-ip>` from
   inside — confirm agent forwarding works without copying the key onto the bastion.
6. Attach a custom NACL to the private subnet: allow inbound 22 from the VPC CIDR only,
   allow outbound ephemeral ports 1024–65535, deny everything else. Test SSH still works
   from the bastion, and confirm the private instance cannot be reached directly from
   your laptop.
7. Break it on purpose: remove the ephemeral-port outbound rule, retry SSH, watch it
   hang (stateless NACL consequence) — then restore it.

### Part 4 — Teardown (mandatory, 25 min)
8. Terminate both instances. Delete the VPC endpoint (`aws ec2 delete-vpc-endpoints`),
   custom NACL (after disassociating), route tables, IGW, subnets, VPC — same order
   discipline as Day 96.
9. Verify: `aws ec2 describe-vpcs --filters "Name=tag:Name,Values=fresher-vpc"` and
   `aws ec2 describe-vpc-endpoints` both return empty.

**Definition of done:** private instance reached S3 via gateway endpoint with no NAT ·
bastion→private SSH via agent-forwarding worked · NACL statelessness demonstrated by
breaking and fixing the ephemeral-port rule · full teardown verified.
