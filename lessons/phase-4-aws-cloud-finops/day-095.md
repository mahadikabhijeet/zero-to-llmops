## Theory (1h)

### A. EBS deep and snapshots (15 min)
- EBS volume types: `gp3` (general purpose, default choice), `io2` (high IOPS), cost
  scales with size + provisioned IOPS/throughput on some types.
- Snapshots are incremental (only changed blocks after the first), stored in S3
  internally, region-scoped (copy across regions explicitly if needed).
- Snapshot → new volume → attach to a new instance is the standard "clone a disk"
  pattern; also the backbone of AMI creation (`aws ec2 create-image`).

### B. Launch templates (15 min)
- A launch template versions everything `run-instances` needs (AMI, type, SG, user-data,
  key) so an ASG can reference "version $Latest" instead of re-specifying every field.
- Replaces the older "launch configuration" (immutable, deprecated pattern) — launch
  templates are versioned and mutable at the template level.
- `aws ec2 create-launch-template --launch-template-name fresher-lt --version-description
  v1 --launch-template-data file://lt-data.json`.

### C. Auto Scaling Groups (15 min)
- ASG = desired/min/max capacity + a launch template + one or more subnets (spread
  across AZs for resilience).
- Scaling policies: target tracking (e.g. keep CPU at 50%), step scaling, scheduled
  scaling — target tracking is the default recommendation for most cases.
- Health checks: EC2 (is the instance up?) vs ELB (did the load balancer health check
  pass?) — ELB health check is stricter and required once an ALB is attached.

### D. ALB & target groups (15 min)
- Application Load Balancer operates at L7 (HTTP/HTTPS) — path/host-based routing,
  unlike a Network Load Balancer (L4).
- Target group: the pool of instances/IPs the ALB routes to, each with its own health
  check path/interval/thresholds; an ASG can auto-register/deregister instances into a
  target group.
- Listener → rule → target group chain: a listener on port 80/443 evaluates rules (host
  header, path pattern) and forwards to the matching target group.

## Lab (2h)

### Part 1 — Launch template + user-data (30 min)
1. Reuse Day 94's SG pattern (recreate SG, keypair — nothing persists after teardown) but
   restrict SSH to your IP.
2. Build `lt-data.json`: AMI id, `t3.micro`, key name, SG id, and user-data that installs
   nginx and writes the instance-id into `index.html` via IMDSv2 (so each instance shows
   a different page — proves load balancing later).
3. `aws ec2 create-launch-template --launch-template-name fresher-lt --launch-template-data
   file://lt-data.json`.

### Part 2 — Target group + ALB (40 min)
4. Find your default VPC's subnets in 2+ AZs: `aws ec2 describe-subnets --filters
   "Name=vpc-id,Values=<default-vpc-id>" --query 'Subnets[].[SubnetId,AvailabilityZone]'`.
5. Create target group: `aws elbv2 create-target-group --name fresher-tg --protocol HTTP
   --port 80 --vpc-id <vpc-id> --health-check-path /`.
6. Create ALB (needs its own SG allowing inbound 80 from `0.0.0.0/0`): `aws elbv2
   create-load-balancer --name fresher-alb --subnets <subnet-1> <subnet-2>
   --security-groups <alb-sg-id>`.
7. Create listener: `aws elbv2 create-listener --load-balancer-arn <alb-arn>
   --protocol HTTP --port 80 --default-actions
   Type=forward,TargetGroupArn=<tg-arn>`.

### Part 3 — ASG wired to the ALB (35 min)
8. `aws autoscaling create-auto-scaling-group --auto-scaling-group-name fresher-asg
   --launch-template LaunchTemplateName=fresher-lt,Version='$Latest' --min-size 2
   --max-size 3 --desired-capacity 2 --vpc-zone-identifier "<subnet-1>,<subnet-2>"
   --target-group-arns <tg-arn> --health-check-type ELB --health-check-grace-period 60`.
9. Wait for 2 healthy targets: `aws elbv2 describe-target-health --target-group-arn
   <tg-arn>`. `curl` the ALB's DNS name repeatedly — confirm the instance-id in the
   response changes (load balancing proof).
10. Terminate one instance manually via `aws ec2 terminate-instances`; watch the ASG
    replace it automatically (`describe-auto-scaling-groups`) — this is self-healing.

### Part 4 — Teardown (mandatory, 15 min)
11. Delete in dependency order: `aws autoscaling delete-auto-scaling-group
    --auto-scaling-group-name fresher-asg --force-delete`, then `aws elbv2
    delete-load-balancer`, `aws elbv2 delete-target-group`, `aws ec2
    delete-launch-template`, then the SGs and keypair.
12. Confirm zero running instances and zero load balancers:
    `aws elbv2 describe-load-balancers` returns empty.

**Definition of done:** ALB distributes traffic across ≥2 healthy targets · terminated
instance auto-replaced by ASG · everything deleted in correct order and verified empty.
