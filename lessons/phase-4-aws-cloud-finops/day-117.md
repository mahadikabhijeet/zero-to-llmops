## Theory (1h)

### A. What FinOps actually is (15 min)
- FinOps is a cultural/operational practice, not a tool: it puts engineering, finance,
  and business together around a shared, real-time view of cloud spend, so cost becomes
  a first-class engineering signal (like latency or error rate) rather than a monthly
  finance surprise.
- The FinOps Foundation's lifecycle: **Inform → Optimize → Operate** — Inform means
  everyone can see and understand costs (today's focus: tagging + allocation);
  Optimize is rightsizing/commitments (Day 118); Operate is making cost review a
  standing engineering habit, not a quarterly fire drill.
- Recall Day 93: budgets/alerts were the *safety* layer. FinOps is the *ongoing
  discipline* layer built on top of that safety net — today formalizes what Day 93
  started informally.

### B. The cost model — where money actually goes (15 min)
- Three cost shapes: **on-demand** (pay per use, most flexible, most expensive per
  unit), **commitment-based** (Reserved Instances/Savings Plans — commit to spend/usage
  for a discount), **spot/preemptible** (steep discount, can be reclaimed — Day 118
  covers this in depth).
- Cost is never flat across a bill: compute, storage, data transfer (egress — recall
  Day 116), and managed-service premiums (e.g. paying for RDS's management layer on top
  of raw compute+storage) are separate line items that need separate levers.
- **Unit economics**: the real FinOps question isn't "how much did we spend" but "cost
  per unit of business value" (cost per customer, per transaction, per API call, per
  build) — a rising bill next to a faster-rising user base is healthy; the reverse is a
  crisis even if the absolute number looks small.

### C. Tagging strategy — the foundation of everything else (15 min)
- Untagged spend is unallocatable spend — this is the single most common FinOps failure
  in real companies: teams build first, tag later (or never), and cost attribution
  becomes forensic archaeology.
- A minimal viable tagging taxonomy: `cost-center` (which budget owns this), `team` or
  `owner` (who to page about it), `environment` (prod/staging/dev — different
  optimization urgency), `project`/`service` (which product line). Fewer, consistently
  enforced tags beat a rich taxonomy nobody follows.
- Enforcement mechanisms: AWS Tag Policies (Organizations), Service Control Policies
  denying resource creation without required tags, or — the practical version for this
  course — Terraform's `default_tags` provider block (Day 108) applied at the module
  level so tags are structurally impossible to omit.

### D. Allocation and showback/chargeback (15 min)
- Allocation: attributing shared/untaggable costs (e.g. a shared NAT Gateway, a shared
  EKS control plane) to consuming teams via a proportional method (e.g. by
  data-transfer volume, by node-hours consumed) — perfect allocation is impossible;
  defensible allocation is the actual goal.
- **Showback**: teams see their cost allocation as information, no money moves — builds
  awareness without political friction; the recommended starting point for any
  organization new to FinOps.
- **Chargeback**: allocated cost is actually billed internally to the team's budget —
  drives real behavior change but requires allocation accuracy and organizational trust
  that showback alone doesn't demand; skipping straight to chargeback before allocation
  is trusted is a common, costly mistake.

## Lab (2h)

### Part 1 — Cost Explorer, real numbers (30 min)
1. Open Cost Explorer (enabled Day 93); group by Service for the last 30 days (should
   be near-zero given teardown discipline, which is itself worth noting — “this is what
   disciplined teardown looks like on a real bill”).
2. Group the same view by Tag — if `Project` or `Environment` tags exist from earlier
   labs, note the allocation gap where they don't; this gap *is* today's lab
   problem to fix.
3. `aws ce get-cost-and-usage --time-period Start=<30d-ago>,End=<today> --granularity
   MONTHLY --metrics "UnblendedCost" --group-by Type=DIMENSION,Key=SERVICE` — the CLI
   equivalent, for scripting cost reports later.

### Part 2 — Build and enforce a tagging taxonomy (40 min)
4. Define the taxonomy in `docs/finops/tagging-policy.md`: the four minimal tags from
   Theory C, their allowed values, and who owns enforcement.
5. Add a `default_tags` block to the Day 108 Terraform provider configuration
   implementing this taxonomy; `terraform plan` against the module set — confirm every
   resource picks up the tags without per-resource edits.
6. Write an AWS Config rule (or a documented intent if not deploying it live, to avoid
   Config's per-item cost) checking for `required-tags` compliance on EC2/S3/RDS;
   `aws configservice describe-config-rules` if deployed, or document the rule JSON in
   `docs/finops/` if not.

### Part 3 — Allocation exercise (30 min)
7. Take the Day 108 module set's shared resources (e.g. a shared NAT Gateway serving
   both compute and database subnets) and write an allocation method: e.g. "NAT
   Gateway cost split 70/30 between compute and database traffic based on historical
   data-processed metrics" — document the method and the arithmetic, not just the
   conclusion.
8. Compute a toy unit-economics number for the project: pick a proxy "unit" (e.g. per
   CI pipeline run, or per smoke-test execution from Day 110) and estimate infra cost
   per unit using this week's actual (near-zero, teardown-disciplined) numbers plus a
   hypothetical "if this ran 24/7 in prod" projection.

### Part 4 — Showback report (20 min)
9. Build a one-page showback report (`docs/finops/showback-report-template.md`):
   project name, allocated cost by tag/service, month-over-month trend placeholder,
   and one flagged anomaly format (e.g. "NAT Gateway data-processed spiked 3x — see
   footnote"). This template is what Day 120's capstone report will be built from.
10. Commit everything: `git add docs/finops/ terraform/ && git commit -m "feat: FinOps
    tagging taxonomy, allocation method, showback template"`.

**Definition of done:** tagging taxonomy defined and enforced via Terraform
`default_tags` · allocation method documented with real arithmetic for a shared
resource · toy unit-economics number computed · showback report template built and
committed.
