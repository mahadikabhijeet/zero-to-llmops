## Theory (1h)

### A. Why cost safety comes before anything else (10 min)
- Free tier limits are per-service, per-month, and easy to blow past silently (e.g. one
  forgotten NAT Gateway or an oversized RDS instance running overnight).
- AWS does not stop you at $0 — budgets/alerts are the only proactive guardrail; Cost
  Explorer is reactive (shows spend after it happens).
- This is why Day 93 comes before Day 94's first EC2 instance — never invert this order.

### B. Billing alerts & AWS Budgets (20 min)
- Enable "Receive Billing Alerts" (Billing preferences) so CloudWatch can see billing
  metrics in `us-east-1` (billing metrics are only published there).
- AWS Budgets: cost budgets (e.g. alert at $1, $5, $10 thresholds), usage budgets, and
  free-tier-usage budgets (built-in template tracks free-tier limits specifically).
- Key CLI: `aws budgets create-budget --account-id <id> --budget file://budget.json
  --notifications-with-subscribers file://notify.json`.
- Cost Explorer: enable it (24h to populate), group by service/tag, forecast view.

### C. IAM deep — policies as JSON (20 min)
- Anatomy: `Version`, `Statement` (list of `{Effect, Action, Resource, Condition}`).
- Evaluation logic: explicit Deny always wins; default is implicit deny; an Allow must
  exist somewhere (identity policy or resource policy) for access to work.
- Roles vs users: a role has no long-term credentials — it's assumed (`sts:AssumeRole`)
  and yields temporary credentials; this is how EC2 instances, Lambda, and cross-account
  access work without embedded secrets.
- MFA enforcement via policy condition: `"Condition": {"BoolIfExists":
  {"aws:MultiFactorAuthPresent": "false"}}` with Deny — the standard "require MFA" pattern.

### D. CLI profile hygiene (10 min)
- `~/.aws/credentials` (secrets) vs `~/.aws/config` (region/output/role config) —
  never commit either; confirm `.gitignore` covers `.aws/`.
- `aws configure list --profile <name>` to audit what's active without printing secrets.
- Rotating access keys: create new, update profile, verify, then deactivate/delete old.

## Lab (2h)

### Part 1 — Budgets & alerts (40 min)
1. Billing console → Billing preferences → enable "Receive Billing Alerts".
2. Budgets → create a **Zero Spend Budget** (AWS's free-tier-alert template) using your
   email for notification.
3. Create a second budget manually: cost budget, $5/month, alert at 80% and 100% actual,
   via console or `aws budgets create-budget` with a JSON file committed to
   `docs/aws-cost/budget.json` (redact account ID before committing).
4. Cost Explorer → enable (note: takes up to 24h to show data) → set default view grouped
   by Service.

### Part 2 — IAM policy authoring (40 min)
5. Write a customer-managed policy JSON granting only `ec2:Describe*` and
   `s3:ListAllMyBuckets` (read-only exploration) — save as `docs/aws-cost/readonly-policy.json`.
6. Create it: `aws iam create-policy --policy-name FresherReadOnly --policy-document
   file://readonly-policy.json --profile fresher` (use the `AdministratorAccess`-holding
   profile from Day 92 to create it).
7. Create a new IAM group `readonly-explorers`, attach the policy, and add a *second*
   test IAM user to it. Assume that user's identity (new CLI profile) and confirm
   `aws ec2 describe-instances` works but `aws ec2 run-instances` fails with
   `AccessDenied`.
8. Attach an MFA-required deny policy (from Theory C) to the `admins` group from Day 92;
   confirm a non-MFA'd session gets denied on a sensitive action.

### Part 3 — Documentation & teardown discipline (20 min)
9. Update `docs/aws-account.md` with: budget thresholds set, the MFA-enforcement policy
   ARN, and a standing rule: "every lab from Day 94 on ends with an explicit teardown
   step — no exceptions."
10. Commit: `git add docs/aws-cost/ docs/aws-account.md && git commit -m "feat: cost
    guardrails + MFA-enforced IAM before first billable resource"`.

**Definition of done:** zero-spend + $5 budgets live with email alerts · Cost Explorer
enabled · least-privilege policy created and tested (allow + deny both verified) · MFA
enforcement policy attached · docs committed.
