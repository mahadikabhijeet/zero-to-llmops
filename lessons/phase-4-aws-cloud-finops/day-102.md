## Theory (1h)

### A. Lambda fundamentals (15 min)
- Lambda = run code without managing servers; you supply a handler function, AWS
  manages the runtime, scaling (including to zero), and patching of the execution
  environment.
- Execution role: every function needs an IAM role (least-privilege, per Day 93) — this
  is how it's granted access to other AWS services, no embedded credentials.
- Cold start vs warm start; timeout (max 15 min) and memory config (which also scales
  CPU proportionally) — tuning memory is a real cost/performance lever (FinOps tie-in).

### B. Triggers and event sources (15 min)
- Push model (synchronous or async invoke): API Gateway, S3 events, ALB.
- Poll model (Lambda polls on your behalf): SQS, DynamoDB Streams, Kinesis.
- Event source mapping vs direct invoke vs resource-based trigger permission
  (`aws lambda add-permission`) — S3 needs the last one explicitly to invoke a function.

### C. API Gateway (15 min)
- REST API vs HTTP API: HTTP API is newer, cheaper, simpler — the default choice unless
  you need REST API's advanced features (usage plans, request validation, private
  endpoints).
- Route → integration (Lambda proxy integration is the common pattern: the whole
  request is passed to Lambda, Lambda returns a structured response object).
- Stages (`dev`, `prod`) and deployment — an API Gateway change isn't live until
  deployed to a stage.

### D. EventBridge, SQS, SNS overview (15 min)
- EventBridge: event bus + rules (pattern-matching on event JSON) → targets; the
  decoupling backbone for event-driven architectures; scheduled rules replace cron for
  serverless (`rate()`/`cron()` expressions).
- SQS: queue for decoupling producers/consumers, at-least-once delivery, visibility
  timeout, dead-letter queues for poison messages.
- SNS: pub/sub fan-out — one message to many subscribers (email, SQS, Lambda); SNS+SQS
  fan-out is the classic pattern (SNS topic → multiple SQS queues, one per consumer).

## Lab (2h)

### Part 1 — First Lambda function (30 min)
1. Write a minimal Python handler (`lambda_function.py`) that returns a JSON greeting;
   zip it: `zip function.zip lambda_function.py`.
2. Create an execution role with just `AWSLambdaBasicExecutionRole` (CloudWatch Logs
   only) attached: `aws iam create-role` + `attach-role-policy`.
3. `aws lambda create-function --function-name fresher-hello --runtime python3.12
   --handler lambda_function.handler --role <role-arn> --zip-file fileb://function.zip`.
4. Invoke directly: `aws lambda invoke --function-name fresher-hello --payload '{}'
   out.json && cat out.json`.

### Part 2 — API Gateway trigger (35 min)
5. Create an HTTP API: `aws apigatewayv2 create-api --name fresher-api --protocol-type
   HTTP --target <lambda-arn>` (quick-create mode auto-wires the integration + route +
   `$default` stage).
6. `aws lambda add-permission --function-name fresher-hello --statement-id apigw
   --action lambda:InvokeFunction --principal apigateway.amazonaws.com --source-arn
   "<api-execution-arn>/*/*"`.
7. `curl <api-endpoint>` — confirm the Lambda response comes back over HTTP.

### Part 3 — S3 event trigger (30 min)
8. Create a bucket; write a second Lambda that logs the uploaded object key to
   CloudWatch Logs.
9. `aws lambda add-permission --function-name fresher-s3-logger --statement-id s3invoke
   --action lambda:InvokeFunction --principal s3.amazonaws.com --source-arn
   <bucket-arn>`.
10. `aws s3api put-bucket-notification-configuration` wiring `s3:ObjectCreated:*` to
    the function; upload a file (`aws s3 cp`); check CloudWatch Logs
    (`aws logs tail /aws/lambda/fresher-s3-logger`) for the event.

### Part 4 — EventBridge scheduled rule + SQS (15 min)
11. `aws events put-rule --name fresher-schedule --schedule-expression "rate(5 minutes)"`;
    `put-targets` pointing at `fresher-hello`; add the matching
    `lambda add-permission` for `events.amazonaws.com`. Watch one invocation land in logs.
12. Create an SQS queue (`aws sqs create-queue`), send a test message
    (`aws sqs send-message`), receive it (`aws sqs receive-message`), delete it
    (`aws sqs delete-message`) — the full lifecycle in one pass.

### Part 5 — Teardown (mandatory, 15 min)
13. Disable/delete the EventBridge rule and its targets, delete the S3 bucket, delete
    the API Gateway API, delete both Lambda functions, delete the SQS queue, delete the
    IAM role (detach policy first).
14. Confirm `aws lambda list-functions`, `aws apigatewayv2 get-apis`, `aws sqs
    list-queues` all return empty of lab resources.

**Definition of done:** Lambda invoked directly, via API Gateway, via S3 event, and on
an EventBridge schedule · SQS send/receive/delete lifecycle demonstrated · all
serverless resources and the IAM role deleted and verified.
