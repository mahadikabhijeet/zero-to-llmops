## Theory (1h)

### A. What "end-to-end" means today (10 min)
- Not new AWS concepts — this is an **integration** day: every piece from Days 103–109
  wired into one pipeline that runs unattended from `git push` to a live, HTTPS URL.
- The test of understanding this phase isn't "can you run each command" but "can you
  explain the whole chain without gaps" — today's lab is that chain, built once, fully.

### B. The pipeline shape (20 min)
- Trigger: push to `main` → GitHub Actions workflow.
- Job 1 (infra): `terraform plan`/`apply` against the Day 108 module set (network,
  compute, database, storage) — infra changes ship through the same pipeline as app
  changes, not a separate manual process.
- Job 2 (build): Docker build → push to ECR (Day 103's flow, OIDC auth — no static
  keys, per Day 103's CI wiring).
- Job 3 (deploy): `aws ecs update-service --force-new-deployment` (ECS path) or `helm
  upgrade` against EKS (Day 104's path) — whichever your project's compute module uses.
- Job 4 (verify): a smoke test — `curl -f https://<domain>/health` — that fails the
  pipeline loudly if the deploy didn't actually work, not just "the API call succeeded."

### C. DNS + TLS in the loop (15 min)
- Recall Day 101: Route 53 Alias + ACM cert, but now the *target* is the ALB from the
  ECS/EKS module, not a CloudFront-fronted S3 site — same DNS/cert mechanics, different
  origin.
- ACM cert validation and DNS record creation belong in Terraform too (an
  `aws_acm_certificate` + `aws_acm_certificate_validation` + `aws_route53_record`
  resource chain) — manual console clicking from Day 101 becomes code today.
- HTTPS listener on the ALB (port 443) references the validated cert ARN; keep an HTTP
  listener too, but have it redirect to HTTPS (a standard ALB listener rule).

### D. Dependency ordering and failure handling (15 min)
- Terraform's dependency graph (Day 108) already orders infra correctly; the pipeline's
  *job* ordering must match: infra before build-deploy, cert validation before ALB
  listener creation (Terraform handles this internally via resource references).
- What happens on partial failure: if the deploy job fails after the build job
  succeeded, the image sits in ECR unused — harmless; if the smoke test fails, the
  pipeline should stop before declaring success (don't silently ship a broken deploy).
- Rollback path: recall Day 103's task-definition revision rollback, or `helm rollback`
  (Day 74) — today's pipeline should *reference* this as the manual recovery step, not
  necessarily automate it yet (that's a Phase 5 SRE concern).

## Lab (2h)

### Part 1 — Terraform: DNS + TLS as code (35 min)
1. Extend the Day 108 module set (or add a `modules/dns` module): `aws_acm_certificate`
   (DNS validation), `aws_route53_record` for the validation CNAME, `aws_acm_
   certificate_validation` (waits for issuance), and an HTTPS listener on the compute
   module's ALB referencing the validated cert ARN.
2. Add an HTTP→HTTPS redirect listener rule; add the final `aws_route53_record` (Alias)
   pointing your subdomain at the ALB.
3. `terraform plan` — review the full new resource set; `apply`.

### Part 2 — GitHub Actions: the full workflow (55 min)
4. Write `.github/workflows/deploy.yml` with jobs `infra` → `build` → `deploy` →
   `smoke-test`, each depending (`needs:`) on the previous.
5. `infra` job: `terraform init`/`plan`/`apply` (OIDC role with permissions scoped to
   exactly this project's resources — Day 93/109's least-privilege habit applied to CI
   itself).
6. `build` job: Docker build, ECR login via OIDC, push tagged with the git SHA (not
   `latest` — traceability).
7. `deploy` job: update the ECS service (or `helm upgrade`) to the new SHA-tagged image.
8. `smoke-test` job: `curl -f --retry 5 --retry-delay 10 https://<domain>/health` —
   fail the workflow on non-2xx.

### Part 3 — Run it and prove it (20 min)
9. Push a trivial change (e.g. a version string in the app); watch the full pipeline
   run in GitHub Actions; confirm the smoke test job goes green.
10. `curl -I https://<domain>` from your laptop — confirm valid TLS (no cert warning)
    and the new version string is live.
11. Intentionally break the smoke test (point it at a wrong path) once, confirm the
    pipeline correctly reports failure — then fix and re-run.

### Part 4 — Document and decide on teardown (10 min)
12. Write `docs/pipeline-e2e.md`: a diagram (ASCII is fine) of push → infra → build →
    deploy → smoke-test → live HTTPS URL, and the manual rollback command for each
    compute path (ECS revision rollback / `helm rollback`).
13. Decide and record: keep this environment live through Day 111's resume checkpoint
    (recommended, it's your best portfolio artifact) or tear down now — either is valid,
    but state the choice and, if tearing down, run the full destroy sequence
    (`terraform destroy`, confirm via console sweep) before ending the session.

**Definition of done:** one `git push` triggers infra→build→deploy→smoke-test
unattended · the app is reachable over valid HTTPS at a custom domain · a deliberately
broken smoke test correctly failed the pipeline · rollback commands documented ·
teardown decision recorded and executed if chosen.
