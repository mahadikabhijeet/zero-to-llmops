## Theory (1h)

### A. CIDR and VPC sizing (15 min)
- Recall Day 15's subnetting math — same rules, cloud-scoped. A VPC gets a CIDR block
  (e.g. `10.0.0.0/16` = 65,536 addresses); subnets carve smaller blocks from it
  (`10.0.1.0/24` = 256 addresses).
- AWS reserves 5 IPs per subnet (network, VPC router, DNS, future use, broadcast-analog) —
  a `/24` gives 251 usable, not 256.
- Plan CIDRs to never overlap across VPCs you might one day peer or connect via
  Transit Gateway — this bites people who "just use 10.0.0.0/16 everywhere."

### B. Subnets: public vs private (15 min)
- A subnet is "public" only because its route table sends `0.0.0.0/0` to an Internet
  Gateway — it's a route table property, not an inherent subnet flag.
- Private subnets have no direct route to the internet; outbound-only internet access
  (for updates, pulling images) comes via a NAT Gateway sitting in a public subnet.
- Spread subnets across ≥2 AZs from day one — this is what Day 95's ASG/ALB required.

### C. Route tables & Internet Gateway (15 min)
- Every subnet is associated with exactly one route table (the main route table by
  default, or an explicit association).
- Internet Gateway (IGW): attached to the VPC (not a subnet), horizontally scaled,
  highly available by default — it's a gateway, not a bottleneck device to size.
- Route table entries: local route (within-VPC, automatic, cannot be deleted) +
  explicit routes you add (`0.0.0.0/0 → igw-id` for public, `0.0.0.0/0 → nat-id` for
  private).

### D. NAT Gateway economics (15 min)
- NAT Gateway bills per-hour AND per-GB processed — **the single most common surprise
  bill in a free-tier account**; a NAT Instance (self-managed EC2) is the free-tier-
  friendly alternative for learning, at the cost of managing it yourself.
- One NAT Gateway per AZ is the HA best practice in production; for this course, one NAT
  Gateway (or NAT instance) is enough to demonstrate the pattern — teardown is mandatory.
- Default VPC already has an IGW and public subnets in every AZ — today we build a
  *custom* VPC to actually understand the pieces instead of relying on defaults.

## Lab (2h)

### Part 1 — Plan and create the VPC (30 min)
1. On paper/markdown, plan: VPC `10.0.0.0/16`; public subnets `10.0.1.0/24` (AZ-a),
   `10.0.2.0/24` (AZ-b); private subnets `10.0.11.0/24` (AZ-a), `10.0.12.0/24` (AZ-b).
2. `aws ec2 create-vpc --cidr-block 10.0.0.0/16 --tag-specifications
   'ResourceType=vpc,Tags=[{Key=Name,Value=fresher-vpc}]'`.
3. Create all 4 subnets with `aws ec2 create-subnet --vpc-id <vpc-id> --cidr-block
   <cidr> --availability-zone <az>`, tagging each with a clear Name.

### Part 2 — Internet Gateway + public routing (30 min)
4. `aws ec2 create-internet-gateway`; `aws ec2 attach-internet-gateway --vpc-id <vpc-id>
   --internet-gateway-id <igw-id>`.
5. Create a public route table: `aws ec2 create-route-table --vpc-id <vpc-id>`; add the
   default route: `aws ec2 create-route --route-table-id <rt-id> --destination-cidr-block
   0.0.0.0/0 --gateway-id <igw-id>`.
6. Associate both public subnets to this route table (`aws ec2
   associate-route-table`); enable auto-assign public IP on both
   (`modify-subnet-attribute --map-public-ip-on-launch`).

### Part 3 — NAT Gateway + private routing (40 min)
7. Allocate an Elastic IP: `aws ec2 allocate-address`. Create the NAT Gateway in a
   **public** subnet: `aws ec2 create-nat-gateway --subnet-id <public-subnet-a>
   --allocation-id <eip-alloc-id>`; wait for state `available`.
8. Create a private route table; add `0.0.0.0/0 → nat-gateway-id`; associate both
   private subnets to it.
9. Launch one instance in a private subnet (no public IP) and one in a public subnet
   (with public IP), reusing Day 94's SG/keypair pattern; SSH into the public one, then
   SSH from *it* into the private one (bastion pattern preview for Day 97).
10. From the private instance, `curl -I https://amazon.com` — confirm outbound-only
    internet works via NAT, then confirm nothing external can reach it directly.

### Part 4 — Teardown (mandatory, 20 min)
11. Terminate both instances. Delete the NAT Gateway (`aws ec2 delete-nat-gateway`) and
    **wait for it to fully delete** before releasing the Elastic IP
    (`aws ec2 release-address`) — NAT Gateways bill until fully deleted.
12. Detach and delete the IGW, delete route tables (after disassociating), delete all 4
    subnets, delete the VPC. Verify: `aws ec2 describe-vpcs --filters
    "Name=tag:Name,Values=fresher-vpc"` returns empty.

**Definition of done:** custom VPC with public+private subnets across 2 AZs · NAT-routed
outbound access proven from a private instance · full teardown verified, NAT Gateway
confirmed deleted before EIP released.
