## Theory (1h)

### A. EC2 building blocks (15 min)
- Instance = a virtual server; **AMI** (Amazon Machine Image) = the template (OS +
  preinstalled software) it boots from — AWS-provided, Marketplace, or your own.
- Instance types encode a family + generation + size (e.g. `t3.micro`): `t` = burstable
  general purpose, `3` = generation, `.micro` = size (vCPU/RAM tier). Free tier: 750
  hrs/month of `t2.micro` or `t3.micro` (region-dependent) for 12 months.
- Instance lifecycle: pending → running → stopping → stopped → terminated (stopped
  still bills for attached EBS; terminated does not, and terminated cannot be restarted).

### B. Security groups & keypairs (15 min)
- Security Group (SG) = stateful virtual firewall at the instance/ENI level: allow rules
  only (no explicit deny), return traffic auto-allowed.
- Default SG denies all inbound, allows all outbound — you must explicitly open ports
  (22 for SSH, 80/443 for web).
- Keypairs: AWS stores the public key, you keep the private `.pem` — `chmod 400 key.pem`
  or SSH refuses it; lost private key on a running instance means no direct SSH recovery
  without extra steps.

### C. User-data & instance metadata (15 min)
- User-data: a script (bash, base64-encoded automatically) run once at first boot via
  cloud-init — the automation hook for bootstrapping (installing packages, pulling code).
- Instance Metadata Service (IMDS): `curl http://169.254.169.254/latest/meta-data/` from
  *inside* the instance — self-discovery (instance-id, AZ, IAM role creds if attached).
  IMDSv2 (token-required) is the secure default — mention SSRF risk of IMDSv1.

### D. Cost & CLI patterns (15 min)
- Free-tier gotchas: EBS volume itself is billed even when the instance is stopped;
  Elastic IPs are free only while attached to a *running* instance.
- Core CLI verbs: `aws ec2 run-instances`, `describe-instances`, `stop-instances`,
  `start-instances`, `terminate-instances`, `describe-security-groups`,
  `create-key-pair`.

## Lab (2h)

### Part 1 — Prep (15 min)
1. Confirm Day 93 budgets are active: `aws budgets describe-budgets --account-id <id>
   --profile fresher`.
2. Pick your working region (from Day 92 docs) and confirm the free-tier AMI: `aws ec2
   describe-images --owners amazon --filters "Name=name,Values=al2023-ami-*-x86_64"
   "Name=state,Values=available" --query 'Images | sort_by(@,&CreationDate)[-1].ImageId'
   --profile fresher`.

### Part 2 — Keypair, SG, and launch (50 min)
3. `aws ec2 create-key-pair --key-name fresher-key --query 'KeyMaterial' --output text >
   fresher-key.pem && chmod 400 fresher-key.pem` (never commit this file — confirm
   `.gitignore` covers `*.pem`).
4. Create a security group: `aws ec2 create-security-group --group-name fresher-sg
   --description "lab sg"`; add inbound SSH from your IP only:
   `aws ec2 authorize-security-group-ingress --group-id <sg-id> --protocol tcp --port 22
   --cidr $(curl -s ifconfig.me)/32`.
5. Write a short user-data script (`userdata.sh`) that installs and starts nginx on boot
   (Amazon Linux: `dnf install -y nginx && systemctl enable --now nginx`).
6. Launch: `aws ec2 run-instances --image-id <ami-id> --instance-type t3.micro
   --key-name fresher-key --security-group-ids <sg-id> --user-data file://userdata.sh
   --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=fresher-lab}]'`.

### Part 3 — Connect and inspect (35 min)
7. `aws ec2 describe-instances --filters "Name=tag:Name,Values=fresher-lab"
   --query 'Reservations[].Instances[].PublicIpAddress'` — get the public IP.
8. `ssh -i fresher-key.pem ec2-user@<public-ip>` and confirm nginx is running
   (`curl localhost`); also `curl http://<public-ip>` from your laptop.
9. From inside the instance: `curl -H "X-aws-ec2-metadata-token: $(curl -Xs PUT
   "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds:
   21600")" http://169.254.169.254/latest/meta-data/instance-id` — inspect IMDSv2 flow.
10. `aws ec2 stop-instances --instance-ids <id>`; confirm state is `stopped`; note it's
    still consuming EBS/free-tier storage hours, not compute hours.

### Part 4 — Teardown (20 min, mandatory)
11. `aws ec2 terminate-instances --instance-ids <id>`; poll `describe-instances` until
    `terminated`.
12. `aws ec2 delete-security-group --group-id <sg-id>`; `aws ec2 delete-key-pair
    --key-name fresher-key`; remove local `fresher-key.pem`.
13. Confirm zero running instances: `aws ec2 describe-instances --filters
    "Name=instance-state-name,Values=running"` returns empty.

**Definition of done:** instance launched with restricted-SSH SG and user-data · nginx
reachable over HTTP · IMDSv2 token flow demonstrated · everything terminated/deleted and
verified empty.
