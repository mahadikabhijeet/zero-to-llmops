## Theory (1h)

### A. The Well-Architected Framework (15 min)
- Six pillars: Operational Excellence, Security, Reliability, Performance Efficiency,
  Cost Optimization, Sustainability — a checklist lens for reviewing any workload, not
  a certification in itself.
- Today focuses on Security + Cost (the other four get touched implicitly by Phase 5's
  SRE work and Day 117–118's FinOps deep-dive) — reviewing everything built Days 92–108.
- AWS Well-Architected Tool (console): create a workload, answer the question set per
  pillar, get a prioritized list of "high risk" items — a free, structured way to do
  this audit instead of ad hoc.

### B. Least-privilege audit method (15 min)
- IAM Access Analyzer: flags resources (S3 buckets, IAM roles, KMS keys) shared outside
  your account/org — catches accidental public exposure Days 99–108 might have left.
- `aws iam get-account-authorization-details` dumps every user/group/role/policy in one
  call — grep it for `"Effect": "Allow"` + `"Resource": "*"` combos (broad grants) as a
  first pass.
- IAM Access Advisor (per role/user, "last accessed" data per service) — the practical
  way to find *unused* permissions to remove, since least-privilege is as much about
  deletion as initial scoping.

### C. Trusted Advisor (10 min)
- Free-tier accounts get a limited check set (core security checks: security groups
  open to the world, IAM use, MFA on root, S3 bucket permissions) — full checks need
  Business/Enterprise support.
- Even the free checks are worth a pass today — it's a second, independent set of eyes
  on exactly the mistakes this phase's labs are prone to (open SGs, no MFA).

### D. Applying it to the project (20 min)
- Walk the module set from Day 108 against Security pillar questions: are secrets in
  variables marked `sensitive`? Do SGs reference SGs (not `0.0.0.0/0`) where possible?
  Is encryption at rest enabled everywhere (S3, RDS, EBS)?
- Cost pillar questions: right-sized instance types? Unused Elastic IPs/snapshots
  anywhere from earlier labs (teardown misses)? Lifecycle rules present on all buckets?
- The output of this review is a punch list — not a rebuild. Fixing the punch list
  *is* the lab today.

## Lab (2h)

### Part 1 — Access Analyzer + authorization dump (35 min)
1. Enable IAM Access Analyzer (console or `aws accessanalyzer create-analyzer
   --analyzer-name fresher-analyzer --type ACCOUNT`); review any findings.
2. `aws iam get-account-authorization-details > iam-dump.json`; grep for
   `"Resource": "*"` combined with `"Effect": "Allow"` — list every match and judge
   whether it's justified (e.g. Day 92's temporary `AdministratorAccess` group is a
   known, flagged exception — decide whether to narrow it now).

### Part 2 — Trusted Advisor pass (20 min)
3. Open Trusted Advisor → Security category; review every check available on the free
   tier (security groups unrestricted, IAM use, MFA on root, S3 bucket permissions,
   service limits).
4. Fix at least one real finding (e.g. tighten an SG left too open, confirm root MFA is
   still active from Day 92).

### Part 3 — Well-Architected Tool review (35 min)
5. Console → Well-Architected Tool → define a workload named "fresher-project" mapped
   to the Day 108 module set's resources.
6. Answer the Security pillar's question set honestly (not aspirationally) — let it
   flag high-risk items.
7. Answer the Cost Optimization pillar's question set — cross-reference against Days
   93/117's cost tools.

### Part 4 — Fix the punch list (25 min)
8. Pick the top 3 flagged items across Access Analyzer, Trusted Advisor, and WAR; fix
   them directly in the Terraform module set from Day 108 (e.g. add `sensitive = true`
   to a variable, narrow an SG rule, enable encryption on a resource missing it).
9. `terraform plan` to confirm the fixes are non-destructive changes (attribute updates,
   not replacements) where possible; `apply` if the environment is still live.

### Part 5 — Documentation and sweep (5 min)
10. Write `docs/aws-security/waraudit.md`: the punch list, what was fixed today, and
    what's deferred with a reason. Commit it.
11. Standard resource sweep: confirm nothing billable was left running from prior days'
    "keep it live for the next lab" choices that should now be torn down.

**Definition of done:** Access Analyzer enabled and findings reviewed · Trusted Advisor
security checks reviewed with ≥1 real fix applied · WAR Security + Cost pillars answered
for the project workload · top 3 punch-list items fixed in Terraform and applied ·
`docs/aws-security/waraudit.md` committed.
