## Theory (1h)

### A. ECR (15 min)
- Elastic Container Registry = private Docker registry, IAM-authenticated (no
  separate registry login/password to manage — recall Day 45's Docker registry basics).
- `aws ecr get-login-password | docker login --username AWS --password-stdin
  <account>.dkr.ecr.<region>.amazonaws.com` — the auth token expires (12h), so CI must
  refresh it every run, not cache it long-term.
- Image scanning on push (basic, free) surfaces known CVEs — ties back to Day 48's
  trivy habit; lifecycle policies on repos prune old untagged images automatically.

### B. ECS core concepts (15 min)
- Cluster (logical grouping) → Task Definition (the "how to run this container" spec:
  image, CPU/memory, port mappings, env vars, IAM roles) → Service (keeps N tasks
  running, handles replacement) → Task (a running instance of the definition).
- Fargate vs EC2 launch type: Fargate = no EC2 instances to manage, pay per
  task-vCPU/memory-second; EC2 launch type = you manage the underlying instances
  (cheaper at high, steady utilization, more ops burden).
- Two IAM roles per task: **execution role** (pulls the image, writes logs — AWS-facing)
  vs **task role** (what the app itself can call, e.g. S3/DynamoDB — app-facing);
  conflating them is a common mistake.

### C. Networking a Fargate service (15 min)
- `awsvpc` network mode (Fargate's only mode): each task gets its own ENI and private
  IP in your VPC — SGs attach to the task directly, same mental model as Day 96–97.
- Fronting with an ALB (Day 95's target group, but target type `ip` instead of
  `instance`) is the standard pattern for a web-facing ECS service.
- Service discovery / health checks: ALB target group health check drives task
  replacement, same as it drove ASG instance replacement on Day 95.

### D. CI wiring (15 min)
- Recall Day 41/48's GitHub Actions patterns: today's addition is `aws-actions/
  configure-aws-credentials` (OIDC federation — no long-lived AWS keys stored in GitHub
  secrets, the modern best practice) then `aws ecr` push, then `aws ecs update-service
  --force-new-deployment` to roll out the new image.
- Task definition revisions are immutable — every deploy registers a new revision; the
  service is updated to point at it, enabling instant rollback to a prior revision.

## Lab (2h)

### Part 1 — ECR repo + manual push (25 min)
1. `aws ecr create-repository --repository-name fresher-project --image-scan-on-push`.
2. Build the project's existing Dockerfile (Day 46/48 image); tag and push manually
   once to confirm the flow: `docker tag fresher-project:latest
   <account>.dkr.ecr.<region>.amazonaws.com/fresher-project:latest` then
   `aws ecr get-login-password | docker login ...` and `docker push`.

### Part 2 — Networking + cluster (25 min)
3. Reuse/rebuild a VPC with public+private subnets (Day 96/97 script); create an ECS
   cluster: `aws ecs create-cluster --cluster-name fresher-cluster`.
4. Create a target group (type `ip`) and ALB in the public subnets (Day 95 pattern),
   listener forwarding to the target group.

### Part 3 — Task definition + service (45 min)
5. Write `task-def.json`: `requiresCompatibilities: ["FARGATE"]`, `networkMode:
   "awsvpc"`, execution role ARN, task role ARN, container definition (image URI from
   Part 1, port mapping, `logConfiguration` to CloudWatch Logs).
6. `aws ecs register-task-definition --cli-input-json file://task-def.json`.
7. `aws ecs create-service --cluster fresher-cluster --service-name fresher-svc
   --task-definition fresher-project --desired-count 2 --launch-type FARGATE
   --network-configuration "awsvpcConfiguration={subnets=[<priv-a>,<priv-b>],
   securityGroups=[<task-sg>],assignPublicIp=DISABLED}" --load-balancers
   "targetGroupArn=<tg-arn>,containerName=fresher-project,containerPort=8080"`.
8. Poll `aws ecs describe-services --cluster fresher-cluster --services fresher-svc`
   until 2/2 tasks running and healthy in the target group; `curl` the ALB DNS name.

### Part 4 — CI wiring + rollback drill (15 min)
9. Add a GitHub Actions job (append to the existing pipeline): on push to main, build →
   push to ECR → `aws ecs update-service --force-new-deployment`. Use OIDC
   (`aws-actions/configure-aws-credentials` with `role-to-assume`), not static keys.
10. Trigger a deploy, watch a new task-def revision roll out; then `aws ecs
    update-service --task-definition fresher-project:<previous-revision>` to prove
    rollback works.

### Part 5 — Teardown (mandatory, 10 min)
11. `aws ecs update-service --desired-count 0`, then `delete-service`, `delete-cluster`,
    deregister task definitions (optional — they're free but tidy up), delete ALB/target
    group/VPC per prior days' order, delete the ECR repo (`--force` to remove images too).
12. Confirm `aws ecs list-clusters` and `aws ecr describe-repositories` show nothing
    from this lab.

**Definition of done:** project image running as 2 healthy Fargate tasks behind an ALB ·
CI deploys via OIDC (no static keys) · rollback to a prior task-def revision proven ·
all ECS/ECR/networking resources deleted and verified.
