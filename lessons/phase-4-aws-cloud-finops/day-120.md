## Theory (1h)

### A. What a real FinOps report contains (20 min)
- Recall Day 117's showback template — today fills it in for real, end to end, using
  the actual project built across Days 92–118. A credible FinOps report has four parts:
  **spend** (what was actually consumed, by service/tag/time), **allocation** (whose
  cost is whose, including the shared-resource method from Day 117), **savings applied**
  (concrete actions taken, not just recommendations — Day 118's rightsizing/tiering/
  orphan cleanup), and **forward plan** (what's recommended next: commitments once
  usage is steady, further tiering, etc.).
- The report's audience matters: a finance stakeholder wants totals and trend; an
  engineering stakeholder wants per-team/per-namespace breakdown and specific fixes —
  a good report serves both without forcing either to read past their section.
- This report is also a **portfolio artifact**: it demonstrates the trainer's own
  specialty transferred cleanly, and it's a distinctive thing very few fresher resumes
  will have — treat it as a genuine writing exercise, not a checkbox.

### B. Bringing the project to a cost-optimized end state (15 min)
- Recall the module set (Day 108) and the end-to-end pipeline (Day 110) — "cost
  optimized" today means applying the concrete, already-identified fixes from Days
  117–118 to that live infrastructure definition, not inventing new ones.
- Prioritize by effort/impact: tagging enforcement (near-zero effort, unlocks all
  future allocation) and orphan cleanup (near-zero effort, immediate savings) go first;
  rightsizing changes to `values.yaml`/Terraform variables go next; commitment
  decisions are documented as a forward-plan recommendation, not applied (a learning
  project shouldn't buy a 1-year Savings Plan).

### C. Certification readiness — using exam objectives as a gate (15 min)
- Recall Day 111's SAA drill; today adds a **Terraform Associate** pass over the same
  material, since Days 79–83 and 107–108 cover its ground (state, providers, modules,
  workspaces, `import`, lifecycle meta-arguments).
- Terraform Associate domains worth self-checking: understand IaC concepts, use CLI
  outside core workflow (`fmt`/`validate`/`import`/`state`), interact with state,
  read/write/modify configuration, understand HCL syntax, manage modules, navigate
  workflow (`init`/`plan`/`apply`/`destroy`), implement/maintain state.
- The exam isn't mandatory (recall the README's stance) — the objective list is a free,
  well-structured coverage check for whether Phase 3–4's Terraform content was actually
  absorbed.

### D. Closing Phase 4 (10 min)
- Phase 4 took the project from "runs on a laptop kind cluster" (Day 90) to "deployed
  end-to-end on real AWS infrastructure via CI/CD, with DNS/TLS, audited for security,
  and now cost-optimized with a real FinOps report" — a genuinely hireable-level
  portfolio artifact for a fresher.
- Phase 5 (SRE/observability/GitOps) builds directly on this: the CloudWatch/Kubecost
  visibility from Days 106/118 becomes the substrate for Prometheus/Grafana SLOs; the
  Day 110 pipeline becomes the target for GitOps takeover.

## Lab (2h)

### Part 1 — Assemble real spend data (25 min)
1. Pull the last 30 days of Cost Explorer data grouped by Service and by Tag (Day 117's
   view); export or screenshot it into `docs/finops/capstone-report.md`'s Spend
   section — if usage was minimal/near-zero due to disciplined teardown, report that
   honestly and note it as evidence the guardrails worked, then supplement with the
   Day 118 Pricing Calculator projections for a "what a real running deployment would
   cost" section.

### Part 2 — Apply the savings, for real (45 min)
2. Add/confirm the `default_tags` block is present across every module in the Day 108
   Terraform set (Day 117's enforcement); `terraform plan` to confirm 100% tag coverage
   with zero unintended resource changes.
3. Re-run the orphan audit from Day 118 Part 1 (`describe-volumes`/`describe-snapshots`/
   `describe-addresses`) one more time across all regions used this phase; clean up
   anything found.
4. Apply the Day 118 Kubecost-identified right-sizing fix to the Helm chart's
   `values.yaml` if not already committed; apply the gp3 migration and the extended
   Glacier lifecycle tier to the storage module if not already applied.
5. Re-run `terraform plan`/`apply` against the module set with all fixes in place;
   confirm the plan is clean and matches expectations.

### Part 3 — Write the FinOps report (35 min)
6. Complete `docs/finops/capstone-report.md` using the Day 117 template's four
   sections (Spend / Allocation / Savings Applied / Forward Plan), with concrete
   numbers wherever available and honest projections where actual usage was
   necessarily minimal for a learning account.
7. Include a short "methodology" footnote: what tools were used (Cost Explorer,
   Compute Optimizer, Kubecost, Pricing Calculator) and what allocation method was
   applied to shared resources (Day 117's NAT Gateway example).

### Part 4 — Certification readiness check (10 min)
8. Self-score against the Terraform Associate domain list from Theory C using the same
   honest method as Day 111's SAA drill — for each domain, cite the Day-N lab that
   covered it, or flag it as a genuine gap.
9. Write a one-paragraph combined readiness statement (SAA + Terraform Associate) into
   `docs/certifications-readiness.md`, updating Day 111's file rather than replacing it.

### Part 5 — Close the phase (5 min)
10. Tag the repo `v1.0-phase4-complete`; update the project README's status section to
    reflect "Phase 4 complete: AWS end-to-end, cost-optimized, FinOps-reported."
11. Commit everything: `git add docs/ terraform/ charts/ && git commit -m "feat: Phase
    4 capstone — cost-optimized infra + FinOps report"`.

**Definition of done:** tagging enforcement verified at 100% coverage via `terraform
plan` · orphan resources cleaned across all regions used this phase · at least one
rightsizing and one storage-tiering fix applied and re-planned cleanly · FinOps
capstone report complete with real or honestly-projected numbers · certification
readiness statement written · repo tagged `v1.0-phase4-complete`.
