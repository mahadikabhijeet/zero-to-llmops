## Theory (1h) — Phase 5 retrospective

### A. What the project became this phase (20 min)
- Trace the arc explicitly: Day 121's SLOs → Day 130's full
  instrumentation → Day 134's GitOps management → Day 136's canary
  release → Day 137's chaos testing → Day 141–142's platform cataloging
  → Day 143's security gates → Day 144's reliability patterns → Day 145's
  live incident. Each day built a load-bearing piece of the next.
- This arc *is* the "how I built it" narrative — today's writing task is
  making that arc legible to someone who wasn't in the room.

### B. What "platform" means now versus Phase 3's "on k8s" (15 min)
- Phase 3 (Day 90) capstone: project running on Kubernetes via Helm.
- Phase 5 capstone: project is **operated**, not just deployed — it has
  SLOs, self-healing GitOps delivery, safe progressive-delivery mechanics
  (canary), verified failure tolerance (chaos), a self-service front door
  (Backstage), and codified incident response. That's the platform
  engineering bar, and it's the story that differentiates a fresher's
  resume from "did a Kubernetes tutorial."

### C. Known gaps, honestly stated (10 min)
- No capstone should claim more than it verifies. Use Day 149's gap list
  and any unresolved Day 145 action items as the "known limitations"
  section of the write-up — a fresher who can name their system's real
  gaps reads as more senior than one who claims everything is perfect.

### D. Setting up Phase 6 (10 min)
- Phase 6 adds an ML/AIOps component (anomaly detection on the very
  Prometheus metrics built in Days 122–130) — today's instrumentation is
  the direct dependency for Day 165's work. Nothing here is a dead end.

## Lab (2h)

### Part 1 — Full milestone verification (40 min)
1. Walk and check off every phase milestone end to end on the live cluster:
   - [ ] SLOs defined and documented (Day 121).
   - [ ] Metrics + logs + traces all correlating for the project app (Day 130).
   - [ ] Burn-rate alerts fire correctly at the expected pace (re-test one, briefly).
   - [ ] ArgoCD manages all project resources with self-heal active (Day 134).
   - [ ] A canary release can be run end-to-end with an abort path (Day 136).
   - [ ] At least one chaos experiment's findings are documented and, where
     found lacking, fixed (Day 137).
   - [ ] Load test results and capacity headroom are documented (Day 138).
   - [ ] PDB and autoscaling posture are documented and justified (Day 139).
   - [ ] Backstage catalogs the project with working links (Day 141/142).
   - [ ] CI has SAST/dependency/SBOM gates; Gatekeeper enforces two policies (Day 143).
   - [ ] Reliability patterns (timeout/retry/breaker/degradation) verified under fault (Day 144).
2. Fix or note as a known gap anything that fails verification — don't
   silently skip a failed check.

### Part 2 — Architecture diagram refresh (25 min)
3. Update the Day 148 architecture diagram to include Istio, ArgoCD,
   chaos-mesh, and Backstage explicitly if not already present — this
   diagram now represents the full Phase 5 system, not just Phase 4's cloud layout.

### Part 3 — Write the long-form "how I built it" post (45 min)
4. Structure: (1) what the project does and who it's for, (2) the
   architecture diagram, (3) the arc from Day 121 to today told as a
   narrative of decisions (why Loki not EFK, why multi-window burn-rate
   alerts, why Istio canary over plain rolling update), (4) the Day 145
   game day story as the proof-it-works section, (5) known limitations
   from the gap list, (6) what's next (Phase 6's ML/AIOps addition).
5. Publish as a blog post / LinkedIn article / repo `docs/how-i-built-it.md`
   — whichever channel from the README's job-readiness track is active;
   link it from the README and from the Backstage catalog entry.

### Part 4 — Tag and close the phase (10 min)
6. `git tag p5-capstone`; commit the final diagram and write-up.
7. Carry forward the Day 149 gap list items and any unresolved Day 145
   action items into `tasks/todo.md` (cross-cutting, this repo's global
   task system) so they don't get lost heading into Phase 6.

**Definition of done:** all 11 milestone checklist items verified or
explicitly noted as a known gap; architecture diagram updated; long-form
write-up published and linked from README + Backstage; `p5-capstone` tag
pushed; open items carried into `tasks/todo.md`.
