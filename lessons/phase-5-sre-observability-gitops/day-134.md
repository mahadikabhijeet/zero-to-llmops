## Theory (1h)

### A. Sync policies in depth (15 min)
- `syncPolicy.automated`: ArgoCD auto-syncs on every detected git change —
  no manual click needed. Two sub-flags matter:
  - `prune: true` — resources removed from git get deleted from the
    cluster too (without it, deleted manifests leave orphaned resources).
  - `selfHeal: true` — manual cluster drift (like Day 132's `kubectl scale`)
    gets reverted automatically, not just flagged.
- `syncOptions`: `CreateNamespace=true`, `ApplyOutOfSyncOnly=true`
  (efficiency), `RespectIgnoreDifferences` (for fields a controller
  legitimately mutates, e.g. HPA-managed replica counts).

### B. Rollback in a GitOps world (15 min)
- Because desired state is a git history, "rollback" is fundamentally a
  git operation: `git revert` the bad commit → ArgoCD reconciles the
  cluster back automatically. `argocd app rollback <app> <revision>` is a
  convenience that does the equivalent without a manual revert commit —
  useful for a fast emergency rollback, but the git history should still
  get the revert committed afterward so state stays truthful.
- Contrast with Helm's own `helm rollback` — ArgoCD's rollback works at
  the "which git revision" level and is aware whether the source is Helm/
  Kustomize/plain YAML underneath.

### C. Image updater concept (15 min)
- `argocd-image-updater` watches a container registry for new tags matching
  a pattern and automatically commits/patches the manifest (or updates via
  an `Application` annotation) to bump the deployed image — closing the
  loop from "CI pushed image :v1.2.4" to "cluster running :v1.2.4" without
  a human editing YAML.
- Tradeoff: convenient for fast iteration, but it writes to git
  automatically — teams often gate it to non-prod or require the commit
  to be reviewable, since it blurs "who/what changed production."

### D. What "GitOps-managed" means for the milestone (15 min)
- Bar for today: every project resource's desired state lives in git,
  ArgoCD auto-syncs and self-heals, a rollback was demonstrated end-to-end,
  and there's a documented (if not fully automated) path from new image
  tag to deployed cluster state.

## Lab (2h)

### Part 1 — Turn on automated sync with prune + self-heal (25 min)
1. Edit the `project-app` `Application` (and the app-of-apps children) to
   set `syncPolicy.automated: {prune: true, selfHeal: true}`.
2. Re-run Day 132's drift test (`kubectl scale --replicas=5`) — confirm it
   now self-heals within seconds without a manual sync.

### Part 2 — Rollback demo (45 min)
3. Make a deliberately bad change in git: bump the app's image tag to a
   nonexistent tag, or set an obviously wrong env var, commit, push.
4. Watch ArgoCD sync the bad state and the app go `Degraded` (via the
   Grafana/Prometheus alerts from Days 123/130 too — connect the dots).
5. Roll back two ways and compare: (a) `git revert <bad-commit>` and push;
   watch ArgoCD auto-reconcile. (b) On a second attempt, use
   `argocd app rollback project-app <previous-revision-id>` for the fast
   path, then still commit a git revert afterward to keep history honest.

### Part 3 — Image updater concept walkthrough (30 min)
6. Install `argocd-image-updater` (or read through its docs/manifests if
   registry access is constrained) and configure one annotation on the
   `project-app` `Application`:
   `argocd-image-updater.argoproj.io/image-list: app=<registry>/<image>`.
7. Push a new image tag from CI (or manually push a new tag to the
   registry) and observe (or trace through logs) the updater detecting it
   and preparing the update — document the flow even if full automation
   isn't wired to prod.

### Part 4 — ★ Milestone verification (20 min)
8. Confirm: all project resources' desired state is in git; automated
   sync with prune+selfHeal is active; a rollback was performed
   successfully (app healthy again); the image-updater flow is documented.
9. Write `/opt/fresher_project/docs/milestone-d134.md`; commit and tag
   (`git tag d134-gitops`).

**Definition of done:** self-heal demonstrated; rollback performed via both
methods; image-updater flow documented; tag `d134-gitops` pushed.
