## Theory (1h)

### A. Branches — cheap pointers, not copies (15 min)
- A branch is a movable pointer to a commit (`.git/refs/heads/<name>`); creating one is
  instant because no files are copied.
- `git branch <name>` (create), `git switch <name>` (checkout, modern syntax),
  `git switch -c <name>` (create+switch), `git branch -d/-D` (delete safe/force).
- `git branch -v`, `git branch --merged`/`--no-merged` — which branches are already
  folded in.
- Why branch: isolate risky work, parallel features, never break `main`.

### B. Merging — fast-forward vs three-way (20 min)
- **Fast-forward merge**: target branch has no new commits since the feature branched —
  Git just moves the pointer forward. No merge commit created.
- **Three-way merge**: both branches have diverged — Git finds the common ancestor
  (merge-base) and combines both diffs into a new **merge commit** with two parents.
- `git merge <branch>` (from the branch you want to merge INTO), `git merge --no-ff`
  (force a merge commit even when fast-forward is possible — keeps feature history visible).
- `git merge --abort` — bail out cleanly mid-conflict.

### C. Conflicts — what they are and how to read them (15 min)
- A conflict happens when the same lines changed differently on both sides (or one side
  deleted what the other edited) — Git can't auto-resolve, so it stops and marks the file.
- Conflict markers: `<<<<<<< HEAD` ... `=======` ... `>>>>>>> branch-name`.
- Resolution: edit the file to the correct final content, remove markers, `git add <file>`,
  then `git commit` (no `-m` needed — Git pre-fills a merge message).
- `git status` during a conflict tells you exactly which files need attention.

### D. Stash — shelving in-progress work (10 min)
- `git stash` — takes uncommitted changes (tracked files) off the working directory and
  parks them on a stack, restoring a clean tree.
- `git stash list`, `git stash pop` (apply + remove from stack), `git stash apply`
  (apply, keep on stack), `git stash push -u` (include untracked files too).
- Use case: mid-feature, need to switch branches urgently (e.g., hotfix).

## Lab (2h)

### Part 1 — Branch and fast-forward (25 min)
1. In `~/lab31`, `git switch -c feature-a`. Add a new file `feature.txt`, commit it.
2. `git switch main`, `git merge feature-a` — observe the fast-forward (no merge
   commit). `git log --oneline --graph --all` to confirm.
3. `git branch -d feature-a` (already merged, safe to delete).

### Part 2 — Create and resolve a real conflict (45 min)
4. `git switch -c branch-x`. Edit line 1 of `notes.txt` to `"BRANCH X VERSION"`, commit.
5. `git switch main`. Edit the SAME line 1 of `notes.txt` to `"MAIN VERSION"`, commit.
6. `git merge branch-x` — watch it fail with a conflict. Read `git status` output
   carefully.
7. Open `notes.txt`, see the `<<<<<<<`/`=======`/`>>>>>>>` markers. Manually pick a
   resolution (e.g., combine both lines), remove all markers.
8. `git add notes.txt`, `git commit` (accept or edit the pre-filled merge message).
9. `git log --oneline --graph --all` — see the merge commit with two parents
   (`git show HEAD` and note `Merge:` line).

### Part 3 — Non-fast-forward and stash drill (30 min)
10. `git switch -c feature-b`, add a commit. `git switch main`, add a DIFFERENT commit
    (no conflict this time). `git merge --no-ff feature-b` — confirm a merge commit was
    created even though a fast-forward was possible.
11. On `main`, start editing `notes.txt` but don't commit. Run `git stash`. Confirm
    `git status` is clean and the edit is gone from the working tree.
12. `git stash list`, then `git switch branch-x` and back to `main`, then
    `git stash pop` — confirm your edit returns.

### Part 4 — Abort practice (20 min)
13. Deliberately create another conflicting pair of commits on two branches. Start the
    merge, then instead of resolving, run `git merge --abort` — confirm you're back to a
    clean pre-merge state. Then resolve it properly this time.

**Definition of done:** fast-forward vs three-way merge explained from your own
`--graph` output · resolved one real conflict by hand · used stash to shelve and restore
work · used `merge --abort` at least once.
