## Theory (1h)

### A. YAML deep dive (20 min)
- Why YAML dominates DevOps configs (Kubernetes, Ansible, GitHub Actions, Docker
  Compose all use it) — human-readable, supports comments (JSON doesn't).
- Structure: indentation-significant (spaces only, never tabs), `key: value`, lists with
  `-`, nested maps by indent level.
- Multi-line strings: `|` (literal block, preserves newlines) vs `>` (folded, joins
  lines with spaces) — a classic source of config bugs.
- **Anchors and aliases**: `&name` defines a reusable block, `*name` references it,
  `<<: *name` merges it in — DRY config, seen constantly in CI/CD and Compose files.
- **Gotchas**: unquoted `yes`/`no`/`on`/`off`/`null` get parsed as booleans/null, not
  strings (the "Norway problem" — `NO` country code becomes `false`); numbers with
  leading zeros; tabs are illegal and fail parsing silently-ish (bad error messages).

### B. JSON and TOML in contrast (10 min)
- JSON: strict, no comments, ubiquitous for APIs (Day 36) and program-to-program data.
- TOML: used by tool configs (`pyproject.toml`, Cargo) — explicit types, `[section]`
  headers, less nesting-friendly than YAML but less error-prone for flat configs.
- When to pick which: APIs → JSON; human-edited app config → YAML (if nesting) or TOML
  (if flat); never invent your own format when one of these three fits.

### C. `jq` — JSON command-line surgery (15 min)
- `jq '.field'`, `jq '.list[0]'`, `jq '.list[] | .name'` (iterate), `jq 'select(.x > 5)'`
  (filter), `jq -r` (raw string output, no quotes — essential for piping into shell
  loops), `jq '.' file.json` (pretty-print/validate).
- Building new JSON: `jq '{name: .login, repos: .public_repos}'`.
- Ties directly to Day 36's API work — this is how you'd inspect API responses at the
  command line instead of writing a Python script for a one-off look.

### D. `yq` — the YAML equivalent (15 min)
- `yq` (the Go-based `mikefarah/yq`, most common today) mirrors `jq` syntax for YAML:
  `yq '.spec.replicas' file.yaml`, `yq -i '.spec.replicas = 3' file.yaml` (in-place
  edit — huge for scripted config changes in CI/CD, seen again in Phase 3 with k8s
  manifests).
- `yq -o=json file.yaml` / `yq -P file.json` — convert between YAML and JSON on the
  command line, useful for feeding YAML config into tools that only speak JSON.

## Lab (2h)

### Part 1 — YAML gotcha hunt (30 min)
1. Write `config.yaml` with a mix of: a country-code field set to `NO` (unquoted), a
   version field `1.10` vs `"1.10"`, and a multi-line description using `|`.
2. Load it in Python with `python3 -c "import yaml, sys; print(yaml.safe_load(open('config.yaml')))"`
   (`pip install pyyaml` if needed) — observe `NO` became `False` and `1.10` became a
   float dropping the trailing zero. Fix both by quoting.
3. Write one block with `|` and one with `>` containing the same 3 lines of text; load
   both and print — compare how newlines differ.
4. Deliberately mix a tab and spaces for indentation in one file; watch it fail to parse
   and read the error message.

### Part 2 — jq drills (35 min)
5. `curl -s https://api.github.com/users/<you>/repos | jq '.'` — pretty-print.
6. `jq -r '.[].name'` — list just repo names, one per line, no quotes.
7. `jq '[.[] | select(.stargazers_count > 0)]'` — filter (may be empty, that's fine,
   explain why).
8. `jq -r '.[] | "\(.name): \(.language)"'` — build a formatted one-line-per-repo
   summary using string interpolation.
9. Reshape: `jq '[.[] | {name, private, url: .html_url}]'` — pick and rename fields
   into a new JSON array.

### Part 3 — yq drills (30 min)
10. Take a Docker Compose-style YAML stub (or the `config.yaml` from Part 1) and run
    `yq '.services'` (or an equivalent key) to extract a section.
11. `yq -i '.log_level = "debug"' config.yaml` — in-place edit; `cat` the file to
    confirm the change and that formatting/comments (if any) survived.
12. `yq -o=json config.yaml` then pipe that into `jq '.'` — confirm the YAML→JSON
    conversion round-trips sensibly.

### Part 4 — Incremental project step (25 min)
13. Convert `sys_report`'s `config.ini` (from Day 37) to `config.yaml`, using anchors if
    you have any repeated blocks (e.g., shared logging settings). Update the Python
    config-loading code to use `pyyaml` instead of `configparser`.
14. Add a `Makefile`-free helper: a one-liner using `yq` that reads and prints the
    current `check_url` from `config.yaml` for a quick sanity check without opening
    Python.
15. `git add -A`, commit: "migrate config to YAML, add jq/yq usage notes to README".

**Definition of done:** identified and fixed at least the `NO`→boolean and unquoted-
float YAML gotchas · ran `jq` filter/reshape/raw-output drills against a real API
response · used `yq -i` for an in-place YAML edit and converted YAML↔JSON · project
config migrated to YAML and loading code updated · committed.
