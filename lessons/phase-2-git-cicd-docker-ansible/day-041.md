## Theory (1h)

### A. Matrix builds (15 min)
- `strategy: matrix: python-version: [3.10, 3.11, 3.12]` — GitHub Actions fans one job
  definition out into N parallel jobs, one per combination.
- Why: prove your code works across the versions/environments you claim to support
  (e.g., a library targeting multiple Python versions, or an OS matrix).
- `fail-fast: false` — let all matrix legs finish and report even if one fails, instead
  of cancelling the rest (useful when you want the full picture).
- `${{ matrix.python-version }}` — reference the current combination inside steps.

### B. Secrets and credentials (15 min)
- Never hardcode tokens/passwords in workflow YAML (Day 58 goes deeper on this).
- Repo Settings → Secrets and variables → Actions — store a secret, reference it as
  `${{ secrets.MY_TOKEN }}` — value is masked in logs automatically.
- `GITHUB_TOKEN` — an automatic, scoped, short-lived token GitHub injects into every
  run for talking back to the repo/API (e.g., commenting on PRs) without you creating
  anything.
- Environment-scoped secrets (concept preview) — different secrets per environment
  (staging vs prod), enforced at job level with `environment:`.

### C. Caching dependencies (15 min)
- Why: reinstalling all pip packages from scratch every run wastes minutes and quota.
- `actions/setup-python@v5` has a built-in `cache: 'pip'` option keyed on
  `requirements.txt` hash — simplest path.
- Manual alternative: `actions/cache@v4` with an explicit `key:`/`restore-keys:` —
  understand this is what the built-in option does under the hood.
- Cache invalidation: changing `requirements.txt` content changes the hash → cache
  miss → fresh install → new cache saved. This is correct and expected.

### D. Badges and branch protection (15 min)
- README badge: GitHub generates a workflow status badge URL
  (`https://github.com/<you>/<repo>/actions/workflows/ci.yml/badge.svg`) — markdown
  `![CI](url)` embeds a live green/red badge.
- Branch protection rules (Settings → Branches): require status checks to pass before
  merging into `main`, require PRs (no direct pushes) — turns "green CI" from a nice-to-
  have into an enforced gate. This is the milestone mechanism for today.

## Lab (2h)

### Part 1 — Matrix build (30 min)
1. Edit `.github/workflows/ci.yml`'s `test` job to use a matrix across 2 Python
   versions (e.g., `3.11` and `3.12`), `fail-fast: false`.
2. Push, confirm the Actions tab shows two parallel job runs under one workflow trigger.
3. Deliberately use a syntax feature only valid in the newer Python (or skip if none
   handy) to see one matrix leg fail while the other passes — then revert.

### Part 2 — Secrets (20 min)
4. Add a dummy secret in repo settings, e.g. `DEMO_TOKEN` with any placeholder value.
5. Add a step: `run: echo "Token starts with ${DEMO_TOKEN:0:3}"` with
   `env: DEMO_TOKEN: ${{ secrets.DEMO_TOKEN }}` — push and confirm the log masks the
   secret value (GitHub redacts any log line containing the exact secret string).

### Part 3 — Caching (25 min)
6. Add `cache: 'pip'` to your `actions/setup-python@v5` step (pointing at
   `requirements.txt`).
7. Push twice: note the install step duration on the first run (cache miss) vs the
   second (cache hit) in the Actions log timing.

### Part 4 — ★ Badge, branch protection, full green CI (45 min)
8. Add the CI status badge to the top of `README.md`, commit, push, confirm it renders
   on the repo's GitHub page.
9. Repo Settings → Branches → add a protection rule for `main`: require the `test` and
   `lint` status checks to pass before merging, require pull requests before merging.
10. Open a real PR with a small improvement (e.g., docstring or a new small test);
    confirm you CANNOT merge until all matrix legs + lint are green; watch the "Merge"
    button unlock only once everything passes.
11. Merge it. On `main`, confirm the README badge shows green and the Actions history
    for `main` is clean.

**Definition of done:** ★ matrix build across 2+ Python versions runs and reports per-
leg status · a secret is used without appearing in logs · pip caching measurably speeds
up the second run · README shows a live CI badge · branch protection on `main` requires
green checks before merge, verified with a real PR.
