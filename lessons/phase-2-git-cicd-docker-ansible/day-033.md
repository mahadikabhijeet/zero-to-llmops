## Theory (1h)

### A. Remotes — a repo's connection to other repos (15 min)
- A remote is just a named URL: `git remote add origin <url>`, `git remote -v`.
- `origin` is convention, not magic — the name of "the remote we cloned from / push to
  by default."
- `git push origin main`, `git push -u origin main` (`-u` sets the upstream tracking
  branch so future `git push`/`git pull` need no args).
- `git fetch` (download refs, don't merge) vs `git pull` (fetch + merge, or fetch +
  rebase with `git pull --rebase`) — fetch is the safer default habit.
- `git clone <url>` — fetch + checkout in one step, remote auto-named `origin`.

### B. GitHub account and SSH auth (15 min)
- Create account (if not already done). SSH keys are the standard auth method (not
  passwords): `ssh-keygen -t ed25519 -C "email"`, add public key to GitHub settings,
  test with `ssh -T git@github.com`.
- Repo creation: empty repo on GitHub → connect existing local repo (`git remote add`)
  vs "push an existing repository" instructions GitHub shows you.
- Public vs private repos — job-readiness reason to go public: real recruiters look at
  GitHub activity/green squares.

### C. `.gitignore` and repo hygiene (15 min)
- Pattern syntax: exact names, globs (`*.log`), directories (`__pycache__/`), negation
  (`!keep-this.log`), leading `/` anchors to repo root.
- `git rm --cached <file>` — untrack a file that's already committed without deleting
  it locally (common mistake: adding `.gitignore` AFTER a file is already tracked does
  nothing until you do this).
- README.md (what/why/how-to-run) and a LICENSE file (MIT is the common permissive
  default for portfolio projects) — both are what recruiters skim first.

### D. The PR (pull request) workflow (15 min)
- Why PRs even on a solo project: practice the muscle, get a diff view, leave yourself
  a record of "why," set up for later collaboration.
- Flow: branch → commit → push branch → open PR on GitHub (base: `main`, compare:
  `your-branch`) → review diff → merge (merge commit / squash / rebase — options
  explained) → delete branch.
- Branch protection concept (preview): requiring PRs + passing checks before merge to
  `main` — ties into CI (Day 40–41).

## Lab (2h)

### Part 1 — SSH auth and first push (25 min)
1. Generate an SSH key if you don't have one; add the public key to GitHub.
   `ssh -T git@github.com` to confirm.
2. On GitHub, create a new **empty** public repo named `fresher-project` (no README —
   you already have history locally).
3. In `/opt/fresher_project`: `git remote add origin git@github.com:<you>/fresher-project.git`.
4. `git push -u origin main` — refresh the GitHub page, confirm your commit history is there.

### Part 2 — `.gitignore` and cleanup (30 min)
5. Check what's currently tracked that shouldn't be: `git ls-files | grep -E '\.log$|__pycache__'`.
6. Write a proper `.gitignore` for a bash+python project: `*.log`, `__pycache__/`,
   `*.pyc`, `.venv/`, `*.egg-info/`, local config/secret file patterns.
7. For anything already tracked that matches: `git rm --cached <file>` (or `-r` for a
   directory), commit: `git commit -m "stop tracking generated/log files"`.
8. `git push origin main`.

### Part 3 — README, LICENSE, first PR (45 min)
9. `git switch -c docs/readme`. Write `README.md`: project name, one-paragraph purpose,
   how to run (`systemctl status system_report.timer`, where output lands), tech stack.
10. Add a `LICENSE` file (MIT template — fill in your name and year).
11. `git add README.md LICENSE && git commit -m "add README and MIT license"`.
12. `git push -u origin docs/readme`. On GitHub, open a Pull Request from `docs/readme`
    into `main`. Read the diff view GitHub renders.
13. Merge the PR on GitHub (use "Squash and merge" — explain what squash does to
    history), delete the branch on GitHub, then locally: `git switch main && git pull`
    and `git branch -d docs/readme`.

### Part 4 — ★ Project goes public (20 min)
14. Confirm repo visibility is **Public** in GitHub repo settings.
15. Add a short repo description and topics (`devops`, `linux`, `bash`, `python`) on
    GitHub for discoverability.
16. `git log --oneline --graph --all` locally — confirm local and `origin/main` match
    (`git log origin/main --oneline` should be identical).

**Definition of done:** SSH auth to GitHub works · `/opt/fresher_project` pushed with
clean history (no logs/pycache tracked) · README + LICENSE merged via an actual PR ·
repo is public with description — job-readiness clock starts today.
