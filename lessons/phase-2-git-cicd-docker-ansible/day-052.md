## Theory (1h)

### A. Playbooks — ad-hoc commands, made repeatable (15 min)
- A playbook is a YAML file (Day 39 payoff) describing one or more **plays**, each
  targeting a group of hosts and running an ordered list of **tasks**.
- Anatomy:
  ```yaml
  - name: Configure web hosts
    hosts: local
    become: true
    tasks:
      - name: Ensure nginx is installed
        dnf:
          name: nginx
          state: present
  ```
- `ansible-playbook -i inventory.ini playbook.yml`, `--check` (dry run), `--diff`
  (show what would change, file-content level), `-v`/`-vvv` (verbosity for debugging).
- Every ad-hoc module from Day 51 works the same way as a task — this day is about
  structure, not new modules.

### B. Variables and facts (15 min)
- Variables: defined in the playbook (`vars:`), in inventory (`host_vars/`,
  `group_vars/`), or passed at runtime (`-e "key=value"`) — precedence order exists
  (documented, not memorized today — know it's layered like Day 37/50's config
  precedence pattern).
- **Facts**: auto-gathered data about each managed host (OS, IP addresses, memory,
  mounts) via the `setup` module, run implicitly at the start of every playbook unless
  `gather_facts: false`.
- `ansible local -i inventory.ini -m setup` — see the raw fact dump.
- Referencing vars/facts in tasks: `{{ variable_name }}`, `{{ ansible_facts['os_
  family'] }}` (or the shorthand `ansible_os_family`).

### C. Handlers — notify-on-change (15 min)
- A handler is a task that only runs when **notified** by another task that reported
  `changed: true` — classic use: restart a service only if its config file actually
  changed.
  ```yaml
  tasks:
    - name: Deploy nginx config
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
      notify: Restart nginx
  handlers:
    - name: Restart nginx
      service:
        name: nginx
        state: restarted
  ```
- Handlers run once, at the END of the play (even if notified multiple times) — avoids
  redundant restarts within one run.

### D. Jinja2 templates (15 min)
- The `template` module renders a `.j2` file (Jinja2 syntax embedded in the target
  file's normal format) with variables substituted, writing the result to the managed
  node — contrast with `copy`, which ships a file byte-for-byte unchanged.
- Syntax: `{{ variable }}` (substitution), `{% if condition %}...{% endif %}`,
  `{% for item in list %}...{% endfor %}`.
- This is how one template produces different, correct configs per host/environment
  (e.g., an nginx vhost with the right server_name per environment) — directly reusable
  knowledge for Helm templates in Phase 3.

## Lab (2h)

### Part 1 — First playbook (30 min)
1. Convert yesterday's ad-hoc package-install sequence into `playbook.yml`: ensure
   `python3`, `git`, `nginx` are present on the `local` group, `become: true`.
2. `ansible-playbook -i inventory.ini playbook.yml` — run it, note `changed`/`ok`
   counts in the recap line.
3. Run it AGAIN — confirm everything reports `ok` (not `changed`) — idempotency at the
   playbook level, not just per ad-hoc command.
4. `ansible-playbook -i inventory.ini playbook.yml --check --diff` after manually
   tweaking something — confirm the dry-run correctly predicts the change.

### Part 2 — Variables and facts (30 min)
5. Add a `vars:` block with `nginx_port: 8080`. Add a task using `-e` override:
   `ansible-playbook -i inventory.ini playbook.yml -e "nginx_port=9090"` — confirm the
   override wins (print it with a `debug: msg="port is {{ nginx_port }}"` task).
6. Add a task that prints `ansible_facts['os_family']`, `ansible_facts['default_ipv4']
   ['address']`, and `ansible_memtotal_mb` using the `debug` module — confirm real
   values appear.
7. `group_vars/local.yml` — move `nginx_port` there instead of inline `vars:`, confirm
   it still resolves the same way.

### Part 3 — Handlers and templates (40 min)
8. Create `templates/nginx.conf.j2` — a minimal nginx config templating in
   `{{ nginx_port }}` for the `listen` directive.
9. Add a task using the `template` module to render it to
   `/etc/nginx/conf.d/fresher.conf` (or similar), `notify: Restart nginx`.
10. Add the `Restart nginx` handler (service module, `state: restarted`).
11. Run the playbook — confirm nginx restarts (check `systemctl status nginx` /
    timestamp) ONLY when the template actually changes; run again unchanged — confirm
    the handler does NOT fire (no restart) since nothing changed.
12. Change `nginx_port` and rerun — confirm the template diff, the restart firing, and
    `curl localhost:<new-port>` working (open firewalld/SELinux context if needed —
    Day 18/19 callback).

### Part 4 — Incremental project tie-in (20 min)
13. Add a task templating an nginx vhost that serves `sys_report`'s output directory
    (recall Day 20's nginx-serving setup) — parameterize the served path and port via
    variables instead of hardcoding.
14. `git add -A`, commit: "add Ansible playbook: package baseline + templated nginx
    vhost for sys_report output, with handler-driven restarts".

**Definition of done:** playbook runs idempotently (second run reports no `changed`) ·
a variable override via `-e` and via `group_vars` both work · facts are printed and
correct for the target host · a Jinja2-templated nginx config restarts nginx via a
handler ONLY when the rendered file actually changes.
