## Theory (1h)

### A. Makefiles as a project's command palette (20 min)
- Problem: by now the project has many multi-word commands to remember (`pytest`,
  `docker compose up -d --build`, `ansible-playbook -i inventory.ini site.yml`,
  `trivy image ...`) — a `Makefile` gives short, memorable, discoverable entry points.
- Syntax basics: `target:\n\tcommand` (tab-indented, a classic gotcha — spaces silently
  break it), `.PHONY: target` (declare non-file targets so `make` doesn't get confused
  by a file of the same name).
- Example targets worth having: `make test`, `make lint`, `make build`, `make up`
  (compose), `make deploy` (ansible), `make clean`.
- `make` isn't Docker/Ansible/pytest-specific — it's a universal glue layer, which is
  exactly why it's still used in modern polyglot repos despite being decades old.

### B. pre-commit hooks (15 min)
- Git hooks recap (brief): scripts in `.git/hooks/` that run at specific points
  (`pre-commit`, `pre-push`) — but raw hooks aren't shared via git by default (they
  live outside `.git`'s tracked content).
- The `pre-commit` framework (`pip install pre-commit`) solves distribution: a
  `.pre-commit-config.yaml` in the repo declares hooks (trailing-whitespace, YAML
  validity, shellcheck, flake8/ruff), `pre-commit install` wires them into
  `.git/hooks/pre-commit` for every contributor who runs it once.
- Catches problems BEFORE they reach CI (Day 40's pipeline) — faster feedback loop,
  fewer "fix lint" commits cluttering history.

### C. EditorConfig (10 min)
- `.editorconfig` — a simple, editor-agnostic file declaring indent style/size, line
  endings, charset, trailing-newline rules per file type — most editors (including
  VS Code, vim with a plugin) respect it automatically.
- Solves the "tabs vs spaces" and "CRLF vs LF" class of problems at the source, before
  they ever become a diff-noise or YAML-parsing problem (Day 39's tab gotcha, again).

### D. Semantic versioning and CHANGELOG discipline (15 min)
- SemVer: `MAJOR.MINOR.PATCH` — MAJOR for breaking changes, MINOR for backward-
  compatible features, PATCH for backward-compatible fixes. Recap Day 34's tags
  (`v0.1.0`) — this is the rule for what the next tag number should be.
- `CHANGELOG.md` (Keep a Changelog format: `## [Unreleased]`, `## [1.0.0] - date`,
  sections `Added`/`Changed`/`Fixed`/`Removed`) — a human-readable release history,
  distinct from raw git log.
- Tying it together: a release = bump version → update CHANGELOG → tag → (later, CI
  publishes automatically on tag push — a natural CI extension, not built today).

## Lab (2h)

### Part 1 — Makefile (30 min)
1. Write a `Makefile` in `/opt/fresher_project` root with `.PHONY` targets: `test`
   (`pytest`), `lint` (shellcheck + flake8/ruff), `build` (`docker build`), `up`/`down`
   (compose), `deploy` (the `ansible-playbook` command from Day 54).
2. Deliberately use spaces instead of a tab in one target, run `make test`, observe the
   error, fix it — internalize the tab requirement the hard way once.
3. Run each target once, confirm they all work as short aliases for the long commands.

### Part 2 — pre-commit hooks (35 min)
4. `pip install pre-commit`. Write `.pre-commit-config.yaml` using at least: the
   `pre-commit-hooks` repo's `trailing-whitespace`, `end-of-file-fixer`, `check-yaml`
   hooks, plus `shellcheck` and `flake8`/`ruff` hooks.
5. `pre-commit install`. Deliberately introduce a trailing-whitespace issue and a YAML
   syntax error, `git add` them, attempt `git commit` — confirm the hook blocks the
   commit and shows what failed.
6. Fix both issues (some hooks auto-fix and re-stage — note which ones do), commit
   successfully.

### Part 3 — EditorConfig (15 min)
7. Write a `.editorconfig`: 2-space indent for YAML, 4-space for Python, LF line
   endings, UTF-8 charset, trim trailing whitespace, insert final newline. Commit it.

### Part 4 — SemVer + CHANGELOG + release (40 min)
8. Create `CHANGELOG.md` in Keep-a-Changelog format; backfill entries for the major
   milestones so far (public repo, CI green, containerized, hardened image, Ansible
   full-VM deploy) under appropriate past version headers, plus an `[Unreleased]`
   section for today's tooling additions.
9. Decide the next version bump: today's changes are additive tooling (Makefile,
   pre-commit, EditorConfig, changelog itself) — a MINOR bump is reasonable, e.g.
   `v0.2.0`. Move `[Unreleased]` entries under `## [0.2.0] - <date>`.
10. `git tag -a v0.2.0 -m "dev-tooling glue: Makefile, pre-commit, EditorConfig,
    changelog"`, `git push origin v0.2.0`. Create the matching GitHub Release with the
    CHANGELOG section as notes.
11. `git add -A`, commit and push everything: "add Makefile, pre-commit hooks,
    EditorConfig, CHANGELOG; tag v0.2.0".

**Definition of done:** `make test`/`lint`/`build` work as short commands · pre-commit
blocked a real bad commit and then allowed a fixed one · `.editorconfig` committed ·
`CHANGELOG.md` follows Keep-a-Changelog format with a real `v0.2.0` entry, tagged and
released on GitHub.
