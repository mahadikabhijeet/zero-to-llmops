## Theory (1h)

### A. HTTP and REST from a Python client's view (15 min)
- Recap: verbs (GET/POST/PUT/PATCH/DELETE), status codes (2xx/3xx/4xx/5xx), headers,
  request/response bodies (tie back to Day 20's `curl -v`).
- REST APIs: resources as URLs, JSON as the near-universal payload format.
- `pip install requests` inside a venv (recap Day 25 discipline: never `pip install`
  system-wide without thinking).

### B. `requests` fundamentals (20 min)
- `requests.get(url, params={...})`, `requests.post(url, json={...})`.
- `resp.status_code`, `resp.json()`, `resp.text`, `resp.headers`.
- `resp.raise_for_status()` — turn a bad status code into an exception instead of
  silently continuing (the #1 beginner mistake: ignoring status codes).
- Timeouts are NOT optional: `requests.get(url, timeout=5)` — a hung request without a
  timeout can freeze an automation script forever.
- Auth basics: `headers={"Authorization": f"Bearer {token}"}`, `auth=(user, pass)`.

### C. JSON handling in Python (10 min)
- `json.dumps()`/`json.loads()` recap from Day 27; `resp.json()` does `loads` for you.
- Common gotchas: keys are always strings after round-tripping, `None` ↔ `null`,
  nested dict/list navigation with `.get()` to avoid `KeyError`.

### D. Error and retry patterns (15 min)
- Exceptions from `requests`: `requests.exceptions.ConnectionError`, `Timeout`,
  `HTTPError` (after `raise_for_status()`).
- `try`/`except`/`else`/`finally` recap (Day 26) applied to network calls.
- Retry with backoff — why: transient failures (network blips, rate limits) shouldn't
  kill an automation immediately. Pattern: loop N times, `time.sleep(2 ** attempt)`
  (exponential backoff), give up after max attempts and log clearly.
- Idempotency concept preview (ties to Ansible, Day 51): a retried GET is safe; a
  retried POST might not be — think before retrying writes blindly.

## Lab (2h)

### Part 1 — First API calls (30 min)
1. In a venv, `pip install requests`. Hit a free public API:
   `requests.get("https://api.github.com")` — inspect `status_code`, `.json()`.
2. `requests.get("https://api.github.com/users/<your-github-username>")` — print
   `login`, `public_repos`, `created_at` from the JSON.
3. Deliberately request a bad URL/endpoint (typo the path) — inspect the status code
   (404) and what `resp.json()` returns for the error body.
4. Add `resp.raise_for_status()` and wrap the bad-URL call in `try/except
   requests.exceptions.HTTPError as e: print(e)`.

### Part 2 — Timeouts and connection errors (25 min)
5. Call an unreachable host with a short timeout: `requests.get("http://10.255.255.1",
   timeout=2)` inside a `try/except requests.exceptions.ConnectionError` (or `Timeout`)
   block — confirm it fails fast instead of hanging.
6. Write a small script `api_check.py` that takes a URL via `argparse`, does a GET with
   a 5s timeout, and prints "UP" (2xx) or "DOWN" (anything else / exception) — this is a
   tiny uptime checker.

### Part 3 — Retry with backoff (35 min)
7. Write `retry_get.py`: a function `fetch_with_retry(url, max_attempts=4)` that loops,
   calls `requests.get(url, timeout=5)`, calls `raise_for_status()`, returns the JSON on
   success; on `ConnectionError`/`Timeout`/`HTTPError`, sleeps `2 ** attempt` seconds and
   retries; after `max_attempts` failures, raises the last exception with a clear log
   line ("giving up after N attempts").
8. Test success path against `https://api.github.com`. Test failure path against a bad
   host — watch the backoff delays happen and the final failure message.

### Part 4 — Incremental project step (30 min)
9. Add a small "external check" feature to `sys_report.py`: fetch
   `https://api.github.com` (or any stable public endpoint) with a 5s timeout wrapped in
   try/except, and include an `"internet_reachable": true/false` field in the JSON
   report output.
10. Run the report tool, confirm the new field appears correctly whether or not you're
    online (test the false case by temporarily using a bad host).
11. `git add -p`, commit: "add internet-reachability check to sys_report".

**Definition of done:** made GET requests and handled both success and error responses ·
built a retry-with-backoff function that visibly delays and eventually gives up ·
`sys_report.py` reports internet reachability without crashing on failure · change
committed.
