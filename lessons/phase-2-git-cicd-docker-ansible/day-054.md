## Theory (1h)

### A. Error handling (20 min)
- Default behavior: a failed task stops the play for that host (other hosts continue
  independently — parallel execution model).
- `ignore_errors: true` — continue past a failure (use sparingly, it hides real
  problems if overused).
- `failed_when:` — redefine what counts as failure based on output (e.g., a `command`
  that returns nonzero on a condition you consider fine).
- `changed_when:` — redefine what counts as a change (useful for `command`/`shell`
  tasks, which report `changed: true` unconditionally by default — a real idempotency
  gap since they're not real modules).
- `block:`/`rescue:`/`always:` — try/except/finally for playbooks (direct parallel to
  Python's Day 26 pattern): group tasks in `block`, handle failure in `rescue`, always
  run cleanup in `always`.
- `any_errors_fatal: true` — stop ALL hosts if any one host fails (for coordinated
  rollouts where partial failure is worse than full stop).

### B. Tags (15 min)
- `tags: [nginx, config]` on a task or role — run only tagged subsets:
  `ansible-playbook playbook.yml --tags nginx`, or skip: `--skip-tags slow`.
- Built-in `always` tag (always runs regardless of `--tags` filter) and `never` tag
  (opt-in only) — useful for expensive/destructive tasks you don't want accidentally
  included.
- Real use: iterate fast on ONE part of a long playbook without rerunning everything
  (e.g., only the nginx role while debugging, skipping user/package setup that's
  already correct).

### C. Check mode in practice (10 min)
- Recap Day 51/52's `--check`; today: not every module supports check mode perfectly
  (raw `command`/`shell` can't predict their own effect) — `check_mode: no` can force a
  task to always run for real even during a `--check` pass (needed for tasks that
  gather info other tasks depend on), and conversely some tasks should be skipped
  during check mode.
- `--check --diff` together is the standard "what would happen" combo before running
  for real against something you're nervous about.

### D. Composing a full-VM playbook (15 min)
- Bring together everything since Day 51: inventory group for the target VM, roles for
  {base packages, user creation, nginx+templated config, project deployment}, vault for
  secrets, tags for selective reruns, error handling around anything that might
  legitimately fail on a fresh host (e.g., a repo clone if already cloned).
- This is the direct playbook that Day 57 will trigger from CI — today's goal is making
  it correct and idempotent against a genuinely fresh target, not just a
  already-configured one.

## Lab (2h)

### Part 1 — Error handling drills (35 min)
1. Add a task that intentionally fails (e.g., `command: /bin/false`) inside a `block`,
   with a `rescue` that logs a debug message, and an `always` that runs regardless —
   confirm the recap output and run order with `-v`.
2. Convert a `shell`/`command` task that always reports `changed: true` (e.g., checking
   disk usage) into one using `changed_when: false` (since it's read-only, it should
   never claim a change) — confirm the recap now shows `ok` instead of `changed`.
3. Add `failed_when: "'ERROR' in result.stdout"` to a task registered as `result` from a
   prior task — test both the pass and fail path by toggling what the command outputs.

### Part 2 — Tags (25 min)
4. Tag your roles/tasks: `users`, `packages`, `nginx`, `project`.
5. `ansible-playbook -i inventory.ini site.yml --tags nginx` — confirm only nginx-
   related tasks run (others show as skipped).
6. `ansible-playbook -i inventory.ini site.yml --skip-tags packages` — confirm the
   inverse works.

### Part 3 — Fresh-VM playbook build (40 min)
7. Provision or reset a genuinely fresh target (a new container/VM, or a Fedora
   container with `sshd` running is acceptable for this lab if a real VM isn't
   available — note the substitution honestly in your notes).
8. Write `site.yml` as the top-level playbook orchestrating roles in order: base
   packages → `svc_fresher` user (recall Day 3) → nginx role (Day 52–53) → deploy
   `sys_report` project (clone or copy from your GitHub repo, install deps, set up the
   systemd timer from Day 12/24).
9. Run `ansible-playbook -i inventory.ini site.yml --check --diff` against the fresh
   target FIRST — review the full plan before applying.
10. Run it for real: `ansible-playbook -i inventory.ini site.yml`. Verify on the target:
    nginx serving the project's report, the systemd timer active, the correct user
    owning the project files.

### Part 4 — Idempotency proof and commit (20 min)
11. Run `site.yml` again against the now-configured host — confirm the recap shows
    zero (or near-zero, for legitimately re-checked items) `changed` tasks.
12. `git add -A`, commit: "add error handling, tags, and a full fresh-VM site.yml
    orchestrating all roles; verified idempotent second run".

**Definition of done:** `block`/`rescue`/`always` demonstrated with a deliberate
failure · `changed_when`/`failed_when` correctly reclassify a command task's outcome ·
`--tags`/`--skip-tags` selectively run subsets · `site.yml` configures a fresh target
end-to-end and is confirmed idempotent on a second run.
