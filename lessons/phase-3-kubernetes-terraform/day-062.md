## Theory (1h)

### A. kubectl as a daily-driver tool (20 min)
- Context/namespace: `kubectl config get-contexts`, `kubectl config
  current-context`, `kubectl config set-context --current --namespace=<ns>`.
- Core verbs: `get` (list), `describe` (deep human-readable detail + Events),
  `logs` (container stdout/stderr — `-f` to follow, `--previous` for a
  crashed container's last logs), `exec` (`-it -- /bin/sh` to get a shell
  inside a running container).
- Output formats: `-o wide`, `-o yaml`, `-o json`, and `-o
  jsonpath='{.status.podIP}'` for scripting — this is how CI/automation reads
  cluster state without parsing human text.
- `kubectl explain <kind>.<field>` — the built-in API-doc lookup, faster than
  web search for field names/types.

### B. Pod anatomy — the atomic unit of scheduling (20 min)
- A Pod is one or more containers that share network namespace (same IP,
  localhost between them) and can share volumes. Not "one container" —
  "one tightly-coupled group."
- **Sidecar pattern**: a helper container running alongside the main app
  (e.g., a log shipper) — same Pod, same lifecycle, different image.
- **Init containers**: run to completion, in order, BEFORE app containers
  start (e.g., wait-for-dependency, run a migration). Defined under
  `spec.initContainers`.
- Pod lifecycle phases: `Pending` → `Running` → `Succeeded`/`Failed`; container
  states within: `Waiting` → `Running` → `Terminated`. `restartPolicy`:
  `Always` (default, for long-running services), `OnFailure`, `Never`.

### C. Labels, selectors, and annotations (10 min)
- Labels are key/value metadata used for **selection** (how Services and
  Deployments find "their" pods) — not for human notes.
- Annotations are metadata NOT used for selection — free-form, for tooling
  (e.g., last-applied-config, build SHA).
- `kubectl get pods -l app=nginx`, `kubectl label pod <name> tier=web`.

### D. Multi-container communication and shared volumes (10 min)
- Containers in a Pod reach each other via `localhost:<port>` (shared network
  namespace) — no DNS needed within a Pod.
- `emptyDir` volume: ephemeral, Pod-lifetime-scoped storage shared between
  containers in the same Pod (preview of Day 68's fuller Storage topic).

## Lab (2h)

### Part 1 — kubectl fluency drills (30 min)
1. Fresh kind cluster if needed (`kind create cluster --name fresher`).
2. `kubectl get pods -A -o wide`; pick any kube-system pod and run
   `kubectl get pod <name> -n kube-system -o yaml | less` — read the full spec.
3. Practice jsonpath: `kubectl get nodes -o
   jsonpath='{.items[0].status.nodeInfo.kubeletVersion}'`.
4. `kubectl explain pod.spec.containers` and `kubectl explain
   pod.spec.containers.resources` — note the nested field paths.

### Part 2 — Multi-container pod with init container (40 min)
5. Write `multi-pod.yaml`: one initContainer named `init-wait` running
   `busybox:1.36` with command `sh -c "sleep 5; echo ready"`; one main
   container `app` running `nginx:1.27`; one sidecar container `logger`
   running `busybox:1.36` with command `sh -c "while true; do date; sleep
   10; done"`.
6. Apply it, then `kubectl get pod multi-pod -w` — watch it sit in `Init:0/1`
   before flipping to `Running` with 2/2 containers ready.
7. `kubectl logs multi-pod -c init-wait`, `kubectl logs multi-pod -c logger
   -f` (Ctrl+C to stop), `kubectl exec -it multi-pod -c app -- sh` and confirm
   `curl localhost:80` works from inside, then `curl localhost:<logger-has-no-
   port>` fails as expected — this demonstrates the shared network namespace.

### Part 3 — Labels and selection (25 min)
8. Apply 3 simple nginx pods with labels `app=web, env=dev`, `app=web,
   env=prod`, `app=api, env=prod` (three separate YAML files or one file with
   `---` separators).
9. `kubectl get pods -l app=web`, `kubectl get pods -l 'env in (prod)'`,
   `kubectl get pods -l app=web,env=prod` (AND semantics with comma).
10. `kubectl label pod <one-of-them> tier=frontend --overwrite`, confirm with
    `kubectl get pods --show-labels`.

### Part 4 — Break something on purpose (25 min)
11. Apply a pod with a typo'd image name (`nginx:doesnotexist999`) —
    `kubectl get pods -w` and watch it go `ImagePullBackOff`. `kubectl
    describe pod` and find the Events explaining why.
12. Fix the image tag, `kubectl apply -f` again, confirm it recovers.
13. Clean up: `kubectl delete pod --all` in the default namespace.

## Definition of done
Comfortable with get/describe/logs/exec/-o yaml/-o jsonpath · built and
explained a pod with an init container and a sidecar · used label selectors
with AND semantics · diagnosed an ImagePullBackOff from Events alone.
