A · seeing what runs

Two syntaxes, one process table

  • ps aux = BSD, no dash, gives %CPU/%MEM · ps -ef = System V, with dash, gives PPID clearly. Read both
  • STAT: R running · S sleeping (the healthy default) · D uninterruptible I/O — can't be killed, not even -9 · T stopped · Z zombie
  • A zombie is already dead — just an exit code awaiting reaping. Fix the parent. Orphans re-parent to PID 1 and systemd reaps them
  • top: M memory · P CPU · 1 per-core · q quit · top -b -n1 for scripts. pstree -p = the family tree back to PID 1
ps -eo stat --no-headers | sort | uniq -c | sort -rn  ←  yesterday's idiom, on process states
B · signals

SIGTERM asks. SIGKILL doesn't.

  • SIGTERM (15) — the default from plain kill. Catchable: flush buffers, finish the request, drop the lock file, exit cleanly
  • SIGKILL (9) — cannot be caught, blocked or ignored. No cleanup, half-written files. TERM first, wait, verify, THEN escalate
  • SIGHUP (1) = "reload your config" for daemons · SIGINT (2) = what Ctrl-C sends
  • kill -0 PID sends nothing — pure liveness check · always pgrep -af before pkill -f. Look before you shoot.
trap "echo CAUGHT SIGTERM" SIGTERM  →  kill %1 prints it · kill -9 %1 is silent
C · priority & job control

High nice = low priority

  • Nice runs -20 to 19. "Nice" means nice to others — 19 = generous = less CPU. Only root goes negative
  • nice -n 10 cmd to start · renice -n 5 -p PID to change a running one
  • & · jobs -l · Ctrl-Z suspends (state T, not killed) · bg %1 · fg %1 — %1 is a job number, not a PID
  • Closing the shell SIGHUPs the children. nohup = deaf process; disown = forgetful shell. Real life: tmux. Real service: systemd — Day 12.
nohup sleep 120 > out 2>&1 &  ·  disown %1  ·  pgrep -af 'sleep 120'
D · /proc and lsof

Day 1's promise, kept

  • "The kernel exposes its state as files" — /proc isn't on disk, it's kernel memory rendered as text on read
  • cmdline/environ are null-separated → tr '\0' ' ' · status has State + VmRSS · cwd = where it writes
  • /proc/$$/fd/ — 0, 1, 2. Day 2's file descriptors, as actual listable files. Not a metaphor any more
  • lsof -i :22 = "what is listening on this port" — the most-typed question in ops · ss -tlnp when lsof isn't installed
ls -l /proc/$$/fd/  ·  grep -E '^(State|VmRSS)' /proc/$$/status  ·  sudo lsof -i :22
Putting it together

The 2am triage sequence

  • 1. What's eating the box? top → P or M · or ps aux --sort=-pcpu | head
  • 2. What IS that thing? /proc/PID/cmdline, its PPID — identify before you touch. Killing something you don't recognize causes outages.
  • 3. What's it doing? lsof -p PID, /proc/PID/cwd
  • 4. Decide — sometimes the answer is renice, not kill. 5. If you kill: TERM → wait → kill -0 to verify → only then -9
kill $PID && sleep 1 && (kill -0 $PID 2>/dev/null && echo escalate || echo "gone cleanly")
