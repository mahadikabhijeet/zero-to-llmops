A · rpm — the low level

rpm knows this box. dnf knows the world.

  • RPM = the format + the local database · dnf = the layer that talks to repos, resolves deps, then hands off to rpm
  • -q version · -qi info · -ql file list · -qa everything · -qf <path> = which package owns this file ← the forensics move
  • "Not owned by any package" = local or hand-made. Nothing overwrites it — and nothing restores it.
  • rpm -V verifies against build-time checksums/perms. Silence = clean. 5=checksum S=size T=time M=mode
rpm -qf $(which bash)  ·  rpm -qf /etc/passwd  ·  sudo touch /usr/bin/tail; rpm -V coreutils
B · dnf — the daily driver

Search, install, and read the summary

  • yum is a symlink to dnf now — same tool, kept for muscle memory
  • dnf search · dnf info — read the repo line, it's how you catch a surprise third-party source
  • install / remove / reinstall (fixes a bad rpm -V) · read the transaction summary before y
  • check-update exits 100 when updates are pending, not 0 · groups bundle packages — quote the name
sudo dnf install tree  ·  dnf group info "Development Tools"
C · repos and trust

gpgcheck=1 is not a formality

  • /etc/yum.repos.d/*.repo — still called yum.repos.d. Pure backward compat; the historical name usually wins in Linux
  • Fields: [id] · name= · baseurl= or metalink= (mirror list, survives an outage) · enabled=0/1 · gpgcheck=1
  • gpgcheck=1 = verify every package's signature before install. "Just set gpgcheck=0" is how people disable their own security — import the key instead
  • dnf config-manager --add-repo: a trust decision, not a config step — you're granting a stranger root
grep -H 'gpgcheck *= *0' /etc/yum.repos.d/*.repo && echo UNSIGNED || echo clean
D · history & rollback

Undo an entire install as one transaction

  • dnf records every transaction — id, time, user, package set. Recorded the set → can reverse the set
  • dnf history · dnf history info <id> (shows the deps you weren't tracking) · dnf history undo <id>
  • The undo is appended as a new transaction, not erased. Same honest-record pattern as git and Terraform state.
  • Limits: restores packages — not config edits, not data. A safety net, not a backup · modularity: just know the word
dnf history info last  ·  sudo dnf history undo last  ·  sudo dnf install -y tree
Putting it together

"What is this file and can I touch it?"

  • 1. Who owns it? rpm -qf /path — unowned means treat it with more care, nothing will restore it
  • 2. What came with it? rpm -ql <pkg> — finds its config and its docs
  • 3. Tampered? rpm -V <pkg> — silence is good, codes mean investigate
  • 4. Broken → sudo dnf reinstall <pkg> · 5. Install broke the box → dnf history undo <id>
rpm -qf /usr/bin/tail → rpm -V coreutils → dnf reinstall coreutils → verify silent
